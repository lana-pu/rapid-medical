# Process Hygiene — идемпотентный запуск, без утечки процессов

## Принцип
Никогда не поднимать второй долгоживущий процесс (dev-сервер, `next dev`, браузер
автоматизации), не убив предыдущий. Иначе старые процессы копятся и съедают память
(десятки ГБ RAM).

## Правила

1. **Dev-сервер — фиксированный порт + kill-first.** App — только `:3000`, лендинг — только
   `:3001` (явный `-p`, без авто-перехода на соседний порт). Перед стартом освободить порт
   (убить старый процесс), потом поднять новый. Roll-forward на соседний порт запрещён.
   Запуск — через npm-скрипт `dev` (сам делает kill-first); «выключить всё» — `dev:stop`
   (глушит `:3000` и `:3001`).
2. **Браузерная автоматизация — гарантированное закрытие.** Ровно один запуск браузера на
   скрипт, с таймаутом на launch. Весь обход в `try`, закрытие браузера в `finally`. В цикле —
   новый контекст и его закрытие, не новый браузер. Каждый `goto` — с таймаутом и
   `waitUntil: 'domcontentloaded'` (не `'networkidle'`: с HMR не наступит). `process.exit` —
   только после закрытия браузера.
3. **Кросс-браузерность.** Движок ставит Playwright (`npx playwright install`), Google Chrome не
   нужен. Нет Chromium — WebKit.
4. **Повторный прогон при провале.** Перед ре-раном прибрать осиротевшие процессы (старый
   dev-сервер на порту) и служебный браузер. Не больше 2–3 авто-повторов — дальше стоп и
   сообщить.

## Hook-страховка
`.claude/hooks/pre-tool-use-process-hygiene.sh` (PreToolUse, Bash): перед стартом dev-сервера
освобождает порт (kill-first); блокирует запуск браузер-скрипта без `try/finally` + `close` +
таймаута. Рецепт — `modules/development/prompts/hardcode-guard-hook.md`, раздел «Другие хуки».
