# Session Continuity — сохранение прогресса между сессиями

## Принцип
Новая сессия не помнит прошлую. Всё, что нужно для продолжения, живёт в памяти проекта
`docs/memory/` (в git), а не в истории чата. Один чат = один проект.

## Старт сессии

1. Прочитать `docs/memory/state.md` (текущий шаг, активная работа, последние решения) и
   `docs/memory/INDEX.md` (оглавление ADR / Findings / Sessions). Больше ничего «на всякий
   случай» не грузить.
2. В Claude Code это подсвечивает SessionStart-хук `.claude/hooks/session-start.sh`
   (статус памяти без `cat` файлов); в инструментах без хуков — выполнять вручную.
3. Вопрос про историю («почему выбрали X», «что делали на прошлой неделе») — через
   `/memory-search` (L1 INDEX → L2 файл по ID → L3 соседние сессии), не чтением всех файлов.

## По ходу работы

- Архитектурное решение («почему X, а не Y») → ADR в `docs/memory/decisions/ADR-NNN-<slug>.md`
  со строками `IMPL: <путь>` + строка в INDEX.
- Неочевидная находка (лимит, баг среды, нюанс API) → `docs/memory/findings/F-NNN-<slug>.md`
  + строка в INDEX.
- Изменение инфраструктуры (деплой, порты, .env, сервисы) → `docs/memory/infrastructure.md`
  в том же шаге.
- Реализованная фича → строка в `docs/memory/feature-registry.md`.

## Конец сессии / этапа

- `/save-session` (`modules/ai-config/prompts/save-session.md`): session-файл в
  `docs/memory/sessions/`, обновление `state.md` (≤80 строк) и `INDEX.md`, коммит памяти.
- Запускать после push, закрывающего логический шаг, перед перерывом и после значимой фичи.
  Мелкие правки — достаточно коммита.

## Перед компрессией контекста
Если настроен PreCompact-хук — он сохраняет снимок состояния; иначе перед длинной операцией
обновить `state.md` вручную.

## Источник правды
При расхождении памяти, истории чата и автоматической памяти — главнее файлы `docs/memory/`
(они прошли ревью и лежат в git).
