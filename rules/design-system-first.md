# Design System First — DESIGN.md как контракт

## Принцип
`docs/DESIGN.md` — единый источник правды для токенов: цвета, шрифты, отступы, скругления.
Направление изменений строго одно: DESIGN.md → UI-кит → экраны.

## Правила

1. Любой UI следует `docs/DESIGN.md`.
2. Нужного токена нет — добавить в DESIGN.md, прогнать lint, потом использовать (в коде —
   через тему: `@theme` / `tailwind.config` / `packages/ui` в монорепо).
3. Шрифты и цвета вне контракта запрещены.
4. При изменении DESIGN.md — обязательный прогон перед коммитом:
   ```bash
   npx @google/design.md lint docs/DESIGN.md
   ```
   errors блокируют коммит; warnings — разобрать или зафиксировать причину.
5. Изменение токена коммитится вместе с зависимыми UI-правками. Компоненты, использующие
   токен через тему, обновляются автоматически — их не трогать.
