# Spec First — спека как источник правды

## Принцип
Прежде чем менять экран или поведение — прочитать его спеку. Спека ведёт код, а не наоборот.
Цепочка изменения поведения: spec → тест-кейс → код.

## Правила

1. Перед правкой экрана / компонента / поведения прочитать:
   - `docs/spec.md` — общая логика, модель данных, доступы;
   - `docs/screens/<экран>.md` — состояния, элементы, условия видимости, тексты, валидация;
   - `docs/screens/_global.md` — сквозные правила (auth guard, ошибки сети, успехи, loading,
     защита от двойного submit, формат дат, empty states) — соблюдать на любом экране.
2. Меняется поведение или дизайн экрана → спека правится в ТОМ ЖЕ коммите, что и код
   (`docs/screens/<экран>.md`, при необходимости `docs/spec.md`, `docs/test-cases.md`).
3. Поведение не меняется (рефактор, стиль) → код остаётся в рамках описанного в спеке.
4. Спеки нет или она поверхностна → сначала дописать спеку, потом код.
5. Спека и код расходятся → привести ОДНУ сторону к совпадению. Спека = источник правды;
   если спека устарела по решению пользователя — сначала обновить спеку.
