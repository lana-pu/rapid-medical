# Формат данных атласа

```
docs/research/
├── project.json
└── stages/
    ├── frame.json     (имя файла = id этапа из assets/stages.json)
    └── desk.json
```

Нет файла — этап «Не начат». Создавать пустые файлы не нужно.

## project.json

```json
{
  "title": "Атлас Acme",
  "product": "Acme",
  "eyebrow": "Acme · исследование для редизайна",
  "heading": "Атлас исследования",
  "lede": "Что знаем, откуда и чего не хватает. Этапы слева, несделанное ниже.",
  "owner": "Анна"
}
```

`owner` — кто принимает решения: подпись в списке «Решение за …». `title` — короткое имя страницы.

## stages/<id>.json

```json
{
  "conclusions": ["Что из этого меняет решение"],
  "outputs": {
    "decision": [{"type": "text", "t": "…"}],
    "questions": [{"type": "table", "head": ["Вопрос", "Этап"], "rows": [["…", "…"]]}]
  },
  "open": [{"kind": "decision", "t": "Подтвердить главный сегмент"}],
  "confirmed": "2026-11-05",
  "skip": "Продукта ещё нет"
}
```

- Ключи `outputs` — разделы этапа из `stages.json`; лишний ключ — ошибка сборки.
- `open`: `kind` — `question` (не знаем) или `decision` (решает владелец).
- `confirmed` — дата подтверждения пользователем. С проставленным `confirmed` незаполненный этап не соберётся.
- `skip` — причина пропуска.

## Блоки

| type | Поля | Для чего |
|---|---|---|
| `text` | `t` | абзац |
| `list` | `items` | список |
| `claims` | `items: [{t, label, level, src}]` | утверждения; `label`: `fact`, `inference`, `limit`, `pattern`; `level`: 1–5 |
| `table` | `head`, `rows`, `fold` | таблица; `fold` — подпись свёрнутой таблицы («Все 71 допущение») |
| `link` | `t`, `url` или `path`, `note`, `final` | материал вне атласа |

Ячейка таблицы — строка, `{"t": "Опровергнуто", "tone": "bad"}` (`ok`, `bad`, `warn`, `none`) или `{"level": 2}`.
В `text`, списках, утверждениях и ячейках работает `**жирный**`, другая разметка показывается как текст.

`link` без `final` — материал лежит в другом месте и ещё не разобран: раздел попадёт в «Что не сделано». С
`"final": true` — итог этого раздела живёт там и раздел считается заполненным (таблица приоритетов).

## Статус этапа

| Статус | Когда |
|---|---|
| Не начат | нет ни материала, ни выводов |
| В работе | заполнена часть разделов, есть только ссылки или нет выводов |
| Ждёт подтверждения | все разделы и выводы есть, `confirmed` нет |
| Готов | всё есть и стоит `confirmed` |
| Пропущен | стоит `skip` |
