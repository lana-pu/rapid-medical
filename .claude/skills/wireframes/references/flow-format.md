# Формат флоу

Флоу — один JSON-файл в проекте: `docs/flows/<slug>.json`. Сборщик превращает его в страницу с тремя видами:
**Flow** (доска: экраны по группам, стрелки переходов, заметки), **Prototype** (экран в натуральную ширину, клик по
горячей зоне ведёт дальше), **Library** (все компоненты с примерами JSON).

```json
{
  "title": "Site editor — change a page and publish",
  "project": "Rapid Medical",
  "description": "Чей путь и на чём основан (ADR, находки, ресёрч).",
  "start": "signin",
  "groups": [{ "title": "1 · Найти страницу", "screens": ["signin", "pages"] }],
  "links": [{ "from": "pages", "to": "page", "label": "клик по строке" }],
  "screens": [
    {
      "id": "pages", "title": "Pages", "device": "desktop", "url": "example.com/admin", "height": 720,
      "body": [ { "c": "appbar", "logo": "Product" }, { "c": "list", "items": [ { "title": "Home", "to": "page" } ] } ],
      "overlay": { "c": "modal", "title": "…", "items": [], "actions": [] },
      "notes": ["Заметка ко всему экрану"]
    }
  ]
}
```

| Поле | Что это |
|---|---|
| `screens[].id` | уникальный, латиница; на него ссылаются `to`, `links`, `groups` |
| `device` | `desktop` 1280 · `tablet` 820 · `mobile` 390 |
| `url` | строка адреса над экраном; без неё — экран без рамки браузера |
| `height` | минимальная высота экрана, px |
| `body` | узлы сверху вниз |
| `overlay` | `modal` или `drawer` поверх затемнённого экрана |
| `groups` | ряды доски; экран вне групп на доске не показывается (сборщик предупредит) |
| `links` | переходы, которых нет на экране как кнопки (например, «через меню») |

## Узел

`{ "c": "<компонент>", …свойства }`. Список компонентов и свойств — вкладка Library собранной страницы
(`build.py --library`). Свойства, которые принимает **любой** узел:

| Свойство | Действие |
|---|---|
| `to` | горячая зона: переход на экран; стрелка на доске |
| `quiet` | с `to`: кликается в прототипе, на доске не рисуется (повторяющиеся кнопки шапки) |
| `label` | подпись перехода |
| `annotation` | нумерованная заметка: красный номер на элементе, текст под экраном. Для UX-решений и источников. Не `note`: так называются поля у многих блоков |
| `selected` / `hover` | синяя рамка выделения / пунктир наведения |
| `toolbar` + `toolbarPos: "below"` | плавающая панель над (под) элементом — как у редакторов |
| `popover` + `popoverPos: "right" \| "up"` | выпадающее меню под элементом |
| `cursor` | курсор у элемента: «здесь кликают» |
| `grow` | внутри `row`: занять свободное место |

## Правила содержания

- **Тексты настоящие.** Из проекта (данные, спека, сайт) или правдоподобные для этого продукта. Без lorem и «Title».
- **Картинки и видео — плашки** `media` с подписью, что там (имя файла или описание).
- **Заметки — решения и их основания:** «почему так», ссылка на находку, ADR, источник бенчмарка. Не пересказ экрана.
- **Один экран — одно состояние.** Ошибка, пусто, загрузка, успех — отдельные экраны.
- Повторяющиеся куски (шапка редактора, страница) удобно собирать генератором; JSON в проекте — результат.

## Свои компоненты проекта

Пак — JS-файл проекта, `docs/flows/pack.js`:

```js
WF.register('deviceDiagram', {
  group: 'Project', doc: 'Схема устройства с метками.',
  props: { label: { type: 'text', doc: 'подпись' } },
  render: n => `<div class="w-media diagram" style="aspect-ratio:21/9"><span class="k">diagram</span><span class="l">${n.label}</span></div>`,
  examples: [{ c: 'deviceDiagram', label: 'TIGERTRIEVER — device anatomy' }],
});
```

Собирать с `--pack docs/flows/pack.js`. Если пак регистрирует компоненты в цикле, перечислить их в комментарии строкой
`@components имя1 имя2 …` — по ней сборщик проверяет флоу. Внутри `render` доступен `WF.node(child)` для вложенных узлов. Тексты
экранировать самостоятельно, если они приходят из данных.
