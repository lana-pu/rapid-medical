# AGENTS.md — воркспейс

Личный воркспейс: общая библиотека методологии сверху, продукты — в `projects/<slug>/`.
Этот файл подгружается в каждом проекте воркспейса (Claude читает AGENTS/CLAUDE из родительских папок) —
держим коротким (< 4 KB).

## Язык и общение
- Отвечать **по-русски**, всегда. Сообщения часто надиктованы голосом: украинские/иноязычные вставки и
  пропущенные буквы (u, m) — шум распознавания, смысл восстанавливать, язык не менять, не переспрашивать.
- Минимум промптов о доступах: не задавать мета-вопросов про разрешения.

## Как устроено
```
Studio/
├── AGENTS.md            ← этот хаб (CLAUDE.md → симлинк)
├── modules/             ← библиотека промтов: ai-config · product · design · development · seo-geo
├── rules/               ← универсальные правила (индекс rules/_INDEX.md)
├── .claude/             ← общие hooks, scripts, skills (+ project-settings.template.json)
├── lessons/             ← исходный курс (только чтение, не в git)
└── projects/<slug>/     ← продукты: свой git, своя спека docs/spec.md, своя память docs/memory/
```
- **Один чат = один проект.** Открывать VS Code / Claude на папке `projects/<slug>/`, а не на корне.
  Тогда у проекта своя авто-память, а этот хаб и правила проекта подхватываются оба.
- Корень открывать только для работы над самой библиотекой (`modules/`, `rules/`, `.claude/`).
- Новый проект → `/init-project` (`modules/ai-config/prompts/init-project.md`). Существующий репозиторий
  тоже через него: клонировать в `projects/<slug>/`, дальше режим «ретрофит».
- Методология проекта (spec.md, DESIGN.md, память, правила) лежит в его `docs/` и его `AGENTS.md`.

## Жёсткие принципы (для всех проектов)
1. **Спека первой.** Изменение поведения → сначала `docs/spec.md` (или `docs/screens/*.md`), потом код.
2. **DESIGN.md → UI-кит → экран.** Новый токен — сначала в DESIGN.md; новый вариант компонента — сначала
   в UI-ките. Хардкод цветов/пикселей/inline-стилей на страницах запрещён. Правка паттерна — на всех
   экранах, где он живёт, а не только на присланном скриншоте.
3. **Никаких обманок в UI.** Кнопка делает реальное действие или её нет (честный disabled — можно,
   фейковый успех — нельзя).
4. **Propose → confirm.** Ничего не создаётся и не меняется за пользователя продукта автоматически без
   замера и явного решения.
5. **Чинить механизм, а не предлагать ручной обход.**
6. **Коммит сразу после логического шага**, атомарно, без `git add -A` вслепую (`rules/commits.md`,
   `rules/parallel-editing.md`). После push — `/save-session`.
7. **Факты против допущений.** Гипотезы и ресёрч помечать как гипотезы, проверять на данных.

## Модули (частые)
| Тема | Индекс |
|---|---|
| Настройка AI, память, скиллы, новый проект | `modules/ai-config/AGENTS.md` |
| Продукт: концепция, спека, экраны, PRD | `modules/product/AGENTS.md` |
| Дизайн-система, UI-кит, экраны, адаптив, лендинг | `modules/design/AGENTS.md` |
| Разработка: БД, auth, API, тесты, деплой, security | `modules/development/AGENTS.md` |
| SEO, индексация, GEO, аналитика, копирайт | `modules/seo-geo/AGENTS.md` |

Правила: `rules/_INDEX.md`. **Полная карта модулей → `modules/_INDEX.md`.**

## Git
Репозиторий на проект: у каждого `projects/<slug>/` свой `.git` и remote. Корень воркспейса — отдельный
репозиторий «личный стек» (modules/, rules/, .claude/, AGENTS.md); `projects/` и `lessons/` в нём
игнорируются.
