# Выбор ORM — Prisma vs Drizzle

Запускай, когда нужно осознанно сравнить ORM и, возможно, взять не дефолтный Prisma. Если пользователь не просит сравнения — дефолт Prisma, этот промт не нужен.

Нужно на входе: решение, где живёт БД (ADR «Слой данных», см. `db-hosting-choice.md`). Если ADR нет — создай `docs/memory/decisions/ADR-<N>-data-layer.md` по той же структуре и добавь в него раздел ORM.

## Что сделать

1. Коротко объясни (на 5–7 минут чтения): что такое реляционная БД (таблицы, ключи, связи); зачем ORM (без ручного SQL, типы из схемы, миграции из коробки); плюсы и минусы Prisma и Drizzle.

2. Сравнительная таблица:

| | Prisma | Drizzle |
|---|---|---|
| Зрелость | стабильная, много пользователей | моложе, быстро растёт |
| Типы | сгенерированный client из `schema.prisma` | из TS-схемы |
| SQL | скрыт за абстракцией | очень близко к SQL |
| Миграции | `prisma migrate` | `drizzle-kit` |
| Перформанс | чуть медленнее | близко к raw SQL |
| Примеры для AI | очень много | меньше, но растёт |
| Edge runtime | сложнее (тяжёлый client) | из коробки |

3. Порекомендуй один с обоснованием. Учти: тип продукта (`docs/spec.md` / `docs/PRD.md`); что большую часть кода генерирует AI (у Prisma больше примеров); уровень владения SQL у пользователя (без опыта SQL абстракция Prisma — плюс, с опытом Drizzle может быть приятнее); выбранную БД (ORM работает одинаково с любым Postgres — меняется только `DATABASE_URL`). Если в проекте уже используется ORM — по умолчанию оставь его.

4. Допиши решение в существующий ADR «Слой данных» (новый файл не создавай; Status и Date не дублируй):
   - в Decision — подраздел `### ORM`: `<Prisma|Drizzle> — потому что <причина>`;
   - в Consequences — последствия выбора (плюсы и минусы);
   - в Alternatives Considered — отвергнутые варианты:
     - `<Prisma|Drizzle>` (невыбранный) — плюсы, минусы, почему не выбрали;
     - голый SQL через pg-клиент — нужен глубокий SQL, нет миграций и типов из коробки;
     - TypeORM / Sequelize — устарели относительно Prisma/Drizzle, медленнее развиваются, меньше примеров у AI;
     - без ORM (raw SQL в каждой функции) — нет типов и миграций, выше риск SQL-инъекций, хрупко для прода.

5. Обнови описание строки ADR в `docs/memory/INDEX.md` на «база + ORM».

6. Если выбран Drizzle — во всех дальнейших шагах (схема, миграции, запросы, seed) адаптируй команды и код под Drizzle вместо Prisma.

В конце покажи финальный ADR (разделы «База данных» и «ORM») и обновлённую таблицу ADR в `INDEX.md`.
