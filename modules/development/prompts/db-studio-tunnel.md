# DB Studio Tunnel — просмотр данных БД через SSH-туннель

Запускай, когда нужно посмотреть или поправить данные в базе на сервере (например, проверить, сохранилась ли запись) без SQL и без захода на VPS.

Нужно на входе: PostgreSQL на VPS, порт 5432 слушает только `127.0.0.1`; адрес сервера и SSH-доступ — в `docs/memory/infrastructure.md`; `DATABASE_URL` — в `.env.production`.

Если БД в Supabase (или другом managed-сервисе с дашбордом) — туннель не нужен: просто напомни, что данные видно в дашборде провайдера, и остановись.

## Что сделать

1. **`scripts/studio.sh`:**
   - открывает SSH-туннель: локальный порт 5433 → `127.0.0.1:5432` на сервере;
   - запускает studio ORM против туннеля. По умолчанию Prisma Studio (`npx prisma studio`, `localhost:5555`); если в проекте другой ORM — его аналог (Drizzle: `npx drizzle-kit studio`);
   - закрывает туннель при выходе (`trap` на Ctrl+C / EXIT);
   - хост и пользователя сервера берёт из `docs/memory/infrastructure.md`, имя базы и пароль — из `.env.production`. В скрипт значения не хардкодь.
2. **`package.json`:** скрипт `db:studio` → `scripts/studio.sh`. В монорепо — в `package.json` приложения, где лежит схема ORM.
3. **`docs/memory/infrastructure.md`:** в разделе «БД» запиши, как смотреть данные (`npm run db:studio`, порт туннеля, адрес studio).

## Правила

- Порт БД наружу не открывай — только туннель.
- Пароли и реальные данные пользователей не выводи в чат, не коммить и не пиши в документацию; секреты — только в `.env*` (права 600, в `.gitignore`).
- Пароли в таблицах должны быть хэшами (например, `$scrypt$...`). Видишь открытый пароль — останови работу и сообщи.

## Проверка

`npm run db:studio` открывает studio на `localhost:5555` с данными сервера; после Ctrl+C туннель закрыт (`lsof -i :5433` пусто).
