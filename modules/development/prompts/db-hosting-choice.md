# Выбор хостинга базы данных — managed (Supabase и др.) vs свой Postgres

Запускай перед подключением БД к проекту. Результат — ADR «Слой данных» (где живёт база + ORM по умолчанию).

Нужно на входе: описание продукта и аудитории в `docs/spec.md` (или `docs/PRD.md`).

Если в проекте база уже подключена (есть `DATABASE_URL`, схема ORM) — не выбирай заново: зафиксируй существующее решение в ADR, если его нет, и закончи.

## Что сделать

1. Сравни варианты под этот проект таблицей:

| | Supabase (managed) | Свой Postgres на VPS |
|---|---|---|
| Запуск | проект за пару минут, БД готова сразу | сервис `db` в docker-compose |
| Что входит | Postgres + Auth + Storage + Realtime + авто-API | только Postgres (Auth/Storage — свои) |
| Цена на росте | бесплатный tier, дорожает со строками/трафиком | стабильно (тот же VPS) |
| Контроль | платформа управляет БД | база полностью ваша |
| Юрисдикция данных | серверы платформы (US/EU) | на вашем сервере, нужная страна |
| Бэкапы | автоматические (на платных тарифах) | свой cron-бэкап |
| Привязка | завязка на платформу (внутри Postgres) | переносится на любой сервер |

2. Объясни ключевую развилку — она про данные, не про удобство:
   - персональные данные под требования локализации (напр. 152-ФЗ для РФ), нужен полный контроль и предсказуемая цена → свой Postgres;
   - нужен быстрый старт, аудитория по миру, БД + Auth + Storage из коробки ценнее контроля → Supabase.
   Дефолт — свой Postgres на том же VPS, где развёрнут проект. Если случай за Supabase — это тоже нормальный выбор.

3. Коротко упомяни другие managed-Postgres (Yandex Cloud, Selectel, VK Cloud, Timeweb, Neon, RDS и т.п.): провайдер сам делает бэкапы, обновления и резервирование, платится отдельно. Имеет смысл на росте, когда данные критичны. Хранилище файлов здесь не выбираем (см. `file-storage.md`).

4. Если пользователь выбирает Supabase/другой managed — предупреди, что меняется:
   - свой Postgres в docker-compose (`postgres-docker-on-vps.md`) не поднимаем: строку подключения из дашборда провайдера кладём в `DATABASE_URL` (`.env.local`, `.env.production`);
   - Auth можно взять готовый у Supabase вместо своей библиотеки — отметь как развилку для решения при настройке auth;
   - ORM работает одинаково — внутри тот же PostgreSQL.

5. ORM отдельно не выбирай: по умолчанию **Prisma** (удобный язык схемы, больше всего примеров у AI). Скажи об этом одной строкой и запиши в ADR как принятый дефолт. Если в проекте уже есть другой ORM (Drizzle и т.п.) — фиксируй его. Осознанное сравнение — `orm-choice.md`.

## Нюансы

- Supabase → свой Postgres позже возможен (dump → restore), но завязка на vendor-фичи (Realtime, RLS-политики, Edge Functions) усложняет переезд — это и есть привязка.
- Если позже понадобится локализация данных, а выбрана зарубежная платформа — придётся переезжать. Решай сейчас по аудитории и типу данных.
- Бесплатный tier Supabase ставит проект на паузу при простое и ограничивает строки/трафик — для боевого продукта посчитай цену на росте.
- БД и ORM — две части одного решения «слой данных», живут в одном ADR.
