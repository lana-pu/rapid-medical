# AI-фичи в продукте через OpenRouter

Запускай, когда в `docs/spec.md` есть AI-функции продукта (классификация, генерация, перевод, суммаризация, чат-ассистент и т.п.). Сервер ходит к модели через один API-ключ и отдаёт ответ пользователю.

Нужно на входе: серверная часть (API-роуты) и БД — для лимитов и логов расхода.

Провайдер по умолчанию — OpenRouter: один ключ и endpoint на много моделей (Claude, GPT, Gemini, DeepSeek, Kimi, Qwen, Llama), прозрачный расход, pay-as-you-go, смена модели без смены вендора. Если в проекте уже подключён другой провайдер — используй его, принципы ниже те же.

## 0. Сначала разбор, потом код
Разбери с пользователем ВСЕ AI-фичи из спеки (не только первую): что делает каждая, как работает, что за чем идёт, какая модель подходит по цене/качеству. Есть скилл `/new-feature` — используй его (интервью → бриф → реализация); нет — задай уточняющие вопросы по спеке, покажи план и реализуй после согласования.

## 1. Ключ
Попроси пользователя: зарегистрироваться на openrouter.ai, пополнить баланс (на отладку и первые фичи хватает ~$10), создать ключ в Settings → API Keys.
Создай/дополни `.env.local` и `.env.production` плейсхолдером `OPENROUTER_API_KEY=впиши-сюда-свой-OpenRouter-ключ` и скажи пользователю открыть файл и вписать ключ — не в чат и не в терминал. Ты читаешь его только через `process.env.OPENROUTER_API_KEY`. Проверь, что `.env.*` в `.gitignore`.

## 2. API-роут — `src/app/api/ai/route.ts`
```ts
export async function POST(req: Request) {
  const session = await getSession()
  if (!session) return Response.json({ error: 'unauthorized' }, { status: 401 })
  const { prompt } = await req.json()

  const response = await fetch('https://openrouter.ai/api/v1/chat/completions', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${process.env.OPENROUTER_API_KEY}`,
      'Content-Type': 'application/json',
      'HTTP-Referer': process.env.NEXT_PUBLIC_APP_URL!,
      'X-Title': '<Имя продукта>',
    },
    body: JSON.stringify({
      model: process.env.OPENROUTER_MODEL,
      messages: [
        { role: 'system', content: '<инструкция фичи>' },
        { role: 'user', content: prompt },   // ввод пользователя — отдельным сообщением, не вклеен в system
      ],
    }),
  })

  if (!response.ok) return Response.json({ error: 'ai_unavailable' }, { status: 502 })
  const data = await response.json()
  return Response.json({ result: data.choices[0].message.content })
}
```
Обрабатывай ошибки провайдера явно: `402` (кончились кредиты), `429`, таймауты — понятное сообщение пользователю и запись в лог, а не молчаливый провал. Для длинных ответов — стриминг.

## 3. Безопасность и расход
- Ключ только в серверном env, никогда во frontend; все AI-вызовы — через бэкенд.
- Rate limit на `/api/ai/*` (middleware или Redis/Upstash).
- Лимит расхода на пользователя в день (напр. поле/таблица `aiUsage`: запросы и токены).
- Логирование запросов (модель, токены, стоимость, статус) в БД — для аналитики и аудита.
- Пользовательский ввод не смешивай с системными инструкциями; у модели нет доступа к данным и действиям сверх прав пользователя.

## 4. Выбор модели
Предложи пользователю варианты под каждую фичу с компромиссом цена/качество — он выбирает. Не каждой фиче нужна дорогая модель:
- **сложное** (рассуждения, длинные ответы, качество критично) — топовые модели (линейки Claude Sonnet/Opus, GPT, Gemini Pro);
- **простое и массовое** (классификация, теги, короткие ответы) — дешёвые (Claude Haiku, DeepSeek, Kimi, Qwen, Llama) — в разы дешевле.

Точные id и цены проверь на openrouter.ai/models — каталог меняется. Модель — через env, можно разные под разные фичи:
```
OPENROUTER_MODEL=<топовая модель>
OPENROUTER_MODEL_CHEAP=<дешёвая модель>
```

## 5. Реализация фич
Реализуй все согласованные AI-фичи из спеки, каждой — свою модель по правилу выше.
Принцип: **AI объясняет, код считает** — числа (суммы, балансы, подсчёты) считаются в SQL/коде; AI доверяем текст: пересказ, классификацию, генерацию.

## После реализации
1. Покажи работающие AI-фичи.
2. ADR в `docs/memory/decisions/`: выбор провайдера, модели под фичи (где дешёвая, где топовая), лимиты.
3. `docs/spec.md` — раздел «AI»: фичи, лимиты расхода, поведение при недоступности AI (fallback).
4. `docs/memory/infrastructure.md` — провайдер, ENV-переменные, где смотреть расход.
