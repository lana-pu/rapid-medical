# Бэкап `.env` и передача проекта другому разработчику

Запускай, когда нужна запасная копия секретов (переустановка, потеря машины) или проект передаётся/открывается другому человеку.

Нужно на входе: `.env.local` (вне git, права 600) и `.env.example` в репозитории — если нет, сначала `development/prompts/env-secrets.md`.

Результат: выбранный и настроенный способ бэкапа секретов + чеклист передачи проекта.

## Шаг 1 — Варианты бэкапа

Покажи таблицу плюсов/минусов и дай выбрать:

| Вариант | Плюсы | Минусы |
|---|---|---|
| Менеджер секретов (1Password / Bitwarden / Doppler) | шифрование, удобный шеринг с командой | аккаунт, часто подписка |
| Личное облако (iCloud Drive / Google Drive / Dropbox) — копия или симлинк | синхронизация между своими машинами | провайдер хранит файл (без E2E), взлом аккаунта = утечка; только для некритичных dev-секретов, не для платёжных ключей и доступа к проду |
| Зашифрованный файл (`age`/`gpg`: `.env.local` → `.env.local.age`) | можно хранить хоть в облаке, хоть в приватном репо — без ключа бесполезен | нужно хранить ключ расшифровки отдельно |
| Локально + ручной бэкап на внешний диск | просто | легко забыть обновить |

## Шаг 2 — Настрой выбранный вариант

- **Облако:** команда копии (`cp`) или симлинка в облачную папку; ещё раз предупреди, что критичные секреты туда не кладутся. Симлинк — всегда актуален, но на второй машине может быть старая версия до синхронизации; копия предсказуемее, но обновляется вручную. iCloud становится E2E только с включённой Advanced Data Protection.
- **age/gpg:** настрой шифрование; `.gitignore` пропускает в git только зашифрованный файл (`!.env.local.age`), ключ/пароль — не в репо.
- **Менеджер секретов:** создай запись/vault для проекта, опиши, как восстановить `.env.local` из него.

## Шаг 3 — Передача проекта разработчику

- Код — через git: пригласить в private-репозиторий как collaborator, не архивом.
- `.env.example` он получает из репо.
- Реальные значения — **никогда** открытым текстом в чат/почту/мессенджер. Каналы: общий vault менеджера секретов, одноразовая ссылка (onetimesecret / yopass / Bitwarden Send), `age`/`gpg`-файл с паролем по отдельному каналу.
- Доступ к серверу — добавить **публичный** ключ разработчика в `authorized_keys` на VPS; свой приватный ключ и свой аккаунт GitHub не передавать.
- Где возможно — выдать собственные ключи (свой API-ключ, свой токен), чтобы при уходе отозвать только его доступ.

Одноразовая ссылка «не открылась» → её уже кто-то открыл: секрет скомпрометирован, отозвать. Секрет ушёл открытым каналом → отозвать у провайдера и выпустить новый (сообщение не «забрать назад»).

## После выполнения

Покажи: таблицу вариантов, команды настройки выбранного, чеклист передачи «чтобы поднять проект с нуля»: репо, `.env.example`, реальные значения (безопасным каналом), доступ к серверу, доступ к доменам и провайдерам.
