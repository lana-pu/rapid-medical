# Extensions Change — правка AI-фич, писем, REST API, алертов и уведомлений

Запускай, когда меняются расширения сервиса: AI-фича, email-шаблон, публичный REST API, Telegram-алерты владельцу, центр уведомлений.

Нужно на входе: `docs/spec.md`; соответствующая подсистема уже есть в коде.

Порядок всегда один: **сначала `docs/spec.md` (или профильный док), потом код.**

## Что меняется → что делать

| Что меняется | Алгоритм |
|---|---|
| Новая AI-фича | описать в `spec.md` (вход, выход, где в UI, лимиты) → серверный endpoint (системный промт и модель задаются на сервере, ключ провайдера только в env) → подключить к UI с loading / error состояниями |
| Изменился или добавился email-шаблон | правка в папке шаблонов писем (например, `src/emails/`) → обновить `spec.md → Уведомления` (триггер, получатель, переменные `{{...}}`) |
| Новый endpoint REST API | роут `/api/v1/*` + scope API-ключа → проверка ключа и scope в роуте → обновить `docs/api.md` |
| Новое событие для Telegram-алерта | вызвать существующий хелпер алертов (например, `sendTelegramAlert(...)`) в месте события; токен бота и chat id — только из env |
| Изменился центр уведомлений | правка в модуле уведомлений → обновить `spec.md` (события, тексты, кто получает) |

## Проверка

1. Фича работает end-to-end (UI → endpoint → результат).
2. Новый AI-endpoint или REST-роут — прогони `modules/development/prompts/security-check.md` по diff: prompt injection, доступ без ключа/с чужим scope, rate limit, секреты не утекают в клиент и логи.
3. Покажи diff спеки/доков и кода.
