# Обновление снимка инфраструктуры — `docs/memory/infrastructure.md`

Запускай после изменений бэкенда/инфры: подключили БД, auth, хранилище, email-провайдера, мониторинг, новый сервис, порт или ENV. Снимок должен отражать реальность — по нему работает любой следующий агент.

Нужно на входе: `docs/memory/infrastructure.md` (нет — создай с разделами ниже).

## Что сделать

1. Сверь снимок с реальностью: прочитай `docker-compose.yml`, `deploy.sh` / скрипты деплоя, конфиг nginx, схему ORM, конфиг auth, `middleware`, список ключей в `.env.example` / `.env.*` (только имена переменных — значения секретов в память не пиши).

2. Обнови или добавь разделы — только те, что есть в проекте:

**БД**
- где живёт база (docker-сервис `db` / managed-провайдер), версия Postgres;
- ORM и путь к схеме (напр. `prisma/schema.prisma`), папка миграций, как применяются на проде (`migrate deploy` в `deploy.sh`);
- клиент-singleton (напр. `src/shared/db.ts`);
- локальная разработка: SSH-туннель к серверной БД или локальный контейнер;
- бэкапы: скрипт, расписание, ретеншн, путь.

**Auth**
- библиотека (по ADR), конфиг (напр. `src/shared/lib/auth.ts`), API-роут (`app/api/auth/[...all]/route.ts`);
- сессии: где хранятся, срок жизни, продление;
- cookie: `HttpOnly` + `Secure` (prod) + `SameSite=Lax`;
- ENV: секрет и base URL auth — в `.env.local` и `.env.production`, значения разные;
- защита роутов (middleware: matcher, rate limit, auth-redirect) и лимиты (напр. 5/мин на `/api/auth/*`, 3/час на регистрацию).

**Хранилище файлов**, **Email**, **AI-провайдер**, **Оповещения/мониторинг** — сервис, ENV-переменные (имена), endpoint/домен, лимиты, куда уходят алерты.

**Доступы и ENV** — какие переменные где лежат (`.env.local` / `.env.production` / секреты CI), без значений; напр. `DATABASE_URL` локально через туннель, на проде — по имени docker-сервиса.

**Ключевые файлы** — схема БД, клиент БД, конфиг auth, middleware, функции отправки писем/алертов.

3. Если принято новое решение (напр. сменили ORM) — пиши новый ADR в `docs/memory/decisions/`, не переписывай старый задним числом; в снимке — текущее состояние со ссылкой на ADR.

4. Удали из снимка то, чего больше нет (снесённые сервисы, порты, переменные).

В конце покажи обновлённые разделы `infrastructure.md` (diff).
