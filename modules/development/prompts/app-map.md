# Карта приложения — маршруты, доступ, граф переходов (MD + HTML)

Запускай, когда в приложении есть реальные маршруты и нужно зафиксировать карту экранов (а также после добавления/удаления экранов).

Нужно на входе: Next.js-приложение с маршрутами; `docs/PRD.md` или `docs/spec.md` со списком экранов.

Результат: `docs/app-map.md` (маршруты, роли, mermaid-граф) и `docs/app-map.html` (та же карта как интерактивная страница).

## Промт

```
Создай docs/app-map.md И docs/app-map.html по фактическому состоянию приложения.

Прочитай:
- маршруты всех приложений (Next.js routing): в монорепо — development/apps/app/src/app/
  и development/apps/landing/src/app/; в одном приложении — src/app/;
- middleware.ts (proxy.ts) сервиса — логика защиты;
- docs/PRD.md / docs/spec.md — список экранов.

Сформируй docs/app-map.md:

# App Map — <продукт>

## Маршруты и доступ

| URL | Экран | Доступ | Описание |
|---|---|---|---|
| / | Главная | все | Лендинг или дашборд |
| /login | Логин | только не-авторизованный | Форма входа |
| /register | Регистрация | только не-авторизованный | Форма регистрации |
| /dashboard | Дашборд | только авторизованный | Главный экран сервиса |
| /<feature> | <Основной флоу> | только авторизованный | По PRD |
| /settings | Настройки | только авторизованный | Профиль, пароль, удаление |

(Только РЕАЛЬНЫЕ маршруты из кода — не выдумывай.)

## Карта переходов (Mermaid)

```mermaid
graph LR
  Home[/] --> Login[/login]
  Home --> Register[/register]
  Login --> Dashboard[/dashboard]
  Register --> Dashboard
  Dashboard --> Feature[/<основной флоу>]
  Dashboard --> Settings[/settings]
  Settings -- "выйти" --> Home
```

(Адаптируй под реальные переходы — Header / Sidebar / все <Link> и redirect.)

## UI-состояния (для каждого экрана)
- Загрузка
- Пустой
- Заполненный
- Ошибка

## Глобальные правила доступа
- Какие экраны публичные, какие требуют авторизации (по middleware).
- Неавторизованный → куда редирект.
- Авторизованный на /login или /register → куда редирект.

---

docs/app-map.html — генерируй из ТЕХ ЖЕ данных одним проходом, чтобы карты не
разошлись. Самодостаточная страница:
- один файл, без сборки: mermaid через CDN
  (<script type="module"> import mermaid from "https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.esm.min.mjs"; mermaid.initialize({ startOnLoad: true }); </script>);
- сверху — граф переходов: узлы = экраны (название + маршрут), стрелки подписаны
  действием («выйти», «после логина», «открыть заказ»);
- подсветка узлов по доступу (гость / авторизованный / админ) через classDef + легенда;
- ниже — таблица маршрутов и ролей;
- заголовок и дата генерации.

ПОКАЖИ МНЕ:
- docs/app-map.md (mermaid рисуется в Markdown Preview);
- docs/app-map.html, открытый в браузере: граф с подсветкой по ролям и таблица.
```

## Edge cases

- Есть admin-зона — отдельный раздел про неё.
- Есть API без UI (вебхуки, public API) — в карте не показываются; перечисли их в `docs/api-routes.md` (опционально).
