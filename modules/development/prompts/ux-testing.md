# UX Testing — прогон через браузер: адаптив, состояния, интерактив

Универсальный промт UX-тестирования. В Claude Code оборачивается в скилл `/ux-testing` (раздел «Скилл-обёртка» ниже); в Codex/Cursor: «прочитай `ux-testing.md` и выполни».

## Когда применять

- После добавления новой страницы или крупной правки UI — проверка адаптива и состояний.
- Перед публичным запуском — финальный регрессионный аудит.
- Smoke-проверка после деплоя (2–3 главных сценария на боевом адресе).
- «Что-то сломалось на телефоне» — диагностический прогон.

## Параметры (спросить, если не указаны)

- **URL** — `http://localhost:3000` или прод.
- **Страницы / маршруты** — список (по умолчанию — из `docs/app-map.md`).
- **Разрешения** — по умолчанию 320 / 768 / 1024 / 1440 px (+ портрет/ландшафт для мобильных).
- **Тестовый аккаунт** — для страниц за логином; на проде — отдельная учётка для аудита.
- **Сценарии** — если нужен путь пользователя (по умолчанию — из `docs/test-cases.md`).

## Шаги

1. **Браузер — ровно один на прогон**, закрыть в конце даже при падении (`try/finally`). Playwright или вручную в DevTools.
2. **Dev-сервер** — если поднимаешь, сначала освободи порт (`:3000`), не плодить зависшие серверы (`docs/rules/process-hygiene.md`).
3. **Обход:** каждая страница из списка × каждое разрешение по очереди.
4. **Состояния:** на каждом экране — empty, loading, error, заполненное (по `docs/screens/<экран>.md`).
5. **Интерактив:** прокликать КАЖДЫЙ интерактивный элемент и проследить полную цепочку смены состояния — что хендлер читает / пишет / сбрасывает по пути. Ловит «тихую отмену»: кнопка ставит `setComposeMode(true)`, затем `selectThread(null)` побочно сбрасывает `composeMode:false` — визуально кнопка ничего не делает.
6. **Адаптив:** нет горизонтального скролла, ничего не вылазит за блоки, touch target ≥ 44×44px, hover не залипает на таче.
7. **Playwright-проверки — web-first:** `expect(locator).toBeVisible()`, авто-ожидание локаторов, ожидание конкретного события (`waitForResponse`). Никаких `waitForTimeout(5000)` / `sleep`. Переходы — `waitUntil: 'domcontentloaded'` с таймаутом.
8. **Скриншоты проблем** — в `.tmp-ux/` (в `.gitignore`).
9. **Отчёт** — `docs/audits/ux-audit-<YYYY-MM-DD>.md`.

## Edge cases

- Страница за логином — тестовый аккаунт; на проде — отдельная учётка для аудита, не реальный пользователь.
- Нет Google Chrome — не помеха: Playwright ставит свой движок (`npx playwright install`); нет Chromium — WebKit.
- 5+ страниц через Playwright — Page Object на страницу (локаторы и методы `goto()`, `search()` в одном месте). Локаторы — `getByRole` / `getByLabel`, `data-testid` — последняя инстанция.
- Ручной прогон в DevTools — тот же чек-лист, без скриптов.

## Что должно получиться

- `docs/audits/ux-audit-<YYYY-MM-DD>.md` с таблицей страница × разрешение × состояние (✅ / 🟡 / 🔴) и находками по интерактиву.
- Скриншоты проблем в `.tmp-ux/`.
- Список задач на починку с приоритетом.

## Антипаттерны

- `waitForTimeout` / `sleep` — флакающий тест; ждать конкретного условия.
- Новый браузер на каждую страницу вместо нового контекста.
- Проверять только «круглые» брейкпоинты — ломается между ними.
