# Секреты — `.env.local`, `.env.example`, `.gitignore`

Запускай при создании проекта и каждый раз, когда появляется новая переменная окружения.

Результат: секреты живут в `.env.local` (вне git, права 600), шаблон `.env.example` без значений лежит в репозитории, в коде нет захардкоженных ключей.

Правила: секреты (API-ключи, пароли, токены) — только в env-файлах, в коде — `process.env.X`. `.env.local` — локальная разработка, `.env.production` — сервер (создаётся на сервере, не в репо), `.env.example` — публичный шаблон без значений. Значения секретов пользователь вписывает прямо в файл, не в чат.

## Шаги

1. **`.gitignore`** в корне проекта содержит (добавь недостающее):
   ```
   .env
   .env.*
   !.env.example
   ```
2. **`.env.example`** — только имена переменных, которые реально использует проект, с пустыми или безопасными значениями. Пример:
   ```
   # Auth
   NEXTAUTH_SECRET=
   NEXTAUTH_URL=http://localhost:3000
   # Database
   DATABASE_URL=
   ```
3. **`.env.local`** (если нет): `cp .env.example .env.local` и `chmod 600 .env.local`. Попроси пользователя вписать значения в файл.
4. **Захардкоженные секреты** в коде:
   ```bash
   grep -rnE 'sk-[A-Za-z0-9]{20,}|sk_live_|ghp_[A-Za-z0-9]{36}|gho_|github_pat_|AKIA[0-9A-Z]{16}|AIzaSy|xox[bp]-|glpat-' src/
   ```
   Нашлось → вынести в env, в коде `process.env.X`; переменную добавить в `.env.example`. Обязательные переменные без значения → явная ошибка при старте, не `process.env.X || 'fallback'`.
5. **История git** (если репозиторий есть):
   ```bash
   git log --all --full-history -- '.env*'
   ```
   В истории есть env-файл с реальными значениями → сначала **отозвать секреты у провайдеров и выпустить новые**, потом чистить историю (`git filter-repo` или BFG). Боты находят слитые ключи за минуты.

Покажи пользователю: `.gitignore`, `.env.example`, `ls -l .env.local` (права `-rw-------`).

## Новая переменная окружения

Добавь имя в `.env.example`, значение — пользователь в `.env.local`; на сервер — по `development/prompts/deploy-cheatsheet.md` (сценарий «новый ENV-секрет»).

## Edge cases

- Windows: права через NTFS; в WSL2 `chmod` работает как в Linux.
- Без `.env.local` приложение может упасть на чтении переменных — заполнить перед запуском фич, которые их используют.
- Запасная копия секретов и передача проекта другому человеку — `development/prompts/env-backup-handoff.md`.
