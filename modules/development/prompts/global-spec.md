# Глобальная логика `docs/screens/_global.md` + её соблюдение

Запускай, чтобы описать сквозную логику поверх экранов (auth guard, роли, ошибки сети, успехи, loading, двойной submit, даты, empty states, уведомления, email) и зашить её соблюдение в правило и/или хук.

Нужно на входе: приложение с авторизацией; `AGENTS.md` проекта; для хука — `.claude/settings.json`.

## Промт

```
Создай docs/screens/_global.md по шаблону (адаптируй под реальный код и маршруты):

# Глобальная логика

## Auth Guard
- Все экраны кроме /, /login, /register требуют авторизации
- Неавторизованный → редирект на /login
- Авторизованный на /login или /register → редирект на /dashboard
- Реализация: <путь к middleware.ts / proxy.ts сервиса> (matcher для (app)/* и (auth)/*)

## Роли и доступ

| Роль | Что видит |
|---|---|
| user (по умолчанию) | свои данные, свои ресурсы |
| admin (если есть админка) | все данные + панель /admin/* |

## Глобальные уведомления

| Триггер | Канал | Кто получает | Текст / Действие |
|---|---|---|---|

## Email-шаблоны

| ID | Когда отправляется | Тема | Переменные |
|---|---|---|---|

## Поведение при ошибках сети
- Все API-вызовы с обработкой ошибок
- Сетевая ошибка → toast «Нет соединения. Попробуйте позже» + retry
- Никаких unhandled rejections в production-консоли
- Критичные операции (сохранение, оплата) — confirm-modal перед повтором

## Сообщения об успехе
- Все формы при успехе показывают toast
- Toast success-цвета из DESIGN.md, текст из спеки экрана
- Автозакрытие через 3 секунды, интерфейс не блокирует

## Loading состояния
- Все async-действия с loading-индикатором
- Кнопки на время запроса блокируются и показывают spinner
- Списки — <Skeleton> из UI-кита

## Защита от двойного отправления форм
- Submit блокируется после клика до завершения запроса
- Двойной клик не создаёт двух записей

## Дата и время
- Отображение в локали пользователя (DD.MM.YYYY или относительное «5 минут назад» через
  date-fns / Intl)
- В БД — UTC (timestamp)

## Empty State
- Иконка
- Заголовок (одно предложение, что здесь должно быть)
- Описание (одно предложение, как это сюда добавить)
- CTA-кнопка к ключевому действию

---

Затем ОБЯЗАТЕЛЬНО зашей соблюдение _global.md в инфраструктуру. СНАЧАЛА СПРОСИ МЕНЯ,
каким слоем, с короткой рекомендацией:

- ЖЕЛЕЗНОЕ ПРАВИЛО в AGENTS.md (минимум). Строка в раздел всегда-on правил:
  «При создании/изменении экрана или фичи — сначала прочитай docs/screens/_global.md и
  соблюдай сквозные правила (auth guard, ошибки сети, успехи, loading, защита от
  двойного submit, формат дат, empty states); меняется само правило — правь _global.md
  в ТОМ ЖЕ коммите». Плюс: AI понимает смысл и может обновить файл. Минус: в длинной
  сессии может не вспомнить.
- SOFT-REMINDER ХУК (вторым слоем). PostToolUse на Edit|Write|MultiEdit: при правке
  UI-файлов (src/app, src/features, src/widgets, src/views, src/pages) печатает
  напоминание в stderr и добавляет через additionalContext «прочитай _global.md, сверь;
  при расхождении сначала обнови _global.md, потом код»; маркер в .claude/.cache глушит
  на ~10 мин. Зарегистрируй в .claude/settings.json (добавь в массив PostToolUse рядом
  с существующими, не затирай), задокументируй в docs/rules/hooks-guardrails.md.
  Плюс: срабатывает детерминированно. Минус: только напоминает, смысл не проверяет.

Рекомендация: ОБА (правило — смысл, хук — гарантия срабатывания). Минимум — правило.
После выбора — поставь, существующее не затирай.

ПОКАЖИ МНЕ:
- финальный docs/screens/_global.md;
- что зашито: строку правила в AGENTS.md и/или скрипт хука + регистрацию в
  .claude/settings.json.
```

## Edge cases

- Своя система уведомлений / специфические сквозные правила — отдельный раздел в `_global.md`.
- Разделы «Глобальные уведомления» и «Email-шаблоны» могут быть пустыми, пока рассылок нет.
