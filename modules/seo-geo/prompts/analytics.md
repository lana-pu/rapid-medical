# Аналитика публичного сайта — счётчик и ключевые события

Запускай, когда публичный сайт выложен в прод и нужно видеть посетителей, источники и конверсию до целевого действия (CTA, signup).

Нужно на входе: публичный сайт на прод-домене; страница `/privacy` (если инструмент ставит cookie — см. `development/prompts/legal-pages.md`).

## Промт

```
Помоги подключить аналитику к публичному сайту продукта. Сначала уточни у меня
аудиторию и юрисдикцию (РФ / EU / US / другое) и разбери варианты с плюсами и
минусами под неё — дефолт не навязывай.

1. Яндекс.Метрика
   + Бесплатно, вебвизор и тепловые карты из коробки; данные в РФ; в пару к
     Yandex Webmaster.
   - Ставит cookie → нужно уведомление/согласие. Данные у Яндекса.
2. Self-host (Plausible / Umami)
   + Данные на своём сервере, без кук → без cookie-баннера (удобно и для 152-ФЗ, и для
     GDPR), лёгкий скрипт.
   - Ещё один контейнер в docker-compose, обновлять самому. Нет вебвизора.
3. Google Analytics 4
   + Глобальный стандарт, бесплатно, мощные отчёты, связь с Google Ads.
   - Данные у Google за рубежом (для РФ — риск по 152-ФЗ при ПДн в событиях; для EU —
     нужен consent по GDPR/ePrivacy), порог входа выше.
4. Другой инструмент (PostHog, Matomo, Fathom, Simple Analytics…) — если я назову,
   разбери так же.

После моего выбора:

1. РЕГИСТРАЦИЯ У ПРОВАЙДЕРА — проведи пошагово: куда зайти, что создать, где взять
   код и ID. Не предполагай, что аккаунт есть.
   - Яндекс.Метрика: metrika.yandex.ru → «Добавить счётчик» → адрес прод-домена и
     название → включить Вебвизор / карты скролла и кликов → создать → вкладка
     «Счётчик» → скопировать ВЕСЬ код (<script>…</script> + <noscript>) и номер
     счётчика (8 цифр).
   - GA4: analytics.google.com → Admin → Account → Property (часовой пояс, валюта) →
     Data Stream → Web (URL сайта) → «View tag instructions» → «Install manually» →
     скопировать ВЕСЬ Google tag (gtag/js?id=G-… + инициализация) и Measurement ID
     G-XXXXXXXXXX.
   - Self-host (Plausible / Umami): подними контейнер в docker-compose рядом с
     приложением, за nginx на поддомене с HTTPS (stats.<домен>), обнови
     docs/memory/infrastructure.md; в веб-панели заведи первого пользователя → «Add a
     website» по домену → возьми data-domain и адрес скрипта.
   В конце прямо попроси: «пришли готовый код счётчика из кабинета и его номер/ID».
   Без кода и ID дальше не иди.

2. ПОДКЛЮЧЕНИЕ. Подключи присланный код через next/script (strategy="afterInteractive").
   ID / Measurement ID / домен не хардкодь — в .env приложения сайта
   (NEXT_PUBLIC_ANALYTICS_ID или аналог), значение впишу сам. Self-host — скрипт с
   адреса своего инстанса.
   ГДЕ: на ВСЕХ страницах публичного сайта (/, /privacy, /terms, /signup) и НЕ внутри
   сервиса за логином. Это маркетинговая воронка сайта, не продуктовая аналитика.
   - Сайт и сервис в одном Next.js: не клади счётчик в корневой layout.tsx — выдели
     публичные страницы в route-group (site) со своим layout и подключи там; у (app)
     свой layout без счётчика.
   - Монорепо (apps/landing + apps/app) или сервис на поддомене: счётчик только в
     layout лендинга/сайта.

3. СОБЫТИЯ — 2-3, не больше, все на публичном сайте:
   - клик по основному CTA;
   - начало регистрации (открыл /signup);
   - signup завершён.
   Целевое действие внутри сервиса этим счётчиком не считается — это отдельная
   продуктовая аналитика. Тонкая обёртка trackEvent(name) в одном месте
   (src/shared/lib/analytics.ts приложения сайта), вызовы — из хендлеров.

4. COOKIE. Инструмент ставит cookie (Метрика / GA4 / др.) — добавь уведомление или
   согласие по требованиям выбранной юрисдикции (для EU — блокировать скрипт до
   согласия) и пункт в политике конфиденциальности (/privacy). Self-host без кук —
   баннер не нужен.

5. ADR. Зафиксируй в docs/memory/decisions/ADR-XXX-analytics.md (что выбрали, почему,
   какие события, что счётчик только на публичном сайте) и строку в
   docs/memory/INDEX.md.

ПОКАЖИ МНЕ:
- выбор и короткое сравнение под мою аудиторию и юрисдикцию;
- инструкцию регистрации у провайдера;
- что ты дождался готового кода перед вставкой;
- где лежит ID (.env), куда вставлен счётчик (layout сайта, не сервиса), обёртка trackEvent;
- что в реалтайме счётчик увидел визит на проде.
```

## Edge cases

- ID счётчика не секрет (виден в HTML), но держим в `.env` (`NEXT_PUBLIC_*`), чтобы dev/prod не путались.
- В события НЕ класть email, имя, телефон — только обезличенные идентификаторы (иначе ПДн утекают во внешнюю аналитику).
- Self-host — ещё один контейнер и поддомен с HTTPS; не готовы поддерживать — облачный инструмент проще.
- «Считать всё подряд» — антипаттерн: 2–3 события воронки «зашёл → signup → целевое действие».
- На localhost счётчик не подключать или фильтровать свой трафик.
