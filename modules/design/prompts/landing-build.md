# Вёрстка лендинга по брифу + отдельный деплой-юнит

Запускай для публичного продукта, когда нужен лендинг. Для внутреннего инструмента не нужен.

Нужно на входе: `docs/landing-brief.md` (если нет — сначала `product/prompts/landing-research-brief.md`), `docs/DESIGN.md`, `docs/spec.md`. Для отдельного деплоя — монорепо (`development/apps/landing` + `packages/ui`, см. `development/prompts/monorepo-split.md`) и настроенный деплой-скрипт.

## Где живёт

- В монорепо лендинг — отдельное приложение `development/apps/landing/`, деплоится независимо, токены и компоненты импортит из `@repo/ui` (`development/packages/ui`). Сервис — `development/apps/app`.
- Без монорепо (одно приложение) — лендинг это роут `/` (группа `(public)`) в `src/app/`.
- Адреса: `/` — лендинг; `/login`, `/signup` — auth на стороне сервиса; `/app` (или поддомен `app.`) — продукт за логином (выбор — `development/prompts/app-domain-placement.md`).

## Правила

**DESIGN.md → UIKit → Лендинг.**
1. Токены (цвета, шрифты, отступы) — только из `DESIGN.md`, общий слой темы — из `@repo/ui`. Не хардкодить.
2. Базовые UI-элементы — из `@repo/ui`. Блоки только для лендинга (Hero, PricingCard, ProductShowcase) — в `apps/landing/src/widgets/landing/`. Базовый элемент, нужный и сервису, — сначала в `@repo/ui`, потом в обоих.
3. Нет токена — сначала в DESIGN.md (и тему `@repo/ui`), прогнать lint, потом использовать.

**Производительность.**
- Серверный компонент со статическим рендером; `'use client'` — только на мелких интерактивных кусках (мобильное меню, аккордеон FAQ) в отдельных компонентах. Статический HTML кэшируется на nginx/CDN.
- Картинки только через `next/image` (`priority` для Hero, остальные ленивые), никакого голого `<img>`.
- Signup и внутренние переходы — `<Link>` из `next/link` (префетч); `<a href>` — только для внешних ссылок.
- Тяжёлые украшения (анимационные библиотеки, 3D, карусели, кликабельное демо) — через `next/dynamic`.

**Степень креатива — по брифу (раздел «Степень креатива»).** По умолчанию цвета и шрифты из DESIGN.md, лейаут, блоки и движение — свободно. «Близко к продукту» — держим стилистику сервиса. «Совсем другое, вплоть до отхода от токенов» — делаем по выбору, предупредив про риск для единства бренда. Выбора в брифе нет — спроси и порекомендуй «токены + свободные блоки».

**Инструменты доводки.**
- Claude Code: скилл `frontend-design` для нешаблонной вёрстки, затем `/critique` → `/polish` или `/bolder`. По ситуации: `/audit` (доступность, производительность, адаптив, P0–P3), `/quieter`, `/overdrive`, `/delight`, `/distill`, `/normalize`, `/typeset`, `/colorize`, `/arrange`, `/animate`, `/adapt`, `/harden`, `/optimize`, `/clarify`. Нет скиллов — поставь дизайн-плагин или применяй принципы ниже вручную.
- Codex / Cursor / без скиллов — принципы ниже вручную.

**Принципы нешаблонного лендинга.**
1. Один сильный визуальный якорь в Hero (крупная типографика, выразительный образ или композиция), а не «заголовок по центру + кнопка».
2. Явная шкала типографики, контраст display-заголовка и текста, нормальная межстрочка. Шрифты — из DESIGN.md.
3. Ритм и воздух: щедрые и неодинаковые отступы, асимметрия, разная высота секций; без монотонной центральной колонки.
4. Палитра из DESIGN.md, акцентный цвет — уверенно и дозированно (CTA, ключевые акценты).
5. Реальная иерархия; клише «три равные карточки в ряд» — только если оправдано контентом.
6. Анимация — по уровню из брифа (статика / сдержанно / заметный креатив); тяжёлое — через `next/dynamic`.
7. Hover и `cursor: pointer` на ВСЕХ кликабельных элементах при любом уровне анимации. Hover только для мыши: `@media (hover: hover) and (pointer: fine)` (в Tailwind проверь, что `hover:` срабатывает только при мыши); на таче обратная связь — `:active`.
8. Избегать AI-шаблона: фиолетовый градиент на всём, generic-иконки, одинаковые карточки, декоративные чёрточки у заголовков секций (только как осознанный приём), пустые маркетинговые фразы.

**Текст без AI-следов.** Когда тексты на странице — прогони `/avoid-ai-writing` (профиль `landing`), без скилла — `seo-geo/prompts/avoid-ai-writing.md`. Вычитывать Hero, Features, «для кого», How it works, FAQ, CTA. Убрать: пустые промо-фразы и псевдо-выгоды («всё в одном месте», «работает в браузере»), инфляцию значимости, антитезу «не X, а Y», тройные перечисления ради ритма, однородный ритм предложений, связки-затычки. Заменять фактами из брифа.

**Показ продукта — живой UI, не стоковые картинки.**
- Приоритет — перевёрстка реальных компонентов продукта (базовые из `@repo/ui`, доменные — по образцу из `apps/app`) в рамке телефона/браузера: компонент `apps/landing/src/widgets/landing/ProductShowcase`, реалистичные демо-данные из домена (не Lorem ipsum).
- Скриншот — только fallback для видео, canvas/WebGL/3D, карт, тяжёлого data-gated UI: снять реальный экран запущенного продукта (Claude Code — скилл `webapp-testing`/Playwright на `http://localhost:3000` с демо-данными; иначе вручную), сохранить webp/avif нужного размера, подать через `next/image` (lazy) в той же рамке.
- Что показывать (1–3 экрана) — из брифа. Место — Hero рядом с крючком и/или блок «как это выглядит внутри» после Features / How it works.
- Нельзя: стоковые dashboard-mockup, абстрактные 3D-интерфейсы, нарисованный UI, не совпадающий с реальным.

**Навигация, ссылки, типографика.**
- Якоря скроллят плавно (`scroll-behavior: smooth` или `scrollIntoView({ behavior: 'smooth' })`) со `scroll-margin-top` под липкую шапку.
- Якоря на блоки главной из футера и внутренних страниц — `href="/#секция"`, не голый `#секция`. Проверять с `/privacy`, `/terms`, `/cookies`.
- Внешние ссылки и `/privacy`, `/terms`, `/cookies` — `target="_blank" rel="noopener noreferrer"`.
- Висячие предлоги и союзы (в, и, с, к, о, на, по, не, что…) привязывать к следующему слову неразрывным пробелом (`&nbsp;`), особенно в Hero и заголовках.

## Структура (минимум)

1. **Hero** — что за продукт, для кого, главная ценность одним предложением (крючок из брифа), CTA из брифа.
2. **Боли / «узнаёте себя»** — зеркало триггеров и болей главного сегмента.
3. **Features** — 3–5 ключевых возможностей, каждая привязана к job/результату.
4. **Для кого / сценарии** — если в брифе несколько сегментов (2–4 «для X → ценность»); один сегмент — пропустить.
5. **How it works** — 3 шага пути пользователя.
6. **Витрина продукта** — живой UI (см. выше).
7. **Social proof** — отзывы, логотипы, цифры, если есть.
8. **Pricing** — если продукт платный.
9. **FAQ** — возражения из брифа.
10. **Footer** — ссылки на `/privacy`, `/terms`, `/cookies`, контакты.

## Деплой — лендинг отдельным деплой-юнитом

- Своя сборка: `npm run build -w apps/landing` (контекст только лендинга).
- Свой сервис в docker-compose (`landing`): образ, порт, рестарт.
- Своя команда деплоя: `docker compose build landing && docker compose up -d landing`, без общего `up -d`.
- nginx: лендинг на корне домена `/`.
- Правка `packages/ui` раскатывается в оба приложения; правки в `apps/landing` — только в лендинг.

Независимость — автоматически в деплой-скрипте:
1. **Деплой по изменениям** — `git diff --name-only <last_sha> HEAD`: `apps/landing/` → лендинг, `apps/app/` → сервис, `packages/ui/` → оба.
2. **Авто-ассерт** — `StartedAt` контейнера сервиса до и после деплоя лендинга; сменился из-за деплоя лендинга → скрипт падает с exit 1. Собственный деплой сервиса его штатно перезапускает — ассерт ловит только рестарт из-за чужого деплоя.

```bash
# фрагмент deploy-скрипта: деплоим только изменившееся + ассерт независимости
CHANGED=$(git diff --name-only "$LAST_DEPLOYED_SHA" HEAD)
ui=$(grep -q '^development/packages/ui/'    <<<"$CHANGED" && echo 1)
ld=$(grep -q '^development/apps/landing/'    <<<"$CHANGED" && echo 1)
ap=$(grep -q '^development/apps/app/'        <<<"$CHANGED" && echo 1)
svc_before=$(docker inspect -f '{{.State.StartedAt}}' app 2>/dev/null)
if [ "$ld" ] || [ "$ui" ]; then docker compose build landing && docker compose up -d landing; fi
if [ "$ap" ] || [ "$ui" ]; then docker compose build app     && docker compose up -d app;     fi
if [ "$ld" ] && [ -z "$ap" ] && [ -z "$ui" ]; then
  [ "$(docker inspect -f '{{.State.StartedAt}}' app)" = "$svc_before" ] \
    || { echo "FAIL: сервис рестартнул при деплое лендинга"; exit 1; }
fi
```

Продакшен сложнее docker-compose — всё равно раздельные сборка и рестарт на приложение, с автоматической проверкой в деплой-скрипте.

```
packages/ui — общий, катится в оба, nginx-роутинг, правило независимости деплоев.

В конце запусти dev-сервер, открой http://localhost:3000, покажи скриншот, спроси,

```

## Проверка

1. Hero понятен с первого взгляда; все CTA ведут на signup.
2. Адаптив: на мобиле читается, ничего не разъезжается.
3. Витрина — перевёрстка реальных компонентов, чёткая на Retina; скрин только там, где живой разметкой нельзя.
4. Текст прогнан через avoid-ai-writing (профиль `landing`): конкретика из брифа, без промо-штампов.
5. Лендинг — отдельный деплой-юнит; в деплой-скрипте деплой по изменениям и авто-ассерт независимости.
6. `docs/memory/infrastructure.md` отражает новую топологию.
7. Якоря плавные и не уезжают под шапку; `/#секция` работает с внутренних страниц; внешние и юридические ссылки — в новой вкладке; hover не залипает на таче; нет случайных чёрточек у заголовков; висячие предлоги привязаны.
