# Адаптив-аудит — лендинг и публичные страницы + sweep продукта

Запускай перед публичным запуском и после вёрстки/правок лендинга и публичных страниц. Глубокий прогон — по публичным страницам (`/`, `/privacy`, `/terms`, `/cookies` и другим новым); по экранам за логином — быстрый контрольный sweep.

Нужно на входе: запущенное приложение (dev или прод).

Главный критерий: ничего не вылазит за блоки и за край экрана, где это не задумано (нет горизонтального скролла, контент не обрезан и не выходит из контейнера) — на всех размерах и соотношениях сторон (портрет/ландшафт).

## Размеры

| Размер | Устройство | Назначение |
|---|---|---|
| 375×667 | iPhone SE | минимум mobile |
| 390×844 | iPhone 14/15 | стандарт mobile |
| 768×1024 | iPad portrait | tablet |
| 1280×800 | MacBook | desktop |
| 1920×1080 | Wide desktop | широкий экран |

## Прогон

### 1. DevTools

Chrome DevTools (`Cmd+Opt+I` → `Cmd+Shift+M`): все размеры из таблицы + плавно тянуть ширину и высоту (между брейкпоинтами ломается чаще всего), портрет и ландшафт. По возможности — глазами на реальных телефоне и планшете.

### 2. Чек-лист

**Публичные страницы (основной фокус)** — по каждому размеру и соотношению сторон:

- [ ] Ничего не вылазит за блоки и край экрана (если не задумано).
- [ ] Нет горизонтального скролла.
- [ ] Hero и секции держат сетку: колонки не наезжают, отступы не схлопываются, фон не обрезает контент.
- [ ] Картинки и фоны масштабируются, не растягиваются, не вылезают за viewport.
- [ ] Текст читается без зума, заголовки не разваливаются и не обрезаются.
- [ ] Длинные слова переносятся.
- [ ] Touch target ≥ 44×44px, CTA виден на первом экране.
- [ ] Мобильное меню открывается и закрывается.
- [ ] На таче нет hover и «залипшего» hover после тапа: hover в `@media (hover: hover) and (pointer: fine)`, на таче обратная связь — `:active`.
- [ ] Cookie-баннер на мобиле не перекрывает Hero/CTA, кнопки влезают и кликаются, после согласия исчезает.
- [ ] В мобильном ландшафте Hero и CTA доступны.

**Продукт (быстрый sweep)** — Login, основной экран за логином, главный флоу:

- [ ] Нет горизонтального скролла и явного overflow.
- [ ] Меню, формы, кнопки на месте и кликаются.
- [ ] Ничего не уехало после последних правок.

### 3. Скриншоты через Playwright (опционально)

Напиши одноразовый скрипт под текущий проект: обход размеров из таблицы × портрет/ландшафт по публичным страницам (+ sweep `/login`, `/app`), скриншоты в `docs/screenshots/adaptive/`.

Требования к любой браузерной автоматизации (иначе процессы текут и съедают память):
- ровно один запуск браузера на скрипт, с таймаутом на запуск;
- весь обход в `try`, закрытие браузера в `finally`;
- в цикле — новый контекст на итерацию и его закрытие, не новый браузер;
- каждый переход с таймаутом и `waitUntil: 'domcontentloaded'` (не `networkidle` — на dev-сервере с HMR может не наступить);
- `process.exit` — только после закрытия браузера;
- движок — Playwright (`npx playwright install`), Chrome не нужен; нет Chromium — WebKit.

## Частые поломки

**Mobile:** sticky/fixed перекрывают контент при открытой клавиатуре; длинные слова → горизонтальный скролл; `vh` на iOS — использовать `dvh`; hover-only элементы не видны на таче и hover залипает; touch target < 44×44px.

**Desktop:** контент растягивается на весь широкий экран (нужен max-width контейнер); несбалансированные колонки; мало whitespace на больших экранах.

4. Скриншоты в `docs/screenshots/adaptive/`.
5. В `docs/spec.md` — какие размеры поддерживаются «первого класса».
