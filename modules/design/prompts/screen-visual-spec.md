# Поэкранный контракт — `docs/screens/<url>.md` (логика + раздел «Визуал»)

Запускай после DESIGN.md, UI-кита и FSD-структуры, до генерации экранов. Обязателен для любого проекта с UI — с Figma и без.

Нужно на входе: `docs/screens-map.md` (карта экранов) и/или индекс «Экраны» в `docs/spec.md`; `docs/DESIGN.md`; UI-кит в `src/shared/ui/`. С Figma — подключённый Figma MCP и ссылка на файл.

Результат: на каждый экран один файл `docs/screens/<url>.md`, в котором и логика (доступ, данные, состояния, действия, связи, валидация), и раздел `## Визуал`. Двух источников правды по одному экрану не бывает.

Режимы: **A** — есть Figma (Code Connect для этого шага не обязателен); **Б** — свой дизайн без Figma (референсы/скриншоты); **В** — без дизайна.

## Алгоритм

1. **Заведи поэкранные файлы.** Прочитай индекс экранов в `docs/spec.md` и `docs/screens-map.md`.
   - Файла экрана нет → создай: экран из карты + общие разделы `spec.md` (данные, доступы, роли) → доступ / данные / состояния (default · loading · empty · error · success) / действия по элементам / связи с другими экранами / валидация форм. Пробел, которого нет ни в карте, ни в спеке → `TODO: <что> + вопрос пользователю`.
   - Файл есть → логику не переписывай, только допиши визуал.
2. **Режим A:** проверь, что у каждого экрана есть Figma node-id (поле «Источник»); нет — спроси.
3. **Покажи список экранов** и жди подтверждения: «Покрываем N экранов: […]. Добавить/убрать?»
4. **Цикл по экранам — режим A:**
   - `get_design_context(nodeId)` + `get_screenshot(nodeId)` → `docs/figma-snapshots/<screen-slug>.png`;
   - допиши в конец файла экрана раздел `## Визуал` по шаблону;
   - деталь не нарисована в Figma → `TODO + вопрос`, не угадывать.
5. **Цикл по экранам — режим Б/В:**
   - есть скриншот-референс (кладутся в `docs/screens-references/`) → опиши, что видишь, сверь с пользователем;
   - структурированное интервью по блокам шаблона: Layout Desktop (max-width, сетка, padding, sticky) → Layout Mobile (что меняется) → компоненты сверху вниз (что, размер, токен, иконка) → визуальные состояния (loading/empty/error) → edge cases (длинный текст, пусто, 100 элементов);
   - записывай в `## Визуал` по ходу разговора;
   - «решай сам» → дефолты (грид → стек на mobile, меню → бургер, hover → tap, tap-таргеты ≥ 44px, токены из DESIGN.md), каждый дефолт **явно помечен** как решение AI.
6. **Большой `get_design_context` (> 50 KB)** → отдай чтение одного экрана sub-агенту, который вернёт выжимку (layout + компоненты + состояния), а не сырой JSON. Без sub-агентов — по одному экрану за раз.
7. **В конце обязательно спроси: «Что упустил?»** — до первой строки JSX.

## Шаблон раздела

```markdown
## Визуал

**Скриншот-референс:** `docs/figma-snapshots/<screen-slug>.png` (A) или `docs/screens-references/<slug>.png` (Б)

### Layout Desktop
- Контейнер: max-width, padding, gap
- Сетка / колонки
- Sticky-элементы
- Hover-состояния ключевых элементов

### Layout Mobile (≤640px)
- Что меняется: сетка → стек, меню → бургер …
- Tap-таргеты ≥ 44px
- Что скрывается / сворачивается

### Компоненты (сверху вниз)
- `<элемент>` → `shared/ui/<Name>` (variant, size, токены)

### Визуальные состояния
- default / loading (скелетон или спиннер) / empty (иконка + текст + CTA) / error (иконка + текст + повтор)

### Edge cases визуально
- Длинный текст: усечение / перенос / tooltip
- Пусто / 100+ элементов: пагинация / виртуализация / скролл

### Открытые вопросы / TODO
- TODO: …
```

## Жёсткие правила

- Точные значения, не «примерно». Запрещённые формулировки: «адаптируй», «возьми за основу», «по образу», «упростим», «как обычно делается» — вместо них «по токену X из DESIGN.md» или «по решению пользователя».
- Деталь не описана → TODO + вопрос, не молчаливый дефолт.
- «Компоненты» заполняются явно с привязкой к компоненту UI-кита; Mobile описан так же подробно, как Desktop.
- Дисциплина точности и интерактивности — правила `figma-design-fidelity` и `prototype-interactivity` (в `rules/`, если есть).

## После выполнения

- В каждом `docs/screens/<url>.md` есть `## Визуал`; в режиме A — PNG на каждый экран в `docs/figma-snapshots/`.
- Все TODO закрыты ответами или явно перечислены; пользователь подтвердил «всё покрыто, можно собирать».
- Покажи превью `## Визуал` 2–3 экранов, `ls docs/figma-snapshots/` (режим A) и список открытых TODO.
