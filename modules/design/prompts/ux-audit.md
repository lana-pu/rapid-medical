# UX-аудит прототипа — битые кнопки, тупики, экраны-призраки, заглушки

Запускай после сборки всех экранов и перед деплоем; повторно — перед каждым новым этапом фич, после подключения реальных данных и перед релизом.

Нужно на входе: экраны из `docs/spec.md` реализованы и запускаются через `npm run dev`.

Результат: отчёт `docs/ux-audit-<YYYY-MM-DD>.md`, все 🔴-проблемы закрыты. Пока в 🔴 есть хотя бы одна строка — к деплою не переходить.

## Шаг 0 — Список страниц

Фреймворк — из `docs/spec.md` (стек). Команды — из корня приложения.

```bash
# Next.js App Router
find src/app -name "page.tsx" -not -path "*/node_modules/*" | sort
# React Router
grep -rE "path=[\"'][^\"']+[\"']" src/ --include='*.tsx' --include='*.ts'
```

Таблица: URL | файл | доступ (все / залогиненные / роль). Не нашлось — спроси пользователя, где лежат страницы.

## Шаг 1 — Быстрый скан

```bash
echo "=== ПУСТЫЕ ОБРАБОТЧИКИ ===";  grep -rnE 'onClick=\{\(\) => \{\}\}|onClick=\{undefined\}' src/ --include='*.tsx' | head -20
echo "=== ЗАГЛУШКИ ===";           grep -rnE 'TODO|FIXME|coming soon|Coming Soon|заглушка|будет позже|в разработке|placeholder text' src/ --include='*.tsx' --include='*.ts' | head -20
echo "=== КНОПКИ БЕЗ ДЕЙСТВИЯ ==="; grep -rn '<Button\b' src/ --include='*.tsx' | grep -vE 'onClick|href|type="submit"|asChild' | head -20
echo "=== ПЕРЕХОДЫ ===";           grep -rnE '<Link|router\.push|router\.replace|href=' src/ --include='*.tsx' | head -30
```

Сохрани вывод для Шага 2.

## Шаг 2 — Каждый экран по 5 пунктам

FSD-проект: контент страницы может лежать в `src/pages/<screen>/`, а не в `src/app/.../page.tsx` — проверяй оба места.

1. **Точки входа** — кто ссылается на экран:
   `grep -rnE "(href|to|push|replace|redirect)\(?=?[\"'\`]/<url>" src/ --include='*.tsx' --include='*.ts'`
   Нет ссылок → 🔴 экран-призрак: добавить навигацию/кнопку/редирект или удалить экран.
2. **Точки выхода** — `grep -nE '<Link|href=|router\.push|router\.replace|redirect\(|navigate\(' <файл экрана>`. Нет ни одной → 🔴 тупик.
3. **Интерактив** — пустые `onClick`, `Button` без `onClick`/`href`/`type="submit"`/`asChild` в файле экрана → 🔴 кнопка ничего не делает.
4. **Заглушки** — TODO / FIXME / «coming soon» / «заглушка» в файле экрана → 🟡.
5. **Состояния** — сверь с `docs/screens/<url>.md`: loading (Skeleton/Spinner), empty (EmptyState с текстом и CTA), error (ErrorState с «Повторить»). Описано в спеке, нет в коде → 🟡.

## Шаг 3 — Отчёт

`docs/ux-audit-<YYYY-MM-DD>.md`:

```markdown

## Сводка
- 🔴 Критических: N
- 🟡 Заглушек / незакрытых состояний: N
- Экранов проверено: N

## 🔴 Критические (блокируют деплой)
| Экран | URL | Проблема | Файл |
|---|---|---|---|
| Настройки | /settings | «Сохранить» — пустой onClick | `src/pages/settings/ui/SettingsPage.tsx:47` |

## 🟡 Требуют доработки
| Экран | URL | Проблема | Файл |
|---|---|---|---|
```

Покажи отчёт. Есть 🔴 → «Нашёл N критических проблем, до их закрытия к деплою не переходим». Нет → «Критических проблем нет».

## Шаг 4 — Закрыть 🔴

| Проблема | Исправление |
|---|---|
| Кнопка без обработчика | добавить обработчик с видимой реакцией или убрать кнопку |
| Экран-призрак | ссылка в навигации или на другом экране |
| Тупик | «Назад» или кнопка с переходом |

После каждого исправления — повтори скан Шага 1. Когда 🔴 = 0: обнови отчёт (удали исправленные строки, обнови дату), запусти `npm run dev` и пройди ключевые пути пользователя руками.
