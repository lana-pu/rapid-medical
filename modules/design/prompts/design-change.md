# Design Change — визуальная правка через DESIGN.md → UI-кит → экран

Запускай, когда нужно изменить внешний вид: цвет, шрифт, отступ, скругление, вариант компонента, или когда обновился макет в Figma.

Нужно на входе: `docs/DESIGN.md` и UI-кит (`src/shared/ui/`, в монорепо — пакет UI-кита).

Направление одно: **DESIGN.md → UI-кит → экран.** Хардкод хексов, пикселей и inline-стилей на странице запрещён.

## Что меняется → что делать

### Цвет, шрифт, отступ, скругление

1. Обнови токен в `docs/DESIGN.md`.
2. Синхронизируй токен в коде (CSS-переменные / тема / конфиг стилей), если он там продублирован.
3. Если нужен новый вариант компонента — добавь его в UI-кит.
4. Примени на экране только через токены и компоненты.
5. Покажи каждый шаг (diff DESIGN.md, UI-кита, экрана).

### Новый вариант компонента (другая кнопка, карточка и т.п.)

1. Нужен новый токен — сначала в `docs/DESIGN.md`.
2. Добавь `variant` в компонент UI-кита (`src/shared/ui/<component>.tsx`), используя только токены.
3. Если есть витрина компонентов (style-guide / Storybook) — добавь туда новый вариант.
4. Используй вариант на экране.

### Обновился макет в Figma

1. Через Figma MCP перечитай переменные (`get_variable_defs`) и, при необходимости, контекст (`get_design_context`) нужного экрана или компонента.
2. Сравни с токенами в `docs/DESIGN.md`, выпиши расхождения.
3. Обнови расхождения в `docs/DESIGN.md`.
4. Проверь, нужны ли правки в UI-ките, затем — на экранах.
5. Покажи список расхождений и что изменено.

## Правила

- Изменение поведения (что происходит при клике, состояния, доступы) — не здесь, а по `spec-change.md` (модуль product): сначала `docs/spec.md`, потом код.
- После правки проверь адаптив затронутых экранов (mobile / tablet / desktop).
