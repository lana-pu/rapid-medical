# Memory Search — поиск по памяти проекта (3 слоя)

Универсальный промт: поиск по памяти с минимальным расходом токенов (progressive disclosure). В Claude Code оборачивается в скилл `/memory-search`; в Codex/Cursor: «прочитай `memory-search.md` и найди в памяти проекта про <тему>».

Запускай, когда спрашивают про историю проекта:
- «Было ли уже X?», «Почему выбрали Y?», «Как решали Z в прошлый раз?»
- «Что делали на прошлой неделе / в этой ветке?»
- «Покажи ADR / finding по теме N», «Какие открытые вопросы остались?»

Нужно на входе: память проекта `docs/memory/` (state.md, INDEX.md).

## Принцип — слоями, не всё подряд

| Слой | Что делает | Когда дальше | Токены |
|---|---|---|---|
| **L1 Search** | Grep по `state.md` + `INDEX.md` | Найден ≥1 кандидат | ~50–100 |
| **L2 Fetch** | Read конкретного файла по ID (ADR-XXX, F-XXX, сессия YYYY-MM-DD) | Ответа нет в L2 | ~500–1500 на файл |
| **L3 Timeline** | Соседние сессии вокруг даты-якоря (±N дней) | Только для широкого контекста | ~2000–5000 |

Не переходи на следующий слой, пока текущего не достаточно.

## Параметры

- **Запрос** — ключевые слова, тема, дата.
- **Проект** — из контекста чата (один чат = один проект; продукты в `projects/<slug>/`). Неясно — спроси.

## Шаги

### 0. Путь к памяти

`docs/memory/` в корне проекта (`projects/<slug>/docs/memory/`). Нет `INDEX.md`, а есть старая схема (`notes.md`, `architecture-decisions.md`) — сообщи и предложи миграцию (`ai-config/prompts/memory-setup.md`).

### 1. Search (L1)

Прочитай `docs/memory/state.md` (≤80 строк) и `docs/memory/INDEX.md` (≤200 строк). Grep ключевых слов запроса по таблицам ADR / Findings / Sessions в INDEX, разделу «Последние решения» и активной работе в state.md. Временное выражение («прошлая неделя», «2026-04-10») — фильтр sessions по дате.

Выход: кандидаты — ID + путь + одна строка релевантности:

```
- ADR-006 (no-gitlab-ci) → docs/memory/decisions/ADR-006-no-gitlab-ci.md
  Релевантно: упоминает CI/CD, отказ от GitLab Actions
- session 2026-04-15 (sidebar-unification) → docs/memory/sessions/2026-04-15-sidebar-unification.md
  Релевантно: дата подходит под «прошлая неделя»
```

Кандидатов нет — ответь: «В памяти проекта <проект> нет записей по запросу. Возможно, тема не фиксировалась». На L2 «на всякий случай» не переходи.

### 2. Fetch (L2)

Read только конкретных файлов из L1 (обычно 1–3). Извлеки нужное:
- ADR — Decision + Alternatives Considered;
- Finding — описание;
- Session — «Что сделано» / «Принятые решения» / «Открытые вопросы».

### 3. Timeline (L3, опционально)

Только если запрос про широкий контекст («что происходило в апреле») или L2 не дал ответа. Дата-якорь → соседние sessions ±3–7 дней.

### 4. Ответ

```
## Найдено

**По запросу «<запрос>»:**

### ADR-006 — Отказ от GitLab CI
- **Дата:** ...
- **Контекст:** ...
- **Решение:** ...
- **Альтернативы и почему отвергли:** ...
- **Подробнее:** docs/memory/decisions/ADR-006-no-gitlab-ci.md

## Связанные записи
- ADR-005 — docs/memory/decisions/ADR-005-...

## Открытые вопросы (если есть)
- ...
```

Можно ответить одной строкой — отвечай одной строкой.

## Антипаттерны

- Читать все ADR / findings / sessions подряд.
- Переходить на L2 без кандидатов из L1.
- Переходить на L3 без нужды в широком контексте.
- Цитировать файлы целиком вместо нужной части.
- Не предложить миграцию при старой структуре памяти.
