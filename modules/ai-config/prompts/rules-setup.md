# Rules Setup — семь правил проекта в `docs/rules/` + индекс в AGENTS.md

Запускай в новом проекте после создания структуры, или в существующем, где правил нет / они неполные. Идемпотентно: существующие правила интегрировать, не перезаписывать.

Нужно на входе: папка проекта с `docs/` и `AGENTS.md` (с разделом «Правила (читать по триггеру)»; нет — создай раздел). Для хуков — `.claude/`.

## Источник правил

Готовые универсальные версии лежат в `rules/` воркспейса (обычно `../../rules/` от папки проекта):

| Файл | О чём |
|---|---|
| `ui-components-first.md` | UI только из компонентов UI-кита, без хардкода классов/хексов/пикселей |
| `design-system-first.md` | DESIGN.md — контракт токенов, lint перед коммитом |
| `spec-first.md` | спека экрана — источник правды, правится в том же коммите |
| `verification.md` | проверки перед «готово» и коммитом |
| `commits.md` | авто-коммит после шага, атомарно, формат, push по автодеплою |
| `session-continuity.md` | память между сессиями: старт, по ходу, закрытие |
| `process-hygiene.md` | фиксированные порты + kill-first, закрытие браузеров автоматизации |

## Задача

1. Скопируй эти семь файлов в `docs/rules/` проекта и адаптируй под проект: реальные пути UI-кита (`src/shared/ui/` или `packages/ui`), имя проекта в формате коммитов, порты dev-серверов, команда lint DESIGN.md. Файл уже есть в проекте — сравни и дополни недостающим, не затирая проектные особенности. Воркспейсных `rules/` нет — создай файлы по описанию в таблице и содержимому ниже по смыслу.

2. В `AGENTS.md` проекта в раздел «Правила (читать по триггеру)» добавь строки (только ссылки, содержимое правил НЕ копировать — AGENTS.md грузится перед каждым промтом и должен быть компактным):

```markdown
| UI / страницы / виджеты / компоненты / стили / запрет хардкода | `docs/rules/ui-components-first.md` |
| DESIGN.md / токены / новые цвета или шрифты | `docs/rules/design-system-first.md` |
| Правка экрана / поведения / перед изменением UI-логики | `docs/rules/spec-first.md` |
| Перед коммитом / завершением задачи (что проверить) | `docs/rules/verification.md` |
| Завершил шаг → коммит (когда и как коммитить/пушить) | `docs/rules/commits.md` |
| Старт сессии / сохранение прогресса между сессиями | `docs/rules/session-continuity.md` |
| Запуск dev-сервера / Playwright-скрипта / повторный прогон | `docs/rules/process-hygiene.md` |
```

Триггер UI делай широким («рисую страницу», «делаю компонент», «правлю стили»).

3. В `AGENTS.md`, раздел «Железные правила — всегда, без исключений», добавь (если такого пункта ещё нет):

```markdown
### N. Запуск процессов — идемпотентно и самоочищающе
Никогда не поднимай второй долгоживущий процесс (dev-сервер, `next dev`, браузер
автоматизации), не убив предыдущий.
- Dev-сервер — фиксированный порт (app `:3000` / лендинг `:3001`) + kill-first; roll-forward
  на соседний порт запрещён.
- Браузер автоматизации — один `launch` с таймаутом, обход в `try`, `close` в `finally`,
  `goto` с `domcontentloaded`+timeout, `process.exit` только после `close`.
- Движок ставит Playwright (`npx playwright install`), Chrome не нужен; нет Chromium → WebKit.
- Повторный прогон при провале — с очисткой осиротевших процессов и лимитом 2–3, дальше стоп.
Детали — `docs/rules/process-hygiene.md`.
```

4. Хуки-страховки (Claude Code), если ещё не стоят: `post-tool-use-edit.sh` (хардкод) и `pre-tool-use-process-hygiene.sh` (порты/браузер) — по `development/prompts/hardcode-guard-hook.md`; SessionStart-хук памяти — по `ai-config/prompts/memory-setup.md`.

5. Закоммить (`docs/rules/commits.md`).

## Результат

Покажи `tree -L 2 docs/rules .claude` и содержимое `AGENTS.md`.
