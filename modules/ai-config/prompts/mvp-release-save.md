# MVP Release Save — финальная фиксация версии в памяти

Запускай, когда MVP (или крупная версия) опубликован и работа над ней завершена: зафиксировать статус, артефакты и следующие шаги.

Нужно на входе: память проекта `docs/memory/`; задеплоенный продукт.

## Шаг 1 — `docs/memory/state.md`

```markdown
# State — <продукт>

## Активная работа
**Статус:** MVP v1.0 готов, опубликован.

## Что сделано
- <ключевые этапы по факту: спека, дизайн-система, прототип, деплой, БД и аккаунты,
  интеграции, тесты, память, упаковка (лендинг, SEO, PWA, юр. страницы)>

## Ключевые артефакты
- Публичный URL: https://<домен>
- Репозиторий: <ссылка>
- Спека: docs/spec.md
- Память: docs/memory/INDEX.md

## Следующие шаги
- <маркетинг / сбор обратной связи / версия 1.1: что добавить>
```

Держать ≤80 строк; подробный бэклог — в `docs/memory/BACKLOG.md`, если он есть.

## Шаг 2 — Session-файл

Выполни `ai-config/prompts/save-session.md` со slug `mvp-release`: `docs/memory/sessions/<YYYY-MM-DD>-mvp-release.md` — что сделано, список реализованных фич (сверить с `docs/memory/feature-registry.md`), ключевые решения со ссылками на ADR, куда двигаться дальше.

## Шаг 3 — README

Проверь корневой `README.md`: актуальный публичный URL, стек, команда запуска и деплоя, ссылки на `docs/spec.md`, `docs/test-cases.md`, `docs/memory/INDEX.md`, `docs/memory/infrastructure.md`. README нет или устарел — `ai-config/prompts/readme-network.md`.

## Шаг 4 — Тег версии

Если есть git: `git tag -a v1.0.0 -m "MVP"` и `git push --tags` (если push не запускает автодеплой; иначе — спросить).

## Результат

Статус версии, артефакты и следующие шаги зафиксированы в памяти и README; версия помечена тегом.
