# AI Setup — permissions и AGENTS.md как разводящий хаб

Запускай в корне проекта (`projects/<slug>/`), когда настраиваешь ассистента под новый проект или на новой машине.

## Окружение

Определи, какой ты AI, и держи пути на весь промт. Наборы инструментов не смешивай.

- **Claude Code:** глобальные настройки — `~/.claude/settings.json`; общие скиллы/хуки воркспейса — `.claude/` в корне воркспейса; правила проекта — `AGENTS.md` в корне проекта + симлинк `CLAUDE.md → AGENTS.md`.
- **Codex:** настройки — `~/.codex/config.json`; правила проекта — `AGENTS.md`; папку `.claude/` не создавай.
- **Cursor:** настройки — Cursor Settings (проектные — `.cursor/settings.json`); правила проекта — `AGENTS.md`.

Память проекта — `docs/memory/` внутри проекта (не в `.claude/`).

## Что сделать

1. Настроить permissions (см. ниже).
2. Создать `AGENTS.md` в корне проекта — компактный хаб по шаблону ниже.
3. Claude Code: создать симлинк `CLAUDE.md → AGENTS.md`.
4. Опционально: проектные permissions поверх глобальных.

## 1. Permissions

Пропиши в конфиге своего инструмента (формат знаешь сам):

**Без подтверждения:**
- читать, искать и редактировать файлы внутри проекта;
- `ls`, `cat`, `head`, `tail`, `grep`, `find`, `mkdir`, `touch`, `cp`, `mv`;
- git на чтение и подготовку: `status`, `log`, `diff`, `branch`, `show`, `add`, `fetch`, `pull`;
- `npm` / `pnpm` / `yarn` / `bun` (install, run), `npx`, `node`;
- dev-сервер, тесты, сборка; `docker ps` и логи; открытие localhost.

**Всегда спрашивать:**
- `git commit`, `git push`, `git reset`, `git checkout`, `git restore`;
- `rm`, `chmod`, публикация пакетов, миграции прод-базы, отправка писем.

**Никогда без явной команды пользователя:**
- `rm -rf /`, `rm -rf ~`, `git push --force` в main, `git reset --hard origin/main`, `sudo rm`.

## 2. AGENTS.md — формат

`AGENTS.md` подгружается перед каждым промтом, поэтому это индекс по триггерам, а не свалка: ≤200 строк, без инструкций «как кодить» и без описания продукта (только указатель на `docs/spec.md`).

```markdown
# AGENTS.md

## Контекст продукта
См. `docs/spec.md → ## Продукт`. Здесь не дублируем — один источник правды.

## Железные правила — всегда, без исключений

### 1. spec.md всегда актуален
Любое изменение поведения продукта (логика, состояния, действия, данные, доступы) →
сначала обновить `docs/spec.md`, потом менять код.
Коммит без обновления spec.md считается незавершённым.

### 2. DESIGN.md → UIKit → Экран
Любое визуальное изменение идёт строго в одном направлении:
`docs/DESIGN.md` → `src/shared/ui/` (в монорепо — пакет UI-кита) → страницы / виджеты / фичи.
Нужен новый токен (цвет, шрифт, отступ) → сначала в DESIGN.md.
Нужен новый вариант компонента → сначала в UI-кит, потом использовать.
Хардкод хексов, пикселей, inline-стилей на странице — запрещён.

## Правила (читать по триггеру)

| Когда | Файл |
|---|---|
| Перед коммитом | `docs/rules/commits.md` |
| Деплой / инфра | `docs/memory/infrastructure.md` |

## Активная работа
См. `docs/memory/state.md`.

## История решений
См. `docs/memory/INDEX.md` (ADR, findings, sessions).
```

В таблицу «Правила» вписывай только существующие файлы; строки добавляй по мере появления правил. Пустые файлы-заглушки не создавай.

## 3. Симлинк (только Claude Code)

```
ln -s AGENTS.md CLAUDE.md
```

Codex и Cursor читают `AGENTS.md` напрямую — симлинк не нужен.

## 4. Проектные permissions (опционально)

Если проекту нужны права сверх глобальных:
- Claude Code — `.claude/settings.local.json`;
- Codex — проектного файла нет, только глобальный `~/.codex/config.json`;
- Cursor — `.cursor/settings.json`.

```json
{
  "permissions": {
    "allow": [
      "Bash(docker compose:*)",
      "Bash(prisma:*)"
    ]
  }
}
```

## После выполнения покажи

1. Итоговый конфиг permissions.
2. `AGENTS.md` целиком.
3. Claude Code: `ls -la | grep -E 'CLAUDE|AGENTS'`.
4. Проектный settings, если создавал.

## Проверка

- Чтение файлов проекта идёт без подтверждения.
- `git push` по-прежнему требует подтверждения.
- В `AGENTS.md` только индекс и железные правила, без инструкций «как кодить».
- Claude Code: `cat CLAUDE.md` и `cat AGENTS.md` выводят одно и то же.
