# Memory System — устройство памяти проекта (файловое ядро + опциональный движок)

Справочник и инструкция: из чего состоит память проекта и как подключить поверх неё семантический движок `agentmemory`. Читай, когда настраиваешь память, решаешь, нужен ли движок, или разбираешься, где что хранится.

## Слой 1 — файловое ядро (обязательный)

Память конкретного продукта живёт в его папке (`projects/<slug>/docs/memory/`), в git, читается глазами и правится руками:

```
docs/memory/
├── state.md              ← текущий шаг, активная работа, последние решения, доступы (≤80 строк)
├── project-context.md    ← продукт, роли, платформа, ограничения («что НЕ делаем»)
├── INDEX.md              ← оглавление (ADR / Findings / Sessions), читается на старте сессии (≤200 строк)
├── decisions/ADR-*.md    ← архитектурные решения, по одному на файл
├── findings/F-*.md       ← неочевидные находки
├── sessions/*.md         ← журнал сессий
├── feature-registry.md   ← что уже реализовано
└── infrastructure.md     ← где что развёрнуто (пути деплоя, .env — без значений)
```

Создание и наполнение — `ai-config/prompts/memory-setup.md`; закрытие сессии — `save-session.md`; поиск — `memory-search.md`; реестр фич — `feature-registry.md`.

## Слой 2 — движок `agentmemory` (опциональный)

Плагин сам записывает ход сессий в локальную SQLite (по умолчанию ничего не уходит в облако), вырезает секреты перед сохранением, изолирует проекты и находит прошлые куски по смыслу. Репозиторий: https://github.com/rohitg00/agentmemory (Apache-2.0).

## Что даёт какой слой

| Преимущество | Файловое ядро | agentmemory |
|---|---|---|
| Решения «почему X, а не Y» — точно и долго | ✅ `decisions/ADR-*.md` | — (авто-захват слишком шумный) |
| Видно глазами, ревью, откат через git | ✅ | — (SQLite непрозрачна) |
| Журнал сессий без ручного действия | частично (`/save-session`) | ✅ авто-захват |
| Поиск по смыслу, а не по словам | частично (`/memory-search` по INDEX) | ✅ семантический retrieval |
| Меньше повторных объяснений контекста | — | ✅ |
| Реестр реализованного перед новой задачей | ✅ `feature-registry.md` | — |

## Как работают вместе

1. Старт сессии: AI читает `state.md` и `INDEX.md` — дёшево и точно.
2. По ходу работы: движок пишет историю сам; важные решения — руками в `decisions/` как ADR.
3. Возврат к старой теме: движок подаёт найденные по смыслу куски прошлых сессий.
4. При расхождении источник правды — файловое ядро (ADR прошёл ревью).

## Оговорки

- Не «вечная память»: поиск по смыслу иногда промахивается — критичные решения держать в `decisions/`.
- Установка: Node 20+, фоновый сервис движка (по умолчанию порт 3113), бинарь `iii-engine` или Docker.
- Молодая версия (0.9.x), API может меняться.

## Установка движка (Claude Code)

Для Codex/Cursor отличается последний шаг — см. README репозитория.

1. `node -v` — Node 20+.
2. Сервис движка в отдельном терминале (работает, пока пользуешься памятью):
   ```bash
   npx @agentmemory/agentmemory
   ```
3. Плагин:
   ```
   /plugin marketplace add rohitg00/agentmemory
   /plugin install agentmemory
   ```
4. Открой просмотрщик памяти (порт 3113) и убедись, что в записях нет ключей и токенов из `.env`.

## Когда подключать

- **Стоит:** проект длится месяцами, сессий много, контекст приходится пересказывать.
- **Не стоит:** короткие задачи и небольшие проекты — файлового ядра хватает. Сначала отладь дисциплину `decisions/`, `findings/`, `/save-session`.
