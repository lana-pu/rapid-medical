# Build Your Prompt — оформить повторяющийся паттерн в промт и скилл

Запускай, когда только что сделал что-то по подробной инструкции и понимаешь, что это повторится (в этом или следующем проекте): «после деплоя всегда прохожу 14 пунктов безопасности», «после нового UI всегда прогоняю адаптив». Результат — промт в библиотеке модулей + (в Claude Code) скилл-обёртка.

Не оформлять: разовую задачу (миграция при первой настройке) и то, что укладывается в 2–3 строки в чат.

## Структура промта — 6 секций

```markdown
# <Название> — <что делает>

## Когда применять
<2–4 ситуации>

## Параметры
<что AI должен знать перед началом>

## Шаги
1. <конкретный шаг с проверкой>
2. ...

## Edge cases
<особые ситуации и как с ними быть>

## Что должно получиться
<конкретный артефакт: файл / отчёт / изменённое состояние проекта>

## Триггеры
<фразы на русском, по которым распознаётся «это про этот промт» — минимум 3>
```

Если у шага есть реальное предусловие — первой строкой «Нужно на входе: …».

## Промт

```
Помоги оформить переиспользуемый промт на основе того, что мы только что делали.

КОНТЕКСТ:
- Только что сделали: <что именно>
- Повторится: <где ещё, в каких задачах/проектах>
- Похожий промт в библиотеке: modules/<module>/prompts/<name>.md (если есть —
  ориентир структуры, адаптируй, не копируй)

ШАГ 1 — Структура. По 6 секциям (когда применять, параметры, шаги с проверками, edge
cases, что должно получиться, триггеры). Спрашивай по ОДНОМУ вопросу за раз. Если
есть полезный материал из похожего промта — покажи 2-3 варианта формулировки на выбор.

ШАГ 2 — Сохрани. Определи модуль (ровно один из ai-config / product / design /
development / seo-geo) и положи в modules/<module>/prompts/<name>.md (имя —
описательное kebab-case, без номеров; предложи 2 варианта). Промт самодостаточный:
без отсылок к конкретному проекту, без путей вида ../../<проект>, только
относительные пути проекта (docs/..., src/...).

ШАГ 3 — Индекс. Добавь строку «триггер → файл» в modules/<module>/AGENTS.md
(правило rules/module-indexation.md). Если есть чекер
.claude/scripts/check-modules-indexed.sh — прогони его.

ШАГ 4 — Скилл-обёртка. ТОЛЬКО Claude Code (Codex/Cursor — пропусти: рецепт
вызывается по пути «прочитай modules/<module>/prompts/<name>.md и выполни»).
Создай .claude/skills/<skill-name>/SKILL.md (воркспейса):

---
name: <skill-name>
description: <когда применять + 3-5 русских триггеров для автоподхвата>
---

# /<skill-name>

Выполни промт `modules/<module>/prompts/<name>.md` (путь от корня воркспейса).

ШАГ 5 — Тест. Я скажу фразу-триггер — скилл должен подхватиться сам. Нет — поправь
description и триггеры.

ШАГ 6 — Память. В docs/memory/state.md текущего проекта — строка «Собран промт
/<skill-name> — modules/<module>/prompts/<name>.md»; в sessions попадёт при
следующем /save-session.
```

## Антипаттерны

- Промт на 2–3 строки — это команда, не промт.
- Скилл без триггеров в `description` — не подхватится автоматически.
- Промт для разовой задачи.
- Промт с привязкой к конкретному продукту (имена, домены, пути) — не переносится.
- Промт, не упомянутый в `AGENTS.md` модуля, — «слепой»: AI его не найдёт.
