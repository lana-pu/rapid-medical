# Save Session — закрытие рабочей сессии

Универсальный промт: обновляет `state.md`, создаёт session-файл, добавляет строку в `INDEX.md`, коммитит память. В Claude Code оборачивается в скилл `/save-session`; в Codex/Cursor: «выполни `save-session.md`, slug `<X>`, описание `<Y>`».

Запускай:
- в конце большого этапа или задачи (больше часа работы, есть что зафиксировать);
- перед перерывом (день+), чтобы следующая сессия знала, где остановились;
- после реализации значимой фичи;
- после `git push`, закрывающего логический шаг.

Не применять для мелких правок (опечатка, цвет кнопки) — хватает коммита.

Нужно на входе: память проекта `docs/memory/` (state.md, INDEX.md, sessions/). Нет — сначала `ai-config/prompts/memory-setup.md`.

## Параметры

Если не указано в запросе — спроси одной строкой:
- **slug** — короткое имя файла (`deploy`, `auth-refactor`, `payments-mvp`);
- **описание** — 1–2 предложения, что делали (если ты участвовал в сессии — собери сам).

Дата — текущая (`date +%Y-%m-%d`).

## Шаги

### 1. Саммари сессии

Если участвовал в работе — собери из контекста; если нет — попроси пользователя описать одним сообщением:
- **Что сделано** — 3–7 главных результатов.
- **Изменённые файлы** — `git diff --stat HEAD~N..HEAD` (N — коммиты сессии) или `git status`.
- **Решения** — архитектурные выборы со ссылкой на ADR или пометкой «требует ADR».
- **Находки** — неочевидное поведение, лимиты, нюансы — кандидаты в `findings/`.
- **Открытые вопросы** — что не решено или отложено.

### 2. Session-файл

Путь: `docs/memory/sessions/<YYYY-MM-DD>-<slug>.md` (занят — `<YYYY-MM-DD>-<slug>-2.md`). 50–150 строк, без пересказа diff.

```markdown
# <YYYY-MM-DD> — <Описание сессии>

**Задача:** <название задачи>

## Что сделано
- ...

## Изменённые файлы
<список из git diff --stat>

## Принятые решения
- <решение>: ADR-XXX или «требует ADR»

## Находки
- <нюанс>: F-XXX или «требует findings»

## Открытые вопросы / следующие шаги
- ...

## Связанное
- ADR: ADR-XXX
- Findings: F-XXX
- Предыдущая сессия: <YYYY-MM-DD>-<slug>.md
```

Только применимые разделы; пустые удалить.

### 3. state.md (`docs/memory/state.md`, ≤80 строк)

- **Текущий шаг** — на следующий.
- **Что сделано** — 1–2 пункта про сессию; при разрастании старое переносить в `feature-registry.md` или удалять (история — в sessions/).
- **Активная работа** — убрать выполненное. Если в проекте есть `docs/memory/BACKLOG.md` — хвосты сессии вносить туда, в state — только журнал.
- **Последние решения** — строка про ADR сессии (держать до 5 свежих).
- **Доступы** — новые сервер/сервис/переменные `.env` (без значений).

### 4. INDEX.md (`docs/memory/INDEX.md`)

В таблицу «Журнал сессий» — строка в начало (реверс-хронология):

```
| YYYY-MM-DD | <Задача> | [<filename>](sessions/<filename>) |
```

ADR / findings, созданные в сессии, — проверить, что их строки тоже есть.

### 5. feature-registry.md

Реализована новая фича — строка в нужный раздел `docs/memory/feature-registry.md` (если файл есть).

### 6. Коммит и push памяти

```bash
git rev-parse --is-inside-work-tree 2>/dev/null && git remote
```

- **Git с remote** — закоммить только файлы памяти/документации этой сессии (не код и не чужие правки) и запушь:
  ```bash
  git add docs/memory/sessions/<файл> docs/memory/state.md docs/memory/INDEX.md   # реальные пути сессии
  git commit -m "memory: <YYYY-MM-DD> <slug> — закрытие сессии"
  git push
  ```
  Push отклонён — `git pull --rebase` и повтори. Если push в ветку запускает автодеплой — перед push спроси разрешение (`docs/rules/commits.md`).
- **Git без remote** — только коммит.
- **Нет git** — сообщи: «git не инициализирован, память сохранена только на диске»; предложи `git init`.

### 7. Отчёт пользователю

Какой файл создан, какие разделы state обновлены, закоммичена/запушена ли память, какие открытые вопросы остались.
