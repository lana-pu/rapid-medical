# Screens Spec from Figma — скелет и детализация экранов по макетам

Запускай, когда у продукта есть Figma с макетами и нужно превратить их в спецификацию экранов.

Нужно на входе: `docs/spec.md` с заполненными разделами «Продукт» и «Платформа» (если нет — сначала `product-concept-interview.md`); Figma-аккаунт с доступом к файлу.

**Делаешь:**
1. Скелет состава продукта: сканируешь Figma, группируешь экраны по разделам, согласовываешь с пользователем → `spec.md → ## Экраны (индекс)`.
2. Файл на каждый согласованный экран: `docs/screens/<url>.md` (доступ, layout, данные, состояния, действия, связи, валидация).
3. Разделы `spec.md`: «Данные (модель)», «Доступы и роли», «Уведомления».

**Не делаешь:** не спрашиваешь «что за продукт / для кого / какая проблема / главный сценарий» — это уже в `spec.md → Продукт`.

Шаги выполняй подряд. После каждого — короткая сводка и сразу следующий; останавливайся только на реальных вопросах к пользователю.

## Подключение Figma MCP

Если инструменты Figma уже доступны (`whoami` возвращает аккаунт) — пропусти раздел.

| Окружение | Способ |
|---|---|
| Claude Code + Figma Professional/Organization/Enterprise, место Dev или Full | Официальный плагин (A) |
| Claude Code на Free/Starter, Codex, Cursor, другие AI | Framelink + PAT (B) |

**A. Официальный плагин (Claude Code):**
1. Пользователь вводит `/plugin install figma@claude-plugins-official`.
2. Перезапуск клиента: VS Code — `Developer: Reload Window`; CLI — выйти и открыть заново; JetBrains — Restart IDE.
3. Открыть Figma Desktop (не браузер), выделить любой frame, вызвать `get_design_context`. При первом вызове откроется `mcp.figma.com` → Authorize.
4. Плагин уже стоял (новая машина): `/plugin` → Disable → Enable → полностью закрыть клиент и открыть заново → пункт 3.
5. Сбои: «Plugin not found» — обновить Claude Code; браузер не открылся — повторить запрос к Figma (OAuth ленивый); «Figma MCP server is not available» — открыть Figma Desktop с активным файлом; «No selection / Forbidden» — у места нет Dev/Full доступа.

**B. Framelink + PAT (любой AI, любой тариф):**
1. Пользователь создаёт токен: https://www.figma.com/settings/personal-access-tokens, scope `file_content:read` (опционально `library_content:read`, `current_user:read`), срок — максимальный доступный.
2. Ты создаёшь/дополняешь `.env.local` строкой `FIGMA_API_KEY=впиши-сюда-свой-Figma-токен` и просишь пользователя вписать токен прямо в файл. В чат и терминал токен не вводится, значение не выводи. Проверь, что `.env*` есть в `.gitignore` (нет `.gitignore` — создай).
3. Пропиши MCP-сервер `npx -y figma-developer-mcp --stdio` с переменной `FIGMA_API_KEY` из `.env.local`: Claude Code — `mcpServers` в `~/.claude/settings.json`; Codex — `~/.codex/config.json`; Cursor — Settings → MCP Servers.
4. Перезапусти AI, проверь любым Figma-инструментом (`whoami` / `get_metadata`).

Framelink не даёт Variables API и dev mode, но `get_metadata` + `get_design_context` работают.

**Ссылка для этой задачи** — на весь файл, без `?node-id=` (Share → Copy link). Точность выше, если экраны — top-level frames с осмысленными именами (`/login`, а не `Frame 23`); если файл организован иначе — работай как есть.

## 1. URL и доступ

Попроси ссылку на файл с макетами. Извлеки `fileKey`, вызови `get_metadata`. Нет доступа → попроси дать view-доступ по ссылке (Share).

Покажи название файла, число страниц и фреймов; спроси, переносить всё или только определённые страницы.

## 2. Скелет состава продукта

### 2.1 Скан

Через `get_design_context` пройди по каждому фрейму (или по списку от пользователя). Для каждого экрана запиши в `docs/screens-map.md`:

```markdown
## Экран: <название из Figma>
- **node-id:** `<id>`
- **Layout:** max-width контейнера, padding, gap между блоками, адаптация — из auto-layout / constraints. Семантически, без хексов. Неочевидно → «уточнить у пользователя»
- **Состояния нарисованы:** только реально нарисованные из default / loading / empty / error / success
- **Ключевые компоненты:** формы, списки, табы, модалы, карточки…
- **Интерактивные элементы:** все кнопки/ссылки/инпуты с подписями
- **Какие данные показываются:** имя, цена, дата…
- **Скриншот:** `get_screenshot` → `docs/screens/<name>.png`
```

Только то, что нарисовано. Не додумывай.

### 2.2 Группировка

Разделы: **Публичная часть** (главная, регистрация, вход, восстановление, публичные страницы) / **Личный кабинет** (основной флоу, профиль, настройки, история) / **Админка** (если есть роль админа) / **Прочие** (онбординг, публичный каталог и т.п.). Под продукт допустимы свои разделы.

### 2.3 Согласование

Про себя назови 1–3 аналога продукта этого типа — чтобы предложить ожидаемый функционал. Покажи один список по разделам (на экран строка: `URL — Название (что показывает)`) и одним сообщением спроси:

> 1. Все ли экраны нужны в первой версии? Что исключаем?
> 2. Каких экранов не хватает? (восстановление пароля, профиль, настройки уведомлений, 404/403, онбординг, экраны под «Основной функционал» из spec.md)
> 3. У аналогов ({1–3}) на ключевых экранах обычно есть {2–4 конкретных предложения: фильтры/сортировка/поиск, пагинация, массовые действия, избранное, экспорт, empty/loading}. Что добавляем? (да / нет / позже)
> 4. Группировка корректна?

По ответу в `screens-map.md`:
- исключённые → `*[не делаем в первой версии]*` (в детализацию не идут);
- недостающие → `*[экран нужен, но в Figma не нарисован — описываем словами]*`;
- принятые усиления → новый экран в индекс, фича на экране — в его описание; отклонённые → `*[не делаем в первой версии]*`;
- группировку правь под пользователя.

### 2.4 Индекс в spec.md

```markdown
## Экраны (индекс)

### Публичная часть
- [`/login` — Вход](screens/login.md)

### Личный кабинет
- [`/dashboard` — Главный экран](screens/dashboard.md)

### Админка
- ...
```

## 3. Пробелы логики

Для каждого экрана запиши в `docs/logic-gaps.md` **только то, на что ответа в Figma нет**:

1. Кнопки/ссылки — куда ведут, что делают.
2. Формы — валидация, что после submit (toast / переход / inline), что при ошибке.
3. Списки — empty, ошибка загрузки, loading (skeleton/spinner).
4. Откуда данные: БД / API / сессия / URL-параметр.
5. Куда уходят данные при действии: POST в API / локальный state.
6. Кто видит экран.
7. Что при попадении без прав: редирект / 403 / сообщение.
8. Откуда сюда приходят, куда уходят.

```markdown
## Экран: <название>

### Действия (нет ответа в Figma)
- [ ] Клик на «Сохранить» → ?

### Состояния (не нарисованы)
- [ ] Что показываем, когда список пуст?

### Данные
- [ ] Куда уходит форма после submit?

### Доступы
- [ ] Что если нет прав?
```

Покажи `logic-gaps.md` и сразу переходи к шагу 4.

## 4. Закрыть пробелы — по одному вопросу

Сводка `logic-gaps.md` одним сообщением (обзор, не вопрос), затем каждый пробел — отдельным сообщением, жди ответа. Неполный ответ → разумный default. «Не знаю» → 2–3 типовых варианта на выбор.

После ответа:
1. Ответ → сразу в `docs/screens/<url>.md`.
2. Не нарисован визуал (например, error state) → предложи: (1) нарисовать в Figma и прислать ссылку; (2) описать словами; (3) стандартный паттерн (например, крупная ошибка + «Повторить») на подтверждение.
3. Отметь `[x]` в `logic-gaps.md`.

## 5. Модель данных

Выведи сущности из экранов и ответов («список заказов» → Order) в `spec.md`:

```markdown
## Данные (модель)

### User
- id: uuid
- email: string (уникальный)
- name: string
- role: 'user' | 'admin'
- createdAt: timestamp

### Order
- id: uuid
- userId: → User
- status: 'new' | 'in_progress' | 'ready' | 'cancelled'
- total: number
- createdAt: timestamp
```

## 6. Сборка spec.md и файлов экранов

`spec.md` — обзор: Продукт, Платформа, Данные (модель), Экраны (индекс со ссылками), Доступы и роли (из ответов «кто видит»), Уведомления (если есть email / Telegram / in-app). Детали экрана — только в его файле.

Файл экрана `docs/screens/<url>.md`, пример:

```markdown
# /login — Вход

**Доступ:** только неавторизованные; авторизованных редирект на /
**Figma node-id:** <id>
**Layout:** max-width 480px, центрирован; padding 32/24; gap 16 между полями, 24 перед кнопкой; ≤640px — на всю ширину, padding 16
**Данные:** email + password, POST /api/auth/login
**Состояния:**
- default: форма
- loading: кнопка со спиннером, форма заблокирована
- error: «Неверный email или пароль» под формой
**Действия:**
- Submit → POST /api/auth/login → success: редирект на /; error: сообщение
- Клик «Забыли пароль?» → /forgot-password
- Клик «Регистрация» → /signup
**Связи:** сюда — лендинг, /signup; отсюда — /, /forgot-password, /signup
**Валидация:** email — формат; password — не пусто
```

## 7. Результат

1. `tree docs/screens/` + подтверждение: на каждый экран из `screens-map.md` (кроме исключённых) есть `docs/screens/<url>.md` — число совпадает. Не хватает → создай сейчас из карты и `spec.md`.
2. `spec.md` целиком.
3. `screens-map.md` и `logic-gaps.md`.

## Правила

- **Не додумывай.** Чего нет в Figma — это вопрос, а не предположение.
- **По одному вопросу**, никогда списком.
- **Пиши по ходу:** файл экрана и `spec.md` обновляй сразу после каждого закрытого пробела.
- **Скриншоты сохраняй** в `docs/screens/` — нужны для сверки визуала при сборке UI.
