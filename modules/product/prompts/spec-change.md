# Spec Change — правка поведения, экранов, ролей и модели данных

Запускай, когда меняется поведение продукта: что делает элемент, состояния экрана, кто что видит, новый экран / роль / бизнес-правило, новое поле или сущность.

Нужно на входе: `docs/spec.md` (и `docs/screens/<url>.md`, если экраны уже расписаны).

Порядок всегда один: **сначала спека, потом код.** Код без обновлённой спеки — правка не завершена.

## Что меняется → что делать

### Поведение (что делает кнопка, состояния экрана, кто что видит)

1. Найди нужный файл: логика экрана — `docs/screens/<url>.md`; сквозное (доступы, уведомления) — `docs/spec.md`.
2. Опиши изменение конкретно: элемент → результат, состояние → что показывается, роль → что видит.
3. Если код уже есть — внеси изменение в код.
4. Покажи diff спеки и кода.

### Новый экран, роль или бизнес-правило

1. **Экран:** создай `docs/screens/<url>.md` и добавь ссылку в `spec.md → ## Экраны (индекс)`. Опиши полностью: доступ, layout, данные, состояния (default / loading / empty / error / success), каждое действие и куда ведёт, связи (откуда сюда / куда отсюда — без тупиков), валидацию полей.
2. **Роль:** обнови `spec.md → ## Доступы и роли` и раздел «Доступ» в файлах затронутых экранов.
3. **Бизнес-правило:** запиши в раздел, к которому оно относится (экран или `spec.md`); если правило сквозное и есть `docs/screens/_global.md` — туда.
4. Неясные места — спроси по одному вопросу, «не знаю» → предложи 2–3 варианта.
5. Покажи, что добавилось.

### Модель данных (новое поле, сущность, связь)

1. Обнови `spec.md → ## Данные (модель)`: поля, типы, связи с другими сущностями.
2. Если UI работает на моках — обнови мок-данные сущности (например, `src/entities/<entity>/api/mock-*.ts`).
3. Если уже есть БД — дальше по `backend-change.md` (модуль development): схема → миграция → API.
4. Покажи diff.

## Правила

- Один источник правды — `spec.md` + файлы экранов. Если есть `docs/PRD.md` и изменилась продуктовая часть (что / для кого / сценарий / out of scope) — перегенерируй его из `spec.md`.
- Визуальные изменения (цвет, шрифт, отступы, варианты компонентов) — не здесь, а по `design-change.md` (модуль design).
