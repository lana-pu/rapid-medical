## Как устроено
- **Tailwind 4** (`@import "tailwindcss"`, плагин `@tailwindcss/turbopack`), конфиг-файла нет —
  токены объявлены в `src/app/globals.css` через `:root` + `@theme inline` → утилиты `bg-accent`,
  `text-muted`, `border-border`, `bg-surface` и т.д.
- **Примитивы** — `src/components/site/primitives.tsx`; составные блоки — `src/components/site/blocks/`,
  медиа — `src/components/site/Media.tsx`. Страницы собираются только из них (плюс Tailwind-утилиты
  раскладки).
- Тёмной темы нет. Админка стилизована отдельно, напрямую палитрой Tailwind `neutral-*` (токены не использует).

## Коллекция блоков

**Статус: рабочий набор от 2026-11-08, не финальный.** Владелица: при редизайне блоки в основном останутся, но могут
измениться визуально, точного списка пока нет. Поэтому механизм должен позволять добавить, убрать или поменять блок
правкой в одном месте, без переделки страниц. Основание — инвентарь всех секций сайта
(`memory/findings/block-inventory.md`) и ADR-006: правка на странице, блоки двигаются и добавляются из пресетов.
Наглядный каталог со скриншотами — ссылка в инвентаре.

### Общие правила
- **Страница — упорядоченный список блоков.** У блока есть тип, вариант и поля. Меню и футер — не блоки, они общие для сайта.
- **Редактор** правит поля, добавляет блок из пресетов, двигает, дублирует и удаляет. Вариант выбирает из тех, что
  разрешил дизайнер; цвета, отступы и шрифты ему недоступны.
- **Дизайнер** задаёт оформление вариантов, добавляет варианты и новые блоки, закрепляет блоки. Порядок изменений прежний:
  DESIGN.md → компонент → страницы.
- **Повторяющиеся элементы** (ряды таблицы, колонки, цифры, вкладки) редактор добавляет, удаляет и переставляет внутри блока.
- **Пустое поле не выводится.** Обязательные поля помечены «обяз.»; блок с пустым обязательным полем не публикуется.
- **Медиа** — картинка или видео из медиатеки. У картинки обязательное описание, кроме декоративных.
- **Регионы:** как блок различается по регионам, решится вместе с моделью регионов (BACKLOG).

### В коде (2026-11-08)

Реестр `src/blocks/`: один файл на блок — название, назначение, варианты, поля, пример, компонент; список — `registry.ts`.
Витрина всех блоков и вариантов на примерных данных — `/style-guide` (noindex). На блоках собран весь сайт, кроме двух шаблонов записей
(человек, вакансия) и страницы 404; меню и футер общие.

**Простые блоки идут одним потоком.** Заголовок страницы (Hero · `page`), Text (`default`, `large`), Rich text, Media и Form
не имеют своей полосы: если стоят подряд, они попадают в одну белую секцию, без двойных отступов. Остальные блоки — каждый
своя полоса. В реестре это поле `flow` у блока.

## Решения по страницам (вайрфреймы, `docs/flows/site-pages.md`)

Записываются после закрытия страницы. В коде пока нет — порядок прежний: спека экрана → примитивы/блоки → страница.

### Композиция «общая линия» (Contact Us, 2026-11-14)
Для страниц, где главное — одно действие (форма) и короткий контекст рядом.
- H1 → тонкая линия на всю ширину контейнера → под ней две колонки **стартуют на одной высоте**: слева 4/12 (одна строка
  текста + таблица контактов), справа 7/12 (форма), между ними 1/12 воздуха.
- Ничего не висит отдельно: у каждой колонки верхний край — линия, ширина — по сетке.
- Телефон: одна колонка — H1, линия, строка, форма, линия, таблица контактов.
- Отклонено: «одна карточка на серой полосе» (контакты уходят на второй план); тихая колонка без общей линии (разваливается).

### Текстовая страница (юридические, исследования; 2026-11-14)
Шаблон `/{slug}` и `/{region}/{slug}` (`screens/pages.md`) — композиция «общая линия».
- Слева (4/12): таблица «ключ — значение» (Last revised / Region / Published), «On this page» — оглавление, собирается
  из заголовков разделов и прилипает при прокрутке; список документов раздела (Legal: 4 страницы из футера, текущая
  выделена). Справа (7/12): текст.
- Условие оглавления: разделы — одним уровнем заголовка (H2). Тексты с Duda (в Terms разделы — h3, h4 и h6 вперемешку) выровнять при переносе.
- Телефон: заголовок, линия, «ключ — значение», оглавление — выпадающим списком «On this page», текст.
- Страницы исследований и новостей — свой шаблон, см. «Страница из документа».

### Страница из документа (исследования, новости; 2026-11-14)
Шаблон для материалов, созданных из документа (статья, постер, пресс-релиз). Порядок сверху вниз:
1. **Заголовок:** надпись «тип · продукт · регион», название (у исследования — акроним и расшифровка), вывод одной
   фразой — дословно из документа.
2. **Основная графика** — блоки из набора инфографики (ниже). У исследования первым — паспорт; у новости паспорта нет,
   ключевые цифры — только если они есть в тексте.
3. **Полный текст** — композиция «общая линия»: слева «ключ — значение» (источник, дата) и ссылки «Download PDF» /
   «Open the original ↗», справа текст. Режим выбирается при создании: скопировать на страницу · встроить PDF (просмотр
   по страницам, скачать) · только ссылка. Если есть и текст, и PDF — переключатель «Read here / Original PDF».
4. **Следующий шаг:** «Discuss … with our team» (Contact Us, тема demo), страница терапии, другие материалы продукта.
5. **Регуляторная строка** (Indications / IFU) — внизу, как у терапий.
Телефон: тот же порядок одной колонкой; графики из чисел перестраиваются под ширину.

### Набор инфографики (2026-11-14)
Фиксированный набор блоков; каждый строится из чисел (не картинкой), в стиле сайта, одинаково на всех страницах.
Свободных графиков нет — блок проверяется MLR один раз как шаблон, дальше меняются только цифры.

| Блок | Данные | Обязательно |
|---|---|---|
| Паспорт исследования | ключ — значение: дизайн, регуляторика, пациенты, центры, сроки, кто оценивал, номер NCT | источник (документ или ClinicalTrials.gov) |
| Ключевые цифры | 2–4 пары «цифра — подпись» | у каждой — цитата из документа |
| Сравнение групп | полосы: группа, значение, n | n, p-value, определение конечной точки |
| Распределение по времени | составные полосы по точкам времени + переключатель | n на каждой точке, легенда шкалы |
| Матрица точек | всего, группы (N из M) | что значит одна точка |
| Таблица | строки и столбцы как в документе | заголовки столбцов с n |
| Карта центров | список центров / стран | — |

Правила: цифры и формулировки — только из одобренного документа; у каждого значения — цитата-источник, по которой оно
сверяется с PDF; блок с несовпадением не публикуется.

### Строка материала (новый примитив, 2026-11-14)
Строка ленты: дата в своей колонке (120 px) · заголовок (жирный) · под ним мелко «вид · источник ↗». Стрелка ↗ и имя
источника — только у внешней ссылки (уйдёт с сайта); без стрелки — своя страница. Между строками — тонкая линия.
Тот же вид — для архива событий («дата · название · город · конгресс») и «материалов продукта» внизу страниц.

### News & Events (2026-11-14)
Композиция «общая линия»: H1, линия; дальше секции через линию: название слева (4/12), содержимое справа (7/12).
1. **Главное** — вместо карусели: одна карточка крупно (7/12, картинка, «вид · дата», заголовок) и 3 строки с
   миниатюрами рядом (4/12). Это хайлайты (ADR-009): самые свежие отмеченные.
2. **Upcoming events** — ближайшее карточкой (дата, время, город, площадка, Register), остальные строками. Нет
   предстоящих — строка «No upcoming events right now.» и ссылка на архив; блок не пропадает.
3. **All news** — чипы-фильтр по виду (All · News · Studies · Company updates), строки материалов, «Show more».
   Начинается со следующих после главного — без повторов.
4. **Past events** (`#past-events`) — строки по годам.
Телефон: одной колонкой, название секции над содержимым; чипы прокручиваются вбок.

**Страница новости** — вариант «Страницы из документа»: «← News & Events», надпись «вид · продукт», H1, линия; слева
«ключ — значение» (дата, вид, продукт-ссылка, «Originally published on … ↗», поделиться: LinkedIn, X, Copy link),
справа ключевые цифры (если есть в тексте), полный текст с «город, дата —» в начале. Внизу на сером — «More about
{продукт}»: строки материалов того же продукта.

**Прошедшее событие:** «← Past events» (на `#past-events`), надпись «Event · конгресс», H1, подзаголовок, линия; слева
«ключ — значение» (дата, город, конгресс, метка «This event has taken place»), справа описание или итоги и «Presented at
this event» — материалы, привязанные к событию (блока нет, если ничего не привязано). Внизу — ближайшие события или
строка «No upcoming events».

### Выбор региона (2026-11-14)
Один компонент выбора — на странице `/choose-your-location` и в панели из переключателя в шапке.
- **Регион = карточка:** название, «N countries» (у последнего — «all others»), страны строкой, кнопка «Go to {регион}».
  Страны — из той же таблицы, по которой регион определяется по IP (`regionForCountry`): страница всегда показывает,
  как сайт работает на самом деле.
- **Поиск «Find your country»:** ввод подсвечивает регион страны (кнопка становится основной, метка «{страна} is here»).
- **Страница:** «общая линия» — H1, строка «…differ by region. Pick the region you practice in.», линия, поиск, три
  карточки в ряд. Телефон — поиск сверху, карточки столбиком.
- **Панель из шапки** (справа, поверх страницы): «Current region» + откуда он (по IP / выбран), поиск, регионы со
  странами списком; выбор возвращает на ту же страницу в новом регионе.
- Названия регионов — одинаковые везде (кнопки, подписи, форма Contact Us); какие — после ответа Emily (BACKLOG №9).

### 404 — отложено до графического дизайна (2026-11-14)
Решение владелицы: сделать запоминающейся на этапе графического дизайна. Состояние «терапии нет в этом регионе» —
страховка (внутренних ссылок туда быть не должно), оформляется вместе с 404.

### Таблица «ключ — значение» (новый примитив)
Строки с подписью слева (мелкий текст) и значением справа, между строками тонкая линия `--border`; последняя строка —
ссылка. Для контактов, сроков, коротких фактов. Строки одной высоты.

### Формы (все формы сайта: Contact, Webinars, Careers, событие)
- **Поле:** подпись над полем, `*` у обязательных. Ошибка — рамка и текст под полем цветом `--danger`, текст говорит,
  что исправить; `aria-invalid`. Введённое после ошибки остаётся. Сводки ошибок сверху нет.
- **Выбор:** до 4 вариантов — чипы (выбранный залит акцентом); больше — 3 частых чипами + «Other topic ▾» со списком
  остальных. Поле, от которого зависит, куда уйдёт заявка, — первым.
- **Поля парами** на десктопе (имя/фамилия, e-mail/телефон, организация/страна), на телефоне — по одному.
- **Кнопка отправки на всю ширину формы**, под ней мелко — строка согласия со ссылкой на Privacy Statement. Подписка —
  отдельный флажок над кнопкой, выключен.
- **Успех:** заголовок страницы меняется на подтверждение, строка — кому ушло и куда ждать ответ; на месте формы — серая
  плашка со сводкой заявки; ссылка «Send another request». Текст — по типу формы. Письмо-подтверждение не обещаем, пока
  его нет в коде.
