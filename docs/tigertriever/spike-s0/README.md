# Спайк S0 — офлайн-пакет инструмента

Проверка из MVP v0.7 (срез S0): открывается ли учебный пакет на компьютере клиента без интернета, играют ли видео,
работает ли пара сравнения. Контракт пакета — `docs/spec.md → Инструмент Tigertriever → Офлайн-пакет`.

**Что внутри** (`package/`, собирается в `tigertriever-offline-test-s0.zip` скриптом `sh build-zip.sh`):
- `index.html` — один этап (Deployment) с двумя ручками рядом и страницей самопроверки; кнопка «Copy results» для
  отчёта клиента письмом.
- `content.js` — данные пакета. Именно скрипт, а не JSON: браузеры не дают странице читать файлы с диска через fetch
  (проверено в Chrome 153, CORS для `file://`). `manifest.json` — те же данные для людей и инструментов, страница его не читает.
- `media/` — два ролика H.264 + AAC с публичного сайта Rapid Medical как заглушки. Учебного содержания нет.
- `READ-ME-FIRST.txt` — инструкция для клиента в три шага, по-английски.

## Проверено (2026-11-08)

| Где | Как | Результат |
|---|---|---|
| macOS, Chrome for Testing 153, headless | ZIP распакован, `index.html` открыт с диска, сеть выключена | Оба видео играют, запросов наружу нет, самопроверка зелёная |

**Не проверено:** Windows, Edge, Firefox, Safari, управляемые больничные компьютеры, блокировка ZIP почтой или
антивирусом. Это и есть задача S0 на машинах клиента (BACKLOG → Сейчас, п. 5).

## Что спросить у клиента после теста
- Результат «Copy results» с каждого типа компьютера.
- Как файл попал на компьютер (почта, USB, скачивание) и не было ли предупреждений безопасности.
- Каким браузером открылась страница по двойному клику.

Если `file://` на их машинах запрещён, следующий вариант — упакованное приложение или локальный веб-сервер в пакете;
решать в ADR по стеку инструмента.
