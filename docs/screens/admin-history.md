# Экран: История записи (`/admin/{resource}/{id}/history`)

Основа: описано по коду 2026-11-13 (как работает сейчас). Откуда открывается (блок History в форме, «Compare ↗») и как
пишутся ревизии — [admin-record-edit](admin-record-edit.md).
Код: `src/app/admin/(dashboard)/[resource]/[id]/history/page.tsx`, `src/admin/workflow.ts` (`listRevisions`,
`getRevision`, `restoreRevision`), `src/admin/actions.ts` (`restoreAction`), таблица `revisions`.

## Что показано
- Заголовок «History · {название записи}», подпись «{N} revisions» (до 200 последних), кнопка **← Back to record**.
- Сравнение: **From** и **To** — «Live (current)», «Pending draft» (если у записи есть неопубликованные правки) и каждая
  ревизия «#{id} {вид} · {кто} · {когда}»; **Compare**. По умолчанию — предпоследняя ревизия → последняя
  (нет ревизий — Live → Live).
- Таблица различий: только поля, которые отличаются; слева название поля, справа текст с пословной разницей
  (добавленное — зелёным, удалённое — красным и зачёркнуто). HTML показывается как текст без тегов, списки и
  объекты — как JSON. Нет различий: «No differences.»
- «All revisions»: # · Kind (`created`, `draft`, `published`, `restored`) · By · When · Note, у каждой —
  **vs live** (сравнить с текущей live-версией) и **restore**.
- Автосохранения одного человека подряд в течение 10 минут — одна ревизия; у записей из импорта первая ревизия —
  «Import», «Baseline before first edit».

## Restore
Без подтверждения. Содержимое ревизии становится:
- у опубликованной записи — черновиком правок (на сайте после Publish);
- у неопубликованной — самой записью.
Опубликована запись или нет, restore не меняет. Добавляется ревизия `restored` «Restored revision #{id}», журнал
`restore`; переход в форму записи с уведомлением о восстановлении.

## Состояния
Ресурс не из списка или записи нет → 404.

## Права
Любая роль после двухшагового входа (просмотр и restore).

В сравнении — только ревизии этой записи: номер чужой ревизии в `?a=` / `?b=` показывается как пустая версия (аудит 2026-11-13).
