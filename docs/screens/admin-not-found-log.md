# Экран: Broken links (`/admin/not-found-log`)

Основа: описано по коду 2026-11-13 (как работает сейчас). Пункт меню **Broken links** в группе Admin
([admin-sections](admin-sections.md)). Сами редиректы — список `/admin/redirects` ([admin-list](admin-list.md)).
Код: `src/app/admin/(dashboard)/not-found-log/page.tsx`, `src/lib/redirects.ts` (`redirectIfLegacy`, `logNotFound`),
таблицы `not_found_log`, `redirects`.

## Откуда берутся строки
- Публичная страница не нашлась → сначала ищется редирект с этого адреса (есть — переход, постоянный или временный по
  флажку редиректа, счётчик Hits редиректа +1); нет — адрес записывается в журнал 404.
- Один адрес — одна строка: число заходов, когда последний раз, откуда пришли (последний referer).
- Не записываются: адреса с символами кроме `a-z 0-9 - _ / . %` или длиннее 200, файлы `.php .asp .env .git .xml .json
  .map .txt`, адреса с `wp-`, `wordpress`, `admin`, `.well-known` (шум сканеров).

## Что показано
- Заголовок «Broken links (404s)», подпись «Paths visitors requested that don't exist. Add a redirect or dismiss.»
- Таблица: Path · Hits · Last seen · Referer · Redirect to. Только нерешённые, по числу заходов, до 200 строк.
- Пусто: «No broken links recorded.»

## Действия
- **Redirect to**: поле «/new/path» и **Add** — создаёт постоянный редирект (флажок «301» в списке) с этого адреса (если редирект с него
  уже был — меняет адрес назначения), строка помечается решённой и пропадает из списка. Назначение — путь на этом сайте
  (`/…`, не `//…` и не `\…`) или `https://…`; иначе ничего не создаётся и экран открывается заново. Журнал: `save`, «{откуда} → {куда}».
- **dismiss** — удаляет строку. Если адрес снова откроют, он появится заново с Hits = 1.
- Решённый адрес, по которому снова пришли без редиректа, возвращается в список.

## Права
Любая роль после двухшагового входа.
