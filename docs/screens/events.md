# Экран: Событие `/events/{slug}` и события на `/news-events`

**Статус:** решение владелицы 2026-11-10 (аудит Emily + вопрос №18 бэклога), **сделано 2026-11-11**.
Код: `src/app/(site)/events/[slug]/page.tsx`, правила дат — `src/lib/events.ts`, блок `src/blocks/events.tsx`,
админка — ресурс `events` (`src/admin/resources.ts`), перенос с Duda — `content/seed/events.ts`.
Данные: таблица `events` (`spec.md → Данные`).

## Зачем

Маркетинг сам публикует мероприятия: конгрессы, воркшопы, ужины с экспертами. Завести событие должно быть так же
просто, как новость. После даты событие **само** уходит в архив, без кнопок и напоминаний.

## Правило «предстоящее / прошедшее»

- Событие **предстоящее**, пока не наступил следующий день после `endsOn` (или `startsOn`, если `endsOn` пуст).
- Потом оно **прошедшее**: исчезает из «Upcoming events», появляется в «Past events», регистрация закрывается.
- Регистрация закрывается раньше, если задан `registrationClosesOn`.
- Считается при каждом показе страницы (сайт рендерится на запрос: layout читает cookie региона), поэтому ни cron,
  ни ручного шага нет. Дни сравниваются как даты (UTC).
- Поля: дата первого дня `startsOn` + время текстом `startTime` («12:45 PM»), последний день `endsOn` — вместо
  `startsAt` из первого варианта спеки.

## Страница события

| Состояние | Что видит посетитель |
|---|---|
| Предстоящее, `registration = form` | Заголовок, дата/время, город и площадка, конгресс, описание, картинка, форма регистрации |
| Предстоящее, `registration = link` | То же, кнопка «Register» на внешний сайт |
| Предстоящее, `registration = none` | То же без регистрации |
| Регистрация закрыта, событие ещё не прошло | Вместо формы — «Registration is closed» |
| Прошедшее, итоги не заполнены | Плашка «This event has taken place», описание, без регистрации |
| Прошедшее, итоги заполнены | Плашка, итоги (`recapHtml`) и галерея (`recapPhotos`) вместо описания |

Форма регистрации — поля как на Duda: First name*, Last name*, Hospital, Email*, Dietary requirements, Message, opt-in;
выбора темы нет (тема = название события). «Dietary requirements» уходит в `meta.dietary`.
Заявка пишется в `contact_submissions` (`form = event`, название события в `meta`), письмо на `MAIL_TO`, событие GA4
«заявка» с `form = event`.

Разметка для Google — `Event` (JSON-LD) из полей события.

## На `/news-events`

| Порядок | Блок | Условие |
|---|---|---|
| 1 | Hero | всегда |
| 2 | **Upcoming events** — карточки по дате, ближайшее первым | есть предстоящие |
| 3 | Новости (карусель, лента) | как сейчас |
| 4 | **Past events** — по годам, новые сверху | есть прошедшие |

## Админка

Раздел «Events»: список по дате с колонкой «When» (Upcoming / Past). Обязательны название, slug и дата первого дня,
остальное — по желанию. Итоги и фото (URL из медиатеки, по одному в строке) можно добавить в любой момент после события.

## Перенос с Duda

Перенесены 5 событий с датой на странице Duda (Busan 12.10.2026 из `/RSVP`, ESMINT Marseille 3.09.2026, Kaneka
15–16.09.2026, LINNC Paris 1.06.2026, DGNR 22.10.2025); старые адреса → 301 на `/events/{slug}`. У четырёх даты на
Duda нет (Murcia 2025, First Asia TIGERTRIEVER Workshop, International Partners Summit, Users Meeting) — даты не
выдумываем: их адреса → 301 на `/news-events`; в архив добавит маркетинг, когда даст даты. Двухсегментные старые
адреса вне регионов (`/event-details/…`) теперь тоже проверяют таблицу `redirects`.

## Проход по юзабилити 2026-11-13
- «← News & Events» с прошедшего события ведёт к «Past events» (`#past-events`), с предстоящего — к «Upcoming events».
