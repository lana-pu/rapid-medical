# Направление: лиды из LinkedIn через исследования

Статус: **в работе параллельно с переносом сайта** (решение владелицы 2026-11-14). Кода нет, спека не менялась.

## Зачем
Клиент хочет больше лидов. Лидов сейчас нет: CRM нет, на выставках не собирают, через форму на Duda — ни одной заявки
(`memory/findings/client-email-2026-11-10.md`). Главный канал, по словам клиента, — LinkedIn: туда изредка пишут, Nir
(IT) ищет там клиентов. Наша идея — генерировать посты из клинических исследований: это самый весомый материал
компании, и его много (102 публикации в Evidence, страницы SUCCESS, DISTALS и др.).

**Гипотеза, не факт:** LinkedIn — канал, через который врачи-нейроинтервенционалисты дойдут до заявки. Проверяется
замером (ниже), а не верой клиента.

## Цепочка
Пост сам по себе лидов не даёт. Работает только вся цепочка, и рвётся она в самом слабом звене:

| # | Звено | Что есть сейчас | Чего не хватает |
|---|---|---|---|
| 1 | **Пост** в LinkedIn | пишут вручную, если пишут | черновик поста из утверждённых выводов исследования |
| 2 | **Клик → страница** исследования | страницы исследований — обёртки над одним файлом: постер-скриншот (SUCCESS), PDF, видео; текст есть только у DISTALS. Превью ссылки в LinkedIn — общая `/og-image.jpg` (у текстовых страниц своей картинки нет) | страница, на которую не стыдно вести: суть исследования текстом, файл, своё превью |
| 3 | **Следующий шаг** на странице | действия нет | «Request a demo» / «Talk to a rep» (тема уже есть в форме Contact), другие исследования продукта, страница терапии |
| 4 | **Регион** | регион в пути URL (ADR-002), утверждения разные по регионам; пост в LinkedIn — один на всех | правило: ссылка на регион продукта или без региона с подсказкой выбора |
| 5 | **Заявка доходит** | на Duda — ни одной; гипотеза: форма не доставляет письма. Новый сайт шлёт заявки, но SMTP не подключён | рабочая форма на проде. До этого гнать трафик бессмысленно |
| 6 | **Видно, что из LinkedIn** | **есть в коде:** UTM, `landing_page`, `referrer` пишутся в саму заявку (`spec.md → Аналитика`, вариант Г); событие `generate_lead` в GA4 | UTM в каждой ссылке из поста; `generate_lead` как key event в GA4 (маркетинг) |

Вывод: звенья 2–6 нужны, даже если посты пишутся руками. Генерация поста — самая дешёвая часть.

## Идея устройства (предложение)
**Одна запись «исследование» — несколько выходов.**

- Запись: заголовок, авторы, площадка (журнал / конгресс), дата, продукт, регионы, файл (PDF / постер / видео),
  **3–5 ключевых выводов, утверждённых MLR**, картинка для превью.
- Выходы: страница исследования · карточка в Evidence · черновик поста LinkedIn (с UTM-ссылкой) · при желании новость.
- ИИ — в двух местах, оба раза **черновик, решает человек** (propose → confirm):
  1. черновик записи из файла: из постера или PDF вытащить авторов, метод, цифры, выводы. Снимает затык «перевод
     скриншотов в текст за клиентом» — клиенту и MLR остаётся проверить, а не набрать;
  2. черновик поста — только из уже утверждённых выводов, без новых утверждений.
- **Без оплаты ИИ с нашей стороны (решение владелицы 2026-11-14).** Сайт сам ИИ не вызывает: в админке «Copy
  instructions for AI» → маркетинг прогоняет файл в своём ChatGPT / Claude / Copilot → вставляет ответ → черновик.
  Полный текст сайт достаёт из PDF сам и сверяет слово в слово; цифры проверяются по цитатам в тексте PDF. Паспорт
  исследования — из ClinicalTrials.gov (бесплатный API). Механизм общий — «Create from a document»: исследования,
  новости, апдейты компании. Вайрфрейм: `docs/flows/site-pages.md → Страница исследования`.
- Публикация в LinkedIn — человек копирует и постит. Автопостинг из админки — только если замер покажет, что канал
  работает (и после проверки доступа к API страниц компании — гипотеза, что нужно одобрение приложения).

Как это соотносится с тем, что есть: таблица `publications` (Evidence) уже хранит часть полей; текстовые страницы
(`pages`) — тело страниц исследований. Объединять или связывать — решение архитектуры, после ответов ниже.

## Что известно о процессе (владелица, 2026-11-14)
- Направление **связано с идеей Nir** (поиск клиентов в LinkedIn).
- Вести LinkedIn будут **Alyssa Elkins или Emily Richardson**. **Они сами выбирают**, какие посты годятся.
- Аккаунт LinkedIn, судя по всему, **один на все регионы** (понимание владелицы, подтвердить у клиента).

Что из этого следует для устройства:
- Генератор никогда не публикует и не решает, что постить: он даёт черновик по запросу из записи исследования, а
  выбирают и публикуют Alyssa или Emily. Это и есть propose → confirm.
- Раз аккаунт один, а утверждения региональные, черновик честно показывает **регионы продукта**: данные уже есть
  (`products.regions`, `publications.regions`). Например: «Product on the site in: OUS, APAC». Решает человек, а не
  мы; помощь — не дать забыть. Регионы на сайте ≠ регуляторный статус: это подсказка, а не проверка.
- Ссылка в посте ведёт туда, где исследование есть. Если оно есть во всех регионах — на адрес без региона, дальше
  выбор региона (как сейчас у Therapies и Evidence). Правило — решить на вайрфрейме страницы.

## Ограничения
- **MLR.** Пост с клиническими цифрами — промо-материал. Безопасный порядок: утверждённый текст → страница → пост.
  Кто проверяет и проверяют ли посты вообще — вопрос клиенту.
- **Регионы.** Аккаунт один, а продукт или показание, не одобренное в US, в посте — риск. Выбор постов — за
  Alyssa / Emily; от нас — пометка регионов в черновике.
- **Объём.** Новое сверх миграции сайта (как веб-DAM). Решение и оценка — за владелицей.

## Как поймём, что работает
Пилот без автоматизации: N постов о исследованиях со ссылками с UTM → месяц → клики на страницы исследований (GA4) и
заявки с `utm_source=linkedin` (в админке «Requests»). Порог «работает» — согласовать с клиентом до старта.

## Пост LinkedIn — структура (вайрфрейм 2026-11-14, предложение)
Флоу: `docs/flows/linkedin-post.py` → `.json`, страница (приватная ссылка): https://claude.ai/artifact/D5mJdwKcQNpjZrEo61CyEF.
Сборка: `python3 docs/flows/linkedin-post.py && python3 .claude/skills/wireframes/scripts/build.py docs/flows/linkedin-post.json <scratchpad>/linkedin-post.html --pack docs/flows/pack.js`, публиковать тем же путём.

- **Вход:** в редакторе опубликованной страницы исследования — кнопка «LinkedIn post» (до Publish неактивна: «Publish
  the page first — the post links to it»); после Publish тост предлагает подготовить пост.
- **Состав поста** — по шаблону из проверенных блоков страницы, без ИИ: зацепка (вывод + главная цифра, влезает до
  «…see more») · контекст (паспорт) · 3 итога (ключевые цифры) · автор (из документа; отметить людей — в LinkedIn) ·
  ссылка · регуляторная строка продукта · хэштеги терапии. Каждая часть подписана, откуда она. Шаблон один раз — в MLR.
- **Ссылка:** по умолчанию без региона — сайт сам ведёт врача в его регион по стране (доработка: сейчас так умеют только
  Evidence и обзор терапий); или один регион. UTM ставится сам; `utm_campaign` своя у каждого поста (в заявку попадают
  только source/medium/campaign). Бейджи: где живёт страница и где продукт на сайте — подсказка, не регуляторика.
- **Форматы:** «Text + link preview» (карточку рисует LinkedIn из og:image страницы) и «Text + image» (квадрат из блока
  ключевых цифр, Download PNG). Та же картинка 1200×627 — превью страницы. Карусель — после пилота.
- **Сверка:** каждое число в тексте ищется среди проверенных значений страницы, на лету и при ручной правке.
- **Другие формулировки:** «Copy instructions for AI» → свой ИИ маркетинга → 3 варианта; вариант с непроверенной цифрой
  помечен и не вставляется.
- **Выложить:** Copy post text → человек постит сам → вставляет ссылку на пост → «Posted». У страницы — список её постов
  и заявок по каждому (из нашей базы). Клики и охват — в LinkedIn и GA4, в админке не показываем.
- **Заявки:** колонка «Came from», фильтр «From LinkedIn», название поста вместо сырой utm_campaign. Форма Contact из
  страницы исследования — тема demo и «About: <исследование>».

Новое для кода (после решения): `social_posts` (страница, текст, формат, регион ссылки, utm_campaign, ссылка на пост,
кто и когда), og:image страницы из ключевых цифр, адрес исследования без региона, «Came from» в Requests.
Гипотезы проверить: сколько знаков до «…see more» на компьютере и телефоне; сокращает ли LinkedIn ссылки; доступ к API.
