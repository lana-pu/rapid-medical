# Бриф фичи: рабочий редактор страниц в админке

Статус: черновик на одобрение владелицы, 2026-11-12. Основа — ADR-006, флоу `docs/flows/site-editor.json` (12 экранов),
текущий редактор на странице (`docs/screens/on-page-editor.md`).

## Намерение
Нетехнический редактор Rapid Medical (маркетинг: Emily, Alyssa) сам меняет сайт: находит страницу, правит текст и медиа прямо
на ней, добавляет, сдвигает и удаляет секции из готовых, проверяет и публикует, при ошибке возвращает прошлую версию. Дизайн
при этом заперт: шрифты, цвета и отступы редактору недоступны, только варианты блоков, разрешённые дизайнером.

Решения владелицы 2026-11-12: делаем весь флоу одним заходом; регионы пока остаются тремя копиями страницы (US, Europe, APAC),
наследование — отдельным этапом после ответа Emily.

## Аудитория
3–4 человека клиента, роли admin и editor. Отдельного согласования нет: одобрение — это Publish (ADR-006).

## Критерии успеха
1. **Страница = список блоков в базе.** Страницы терапий, текстовые страницы, Home, About, Careers, Evidence и обзор терапий
   хранят свой состав как упорядоченный список блоков. После переноса сайт выглядит как до него (e2e и снимки сравнения).
2. **Список страниц** (`/admin/pages-list` или вход «Pages»): поиск по названию, миниатюра, регион, статус словами
   («Live», «Live, with unpublished changes», «Draft»). Клик — страница открывается в редакторе.
3. **Верхняя панель редактора** вместо нижней: назад, название страницы, меню региона, статус сохранения
   («Saving…» → «Saved. Not live yet»), отмена последнего действия, Preview, Publish.
4. **Секции:** клик по секции выделяет её; панель секции — вариант (из разрешённых), вверх / вниз, копия, удалить.
   Между секциями — «+ Add section»: список готовых блоков с картинкой и описанием. Новая секция появляется с примерным
   текстом и сразу правится. Регуляторный блок (Indications) нельзя удалить или сдвинуть.
5. **Правка на месте** остаётся: короткий текст — прямо в странице; видео, картинки, ссылки и скрытые поля — в боковой
   панели рядом со страницей.
6. **Регион:** меню над страницей переключает на ту же страницу в другом регионе. «Compare with…» подсвечивает рамкой
   секции, которые отличаются от выбранного региона.
7. **Проверка перед публикацией:** список изменений на странице словами («Changed title», «Added section Key numbers»),
   Publish → экран «Live now» с адресом и ссылкой на живую страницу.
8. **История:** список версий страницы (кто, когда), просмотр и «Restore this version» (восстанавливается черновиком,
   на сайт — после Publish).
9. **Новая страница по шаблону:** «New page» → шаблон (текстовая страница, лендинг, страница терапии) → регион → открывается
   в редакторе черновиком.
10. **Двое правят одну страницу:** второй получает «This page was changed by {имя} — reload to see their changes», правка
    не затирает чужую молча.
11. **Демо на GitHub Pages:** секции работают и там, сохраняются в браузере, как сейчас тексты.

## Исключения (не строим сейчас)
- Наследование регионов и «сбросить к общему» — после ответа Emily (BACKLOG).
- Комментарии на месте, как в Figma (ADR-006) — отдельная фича.
- Экран «Website или training tool» — админки инструмента ещё нет; кнопка без действия запрещена правилами.
- Правка меню и футера — ADR-006 называет второстепенным.
- Библиотека компонентов для дизайнера и правка оформления блоков.
- Страницы, собранные из коллекций целиком (News & Events, Webinars, Open positions, Contact, выбор региона): их секции
  остаются фиксированными, записи правятся как сейчас.
- Отложенная публикация в редакторе (в админке она есть).

## Контекст проекта
- Next 16, React 19, Drizzle + Postgres, Vitest, Playwright.
- Блоки: `src/blocks/` (23 типа, у каждого `fields`, `variants`, `pinned`, `nestable`). Сейчас страницы собираются из полей
  записей адаптерами `from-solution.ts`, `from-pages.ts`, `from-settings.ts` — они станут разовым переносом в список блоков.
- Черновики и версии: `drafts` (полный снимок записи), `setting_drafts`, `revisions` (ADR-003). Список блоков — поле записи,
  поэтому черновик, публикация и история работают для него без отдельного механизма; для синглтонов нужно добавить версии.
- Текущий редактор: `EditorOverlay.tsx`, server actions `src/admin/inline.ts` (проверка пути поля по схеме).
- Блоки со списками из коллекций (новости, публикации, вебинары, вакансии) хранят настройку, а данные подтягиваются при
  показе. Адреса, зависящие от региона и продукта, хранятся шаблоном и подставляются при показе.
