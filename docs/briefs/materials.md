# Бриф фичи: одна сущность «материал» (ADR-009, шаг 1)

## Намерение
Публикации (102), новости (53) и 9 страниц-материалов из `pages` (11 строк по регионам) становятся одной таблицей
`materials` с полем «вид»: исследование · публикация · новость · клинический случай · документ. Сайт (Evidence, News &
Events, главная, страницы материалов) читает только её; в админке — один список **Publications & news**. Это
фундамент: следующий шаг — «Create from a document» (BACKLOG п. 8) поверх одной сущности, а не двух таблиц.
Посетитель изменений не видит.

Вариант (а) развилки BACKLOG п. 8 — решение владелицы 2026-11-18.

## Аудитория
Маркетинг Rapid Medical в админке (Emily, Alyssa): один список вместо двух, материал можно показать и в Evidence, и в
новостях. Посетители сайта — без изменений.

## Решения владелицы (интервью 2026-11-18)
- «Показать в новостях» — **простой флаг**, без даты «до»: лента по дате, старое уезжает вниз само.
- Название списка в админке — **Publications & news**.
- Рамки — как ниже; «Create from a document», страница knowledge base и слияние дублей — не в этом шаге.

## Решения по коду (выведены из ADR-009 и кода, не спрашивались)
- **Таблица `materials`:** `kind`; общие поля (заголовок, дата, продукт, регионы, источник, ссылка на оригинал, PDF и
  лицензия, аннотация, картинка, Google-тексты, статус); поля страницы (`slug` для прежних адресов, `blocks`, `bodyHtml`,
  `noindex`); где появляется — `showInEvidence`, `showInNews`, `featured` (хайлайты); `legacyRef` (`publications:12`,
  `news_items:5`, `pages:6`) — откуда перенесена запись.
- **Перенос один в один.** Публикации сохраняют свои id (1–102) — адреса `/{region}/evidence/{id}-{slug}` не меняются.
  Новости и страницы получают новые id; старый адрес новости `/news-events/{старый id}-…` переадресуется (308) на новый
  по `legacyRef`. Страницы исследований сохраняют прежние адреса (`/us/success-study-final-results`, `/distals-results`,
  `/LongTerm_Outcomes` …) через `slug`.
- **Где появляется после переноса — как сейчас:** публикации — Evidence; новости — News & Events; страницы — только своим
  адресом (в списки не попадают, пока владелица не отметит). `featured` — как было у записи.
- **Вид при переносе:** публикации → «публикация»; новости → «новость»; SUCCESS ×3, DISTALS, DW24 SVIN Poster →
  «исследование»; Long-term outcomes → «публикация»; Patankar, See the comparison ×3 → «клинический случай»;
  IFU Canada → «документ» (по таблице ADR-009).
- **Старые таблицы** `publications`, `news_items` не удаляются (откат), код их не читает и не пишет. Перенесённые строки
  `pages` удаляются в той же миграции — их содержимое целиком в `materials` (`legacyRef`). В `pages` остаются Privacy,
  Terms, Compliance, Patents и лендинги «COMANECI for vasospasm».
- **Админка:** ресурс `materials`, фильтр по виду; в дереве разделов он виден в Evidence (публикации и исследования) и в
  News (новости); `/admin/publications` и `/admin/news` ведут на него с фильтром.

## Критерии успеха
- В базе одна таблица материалов: 102 + 53 + 11 = 166 записей; у каждой есть `legacyRef`.
- Evidence (три региона), News & Events, главная, страницы публикаций, новостей и исследований показывают то же, что до
  переноса: те же записи, порядок, счётчики, featured; e2e зелёные.
- Прежние адреса работают: публикации — те же; новости — 308 на новый id; исследования — те же slug-адреса.
- В админке **Publications & news** — один список с фильтром по виду; новая запись любого вида сохраняется и публикуется
  через обычный workflow (черновик, история, расписание).
- Медиатека считает файлы материалов «используемыми», как раньше.
- Статическое демо собирается.

## Исключения
- «Create from a document», «Copy instructions for AI», проверка цитат.
- Страница knowledge base и вебинары как вид материала.
- Слияние дублей публикаций (27 групп) — ждём Emily (письмо, вопрос 21).
- Новые шаблоны страниц по виду; дизайн страниц не меняется.
- Удаление старых таблиц — отдельной миграцией после проверки.

## Контекст проекта
Next.js 16 (app router), Drizzle + Postgres, ресурсы админки декларативно (`src/admin/resources.ts` → `engine.ts`),
редакционный процесс общий (`drafts`, `revisions`, `comments` по `resource` + `recordId`; для публикаций и новостей в
базе пусто). Страницы материалов: `src/lib/material.ts`, `docs/screens/material.md`. Блоки страниц — ADR-007.
