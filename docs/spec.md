## Продукт

**Что.** Корпоративный маркетинговый сайт Rapid Medical (производитель нейроваскулярных
медицинских изделий: TIGERTRIEVER™, COMANECI™, DRIVEWIRE™ / COLUMBUS™) + собственная контент-админка.
Заменяет четыре сайта на Duda (`www.`, `us.`, `ous.`, `apac.rapid-medical.com`) одним Next.js-приложением.

**Для кого.**
- **Посетители** — клиницисты (нейроинтервенционисты) и дистрибьюторы; контент и регуляторные тексты
  отличаются по регионам (US / OUS / APAC). Ищут: терапии и устройства, клинические публикации (Evidence),
  вебинары, контакты/заказы, вакансии.
- **Редакторы** — маркетинговая команда Rapid Medical: правят тексты и медиа без разработчика
  (формы админки + on-page editor), публикуют через редакционный процесс.

**Ключевые возможности.** Региональные терапии с регуляторными текстами; Evidence с вкладками по
продуктам; формы (контакт / вебинар / карьера) с сохранением в БД и e-mail; админка, сгенерированная
из декларативного описания ресурсов; черновики поверх live, preview-ссылки, отложенная
публикация, история ревизий; on-page editor; медиапайплайн (WebP-варианты, постеры видео); 301 со
старых доменов Duda; статическое демо на GitHub Pages.

**Стадия (со слов владелицы, 2026-11-05).** Продукт существует на уровне документации и демо. Внешние
сервисы **не подключены**: нет Vercel, Neon, домена, SMTP, S3 — сайт нигде не работает в проде.
Демо повторяет текущие сайты Duda и нужно прежде всего, чтобы собрать с них информацию.

**Задача по сайту:** миграция с Duda и визуальный редизайн. Структуру сильно не меняем, юзабилити улучшаем
попутно. **Админка проектируется заново** и детально: она запутанная, и в ней будет вход сразу в два продукта
(ADR-005). Целевая модель работы: редакторы и дизайнер, шаблоны страниц, комментарии вместо согласования (ADR-006);
разделы «Доступы» и «Редакционный процесс» ниже описывают текущий код.

**Инструмент Tigertriever** — отдельный продукт в этом же репозитории: офлайн-обучение врачей плюс онлайн Content
Studio, материалы в `docs/tigertriever/`. Пользователи пересекаются, поэтому админка общая: вход, затем выбор,
сайт или инструмент. Модель контента инструмента отличается от сайта — см. раздел «Инструмент Tigertriever» ниже
(предложение, кода нет).

Новый тип контента = таблица в `src/db/schema.ts` + запись в `src/admin/resources.ts`; списки, формы,
валидация и сохранение генерируются (`src/admin/engine.ts`).

**Блоки страниц** (`src/blocks/`). Страница рендерится как упорядоченный список блоков `{type, variant, data, edit}`.
Блок описан в одном файле: название, назначение, варианты, поля, пример данных, компонент; все блоки собраны в
`registry.ts`. Похожие секции — один блок с вариантами. Поле `edit` связывает поля блока с полями записи для
on-page editor (`data-e`), поэтому правка на странице пишет туда же, что и форма админки.
**Хранение — список блоков (ADR-007, в работе с 2026-11-12).** Состав страницы — поле `blocks` записи
(`solutions`, `pages`, `site_pages`): `{id, type, variant, data, source?}`. Списки из коллекций (`source`) и `{region}` /
`{product}` в ссылках подставляются при показе (`src/blocks/stored.ts`). Пока `blocks` пуст, страница собирается из полей
записи старыми адаптерами `src/blocks/from-*.ts`; перенос — `scripts/migrate-blocks.ts` (в bootstrap и после сида).

## Регионы и URL

| Регион | Код | Охват (по `REGION_LABELS` / `regionForCountry`) |
|---|---|---|
| Americas | `us` | Северная и Латинская Америка |
| Europe, Middle East, LatAm & Australia | `ous` | всё, что не `us`/`apac` |
| Asia & Pacific | `apac` | Азия + Ближний Восток (IL, SA, AE, TR, EG …) |

Расхождение: подпись `ous` говорит «Middle East / Latin America», а `regionForCountry` относит Ближний
Восток к `apac`, Латинскую Америку — к `us` (см. BACKLOG → Решения за владельцем).

- **Регион в пути**, не в cookie: `/{us|ous|apac}/…` (см. ADR-002). Неверный сегмент → 404.
- Cookie `rm_region` (1 год) — последний посещённый регион, только чтобы выбрать меню «Therapies»
  и CTA на главной. Cookie `rm_geo` (30 дней) — предложенный по стране регион (заголовки
  `x-vercel-ip-country` / `cf-ipcountry` / `x-country-code`); жёсткого гео-редиректа нет. Если
  предложенный регион не совпадает с текущим — баннер над шапкой «It looks like you are in … · Go to the
  … site / Stay here» (`RegionBanner`), отказ запоминается cookie `rm_geo_dismissed` (30 дней).
  Региональные страницы (терапии, лендинги, Evidence, вебинары) отдают `hreflang`: `en-US` → `/us/…`,
  `en` → `/ous/…`, `en-AU` → `/apac/…`, `x-default` → OUS-версия.
- **Решение 2026-11-10 (аудит Emily), сделано:** (баннер выше остаётся только для чужого региона по прямой ссылке —
  IP-регион ≠ регион страницы, пока посетитель сам не выбрал регион)
  - Регион по IP **применяется сразу** при первом заходе на любую страницу (пишется в `rm_region`), без
    баннера-вопроса. Ручной выбор в переключателе шапки тоже пишется в `rm_region` и IP больше не перебивается.
  - Страна не определилась (VPN, нет заголовка, страны нет в карте) → «Therapies» и «Evidence» ведут на
    `/choose-your-location`; это единственный случай, когда посетитель видит выбор региона.
  - «Therapies» в шапке — выпадающий список терапий текущего региона, сгруппированный по направлениям
    (Ischemic stroke / Hemorrhagic stroke / Access), внизу «All therapies» → `/{region}/therapies`.
    «Evidence» → `/{region}/evidence`. www-адреса `/our-solutions`, `/evidence` → в регион, при неизвестной
    стране — выбор региона.
  - Обзор `/{region}/therapies` остаётся **необязательной** страницей для тех, кто не знает линейку (инвесторы,
    первый визит). Ведут на него: кнопка на главной, «All therapies», корень legacy-хостов и `/{region}`.
    Собирается из записей терапий (название, подзаголовок, картинка, направление), своих текстов — только
    заголовок; у терапии необязательное поле «одна цифра-доказательство» (заполняется после MLR).
  - Реализация: `proxy.ts` пишет `rm_region` из IP и в ответ, и в сам запрос (первая страница уже с регионом);
    коды стран-заглушки (XX, T1, A1, EU…) = страна неизвестна. Переключатель в шапке (`RegionSwitcher`) →
    `GET /api/region?to=&back=` (запоминает выбор, гасит баннер, возвращает на ту же страницу в другом регионе;
    нет такой страницы в регионе → обзор). Направление — поле `solutions.therapyGroup` (миграция 0010),
    доказательство — `solutions.proofPoint`. `hreflang x-default` → OUS-версия страницы (выбор региона теперь
    редиректит и не может быть x-default).
- **Legacy-хосты** (`us.` / `ous.` / `apac.rapid-medical.com`, `*-rapid-medical.juuced.co`) → 301 на
  `NEXT_PUBLIC_SITE_URL/{region}{path}`; корень → `/therapies`, `lvo|mvo|aneurysm|vasospasm|access|drivewire` →
  `/therapies/{slug}`.
- Прочие старые пути — таблица `redirects` (проверяется перед 404 в catch-all страницах); промахи
  пишутся в `not_found_log`.
- `/{region}` → редирект на `/{region}/therapies`; `/{region}/contact-us` → `/contact-us?region=…`.
- Терапии в сиде: US — lvo, aneurysm, drivewire; OUS и APAC — lvo, mvo, aneurysm, vasospasm, drivewire.
  Страница DRIVEWIRE живёт на `/{region}/therapies/drivewire` (Fix List C.18); `/{region}/access` и
  `/{region}/therapies/access` → 301 через таблицу `redirects` (страница терапии проверяет её перед 404).

| Кто | Что может (по коду) |

| **Посетитель** | Все публичные страницы (только `status = published`), формы. С preview-ссылкой (JWT, 7 дней) — видит черновики и pending-правки |
| **editor** | Вход в `/admin` и редактор на странице; создаёт, правит, публикует и снимает с публикации любые записи; медиатека, заявки, расписание. ## Редакционный процесс

Ресурсы со `status` (`solutions`, `publications`, `news`, `webinars`, `team`, `jobs`, `pages`) идут через
workflow (`src/admin/workflow.ts`); `products` и `redirects` сохраняются сразу.

| Ситуация | Что происходит при Save |
|---|---|
| Новая запись | Вставка со `status = draft`, ревизия `created` |
| Запись не опубликована | Правка на месте, ревизия `draft`; если в форме выбран `published` — сразу `publish()` |
| Запись опубликована | Live не трогается; изменения → `drafts`, ревизия `draft`, «pending» |

- **Publish** — любой вошедший (редактор, дизайнер, админ). Сохранение само не публикует: только Publish или статус
  `published` в форме неопубликованной записи. Черновик сливается в live, `status = published`, черновик удаляется, ревизия `published`,
  `revalidatePath` по `resource.revalidate` + preview-URL + `/sitemap.xml`.
- **Unpublish**: неопубликованные правки переходят в запись (ревизия), расписание отменяется; так же и массовое Unpublish из списка.
- **Отложенная публикация**: `drafts.publishAt`; `GET /api/cron/publish` публикует всё, у чего время
  наступило (системный актор «Scheduler»).
- **История**: `/admin/{resource}/{id}/history` — сравнение двух ревизий (или live/pending) по полям с
  подсветкой слов; restore = сохранение через тот же workflow.
- **Preview**: `/api/preview?token=…` включает Next draft mode; публичный слой (`src/lib/content.ts`)
  показывает неопубликованные строки и накладывает `drafts`; баннер «Exit preview».
- **On-page editor**: см. `docs/screens/on-page-editor.md`. Секции, история и проверка перед публикацией — там же.
  Синглтоны (Home, About, Careers, Evidence, обзор терапий) — ресурс `site-pages` с тем же workflow (ADR-007).
  `setting_drafts` остаётся для полей настроек, которые видны на странице (офисы на About — из Contact details).
- **Restore не меняет статус записи** (2026-11-12, ревью безопасности): версия, снятая в опубликованном состоянии,
  не публикует неопубликованную запись — публикация всегда отдельный шаг с проверкой прав.

### Состояния и публикация

- **Save не меняет пакет.** Правки копятся в черновике урока. Статус урока и конфигурации: «In package v1.2»,
  «Unpublished changes», «Not in any package».
- **Отдельного согласования нет** (ADR-006): Publish в инструменте = собрать новый пакет. Кто имеет право нажимать —
  вопрос MED-08 к маркетингу.
- **Publish:** состав пакета (какие конфигурации и пары) → проверки → сборка → пакет vN+1 со статусом Built →
  редактор скачивает, проверяет офлайн, отмечает Sent. Блокеры: пустое обязательное поле; у этапа нет медиа или медиа
  «Needs filming»; у пары нет одной стороны. Блокер показан у места с действием «Open stage» или «Leave out of this package».
  **Предложение 2026-11-11, ждёт владелицы:** у блокера «нет видео» на этапе есть третье действие «Publish without this
  video». Оно ставит этапу явную отметку (видна в уроке и в What's ready, снимается одной кнопкой, попадает в Changes);
  врач на этом этапе видит «Video not filmed yet», в сравнении эта сторона пустая с той же надписью. Без этого спека
  противоречит себе: путь врача и автопереход описывают этап без видео, а Publish такой пакет не собирает.
- **Changes:** тот же этап рядом: слева «In package v1.2», справа «Your draft»; изменённые поля подсвечены; список
  затронутых конфигураций и пар.
- **Общее медиа и общий текст:** перед заменой показать, где ещё используется; выбор «Only this lesson» (урок получает
  свою ревизию) или «Everywhere it's used (N lessons)». Ничего не распространяется само. Тот же выбор для заголовка и
  пунктов, которые у клиента помечены «All handles — same».
- **Предупреждение в уроке** — наше добавление из ресёрча (FS-05), в черновике клиента такого блока нет. Поле
  необязательное; нужен ли блок и какой текст — вопрос к маркетингу (MED-04).

  утверждения и данные исследований. Правило проверки или пометки текста — вопрос к маркетингу, в инструменте пока нет.
- История, комментарии на месте, Undo — те же механизмы, что у сайта.

### Офлайн-пакет (контракт для спайка S0)

ZIP: `index.html` + `manifest.json` (версия, рынок, конфигурации, пары, зафиксированные ревизии) + медиафайлы.
Открывается с `file://`, без сетевых запросов; тот же рендер урока, что в Preview. Проверить на машинах клиента
(BACKLOG → Сейчас, п. 5); до проверки архитектуру сборки не обещать.

**Данные пакета** (формат 1, 2026-11-11). Один объект: `format`, `package`, `version`, `market {id, name}`, `built`,
`sections` (порядок разделов), `configs` (id, модель, ручка с названиями), `upcoming` (модели фазы 2 для «No training
yet»), `lessons[config][section]` (`head`, `points`, `cues` — время начала пунктов в секундах, `notes`, `same`, `media`,
`graphics`, `warn`), `media[id]` (`file` относительно пакета, исходное имя, версия, длительность), `pairs` (модель, две
конфигурации, `diffs[section]` — текст «What's different»). Этап без видео — `media: null`. В ZIP объект лежит в
`content.js` как `window.TT_PACKAGE = {…}` (браузер не читает JSON с диска); Studio отдаёт тот же объект файлом `.json`.
Учебный прототип v0.6 рисуется только из этого объекта.

Отметки «смотрел» и место в клипе хранятся в хранилище браузера (localStorage). Ключ включает пакет, рынок и версию:
в Chrome все страницы `file://` делят одно хранилище, и без этого два пакета на одной машине видят отметки друг друга.
Хранилище недоступно — обучение работает без отметок и без «Продолжить», без ошибки. Проверка «Remembered after
reopening» в пакете S0 (2026-11-11).

### Путь врача (по вайрфрейму клиента)

**Рынок в интерфейсе обучения не выбирается** (владелица, 2026-11-09). У клиента рынок определяется геолокацией, рядом переключатель локации в хедере; в обучение он приходит готовым, пакет собран под один рынок. Позже возможно разовое подтверждение при входе, что геолокация сработала верно, но не постоянное окно.

Модель (фаза 1: Tiger 13, 17; фаза 2: Tiger 21, 25) → ручка, если у модели и рынка есть
выбор → первый раздел программы, Before you begin, если есть для конфигурации. Отдельного экрана обзора нет: разделы показывает полоса этапов, при повторном открытии врач попадает туда, где остановился. Если в пакете одна конфигурация, шаги выбора
пропускаются. Экраны врача — `docs/tigertriever/design/screen-map-v0.1.md`, прототип `prototypes/training-app-v0.4.html`.

- **Модели фазы 2** (Tiger 21, 25) видны в выборе с пометкой «ещё нет обучения» и не открываются, пока у них нет контента
  (владелица, 2026-11-09).
- **Автопереход** (владелица, 2026-11-09): по умолчанию выключен, клип при открытии этапа не стартует, его запускают
  кнопкой. В плеере переключатель «Автопереход»: когда он включён, после конца клипа 3 секунды показывается «Дальше:
  <этап>» с кнопкой отмены, затем открывается следующий этап и его клип стартует сам. После Closing всё останавливается.
  Работает в обычном плеере и в режиме показа; в сравнении ручек выключен. Выбор запоминается на этом компьютере,
  если браузер позволяет хранить настройки для файла с диска (проверить в S0). Если у следующего этапа нет видео, переход останавливается на
  этом этапе с сообщением «видео ещё нет».
- **Экран этапа** (бенчмарк, этап 07): плеер. Сверху только контекст и номер этапа, видео крупно, заголовок и пункты рядом и
  видны без прокрутки. Над видео переключатель ручки, если у модели и рынка их две: тот же этап перерисовывается с другой ручкой,
  метка активной ручки крупная. «Показать обе» открывает сравнение рядом, выход возвращает на этап. Одна навигация по этапам:
  полоса и «назад-вперёд», без хлебных крошек и поиска. Режим показа: на весь экран, крупный текст, стрелки клавиатуры, без полосы этапов; только на ноутбуке и большом экране.
- **Выход и продолжение** (владелица, 2026-11-10): в шапке урока «Programme» открывает список разделов поверх урока (отметки
  «смотрел», длительность, где остановился) и выход к выбору устройства. Место в клипе сохраняется; при возврате на этап
  предлагается «Продолжить с 0:07» или «С начала», сам клип не стартует. На экране выбора устройства — «Продолжить» с последнего
  места.
- **Текст идёт за видео**: пункт, который сейчас показывает клип, подсвечен; клик по пункту переводит клип к его началу. Время
  пунктов задаёт редактор в Content Studio.
- **Сравнение ручек** заметно на каждом этапе Tiger 13, где есть обе ручки; где пары нет, кнопка недоступна с причиной.
  В сравнении: «Play both» запускает оба клипа одновременно, скорость 1× / 0.5× / 0.25×, общий ползунок для медленного
  просмотра. Ползунок выравнивает клипы по пунктам текста, а не по секундам: клипы сняты по-разному и разной длины.
  Без времени пунктов ползунок двигает каждый клип в своей доле длительности, с пометкой об этом. Над текстами блок
  «Что отличается» от Rapid Medical; пункты, одинаковые для обеих ручек, приглушены, различающиеся выделены. Раньше
  синхронизацию отвергали (этап 08), решение владелицы 2026-11-10.
