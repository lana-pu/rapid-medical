# Юзабилити публичного сайта глазами нового посетителя (2026-11-13)

Кто смотрел: агент, в роли нейроинтервенциониста из США и из Европы, который впервые зашёл на сайт.
Как: демо https://lana-pu.github.io/rapid-medical/ (Playwright, ширина 1280 и 390) плюс сверка с кодом
`src/app/(site)/`, `src/blocks/`, `src/components/site/`. Путь: Home → выбор региона → Therapies → LVO
(US, OUS) / Aneurysm (OUS) с вкладками → Evidence → Webinars с формой → News & Events → событие → About →
Careers → Open positions → Contact Us с формой → Privacy Statement → 404, плюс переключатель региона.

Что сюда **не** входит: визуальный стиль (он намеренно нейтральный), смена структуры, 9 вопросов из
`docs/site-ia.md → 7` и пункты из `BACKLOG.md → Сайт: найдено во флоу врача` и `Cookie consent` (№10).
Код не менялся.

Обозначения: **[мешает]** — посетитель не может выполнить задачу или путается · **[неудобно]** ·
**[мелочь]**. **Код** — исправляется в коде. **Текст** — тексты и материалы клиента.
Формат пункта: где → что не так → почему мешает → **Минимальная правка**.

## Ограничения демо (это не баги сайта)

Демо — статическая сборка без сервера, поэтому часть поведения в нём не проверить. Код смотрел отдельно:
- `?topic=demo&region=ous` не предзаполняет форму, а `?next=evidence` в выборе региона ведёт на Therapies.
  В коде это работает (`contactToBlocks`, `choose-your-location/page.tsx`).
- Переключатель региона ведёт на обзор терапий, а не на ту же страницу. В коде `/api/region` сохраняет
  страницу (`RegionSwitcher.tsx`, ветка `DEMO`).
- Отправка формы в демо **молча ничего не делает**: нет ни ошибки, ни успеха. Если демо показывают клиенту,
  кнопка выглядит сломанной. Можно добавить заглушку «в демо формы не отправляются».
- Ссылки из текстов без base path ведут на 404 GitHub Pages: `/ous/success-study-final-results`,
  `/ous/comaneci-spinal-case-patankar`, ссылки регионов на карте About (`/contact-us?region=…`). В проде
  (base path пустой) они работают.
- Регионального уведомления в футере и баннера «you seem to be in …» в демо нет: они зависят от cookie
  и IP.
- Панель редактора перекрывает переключатель региона, поэтому для прогона её приходится убирать.

## Находки (код), по важности

### [мешает]

1. **Все формы сайта (Contact, Webinars, Careers, Event), ошибка сервера, обе ширины.** Если сервер вернул
   ошибку, введённое стирается. `ContactForm.tsx` передаёт `useActionState` в `<form action>`, а React 19
   после завершения action сбрасывает неконтролируемые поля даже при ответе `{ ok:false }`. Типичный
   случай: адрес `a@b` браузер пропускает (`type=email`), а zod отклоняет. Врач видит «Please check the
   highlighted fields» и пустую форму из 12 полей, сообщение тоже пропало. Вдобавок на 390 «подсвеченных»
   полей нет: только мелкий красный текст справа от подписи, а ошибка темы не выводится вовсе.
   *Посмотреть вживую в демо нельзя, проверить на `npm run dev`.*
   **Минимальная правка:** возвращать введённые значения в `FormState` и подставлять их в `defaultValue`
   (или сделать поля контролируемыми), выводить `err("topic")`, а полю с ошибкой ставить `aria-invalid` и
   рамку из токена ошибки.

2. **Регистрация на событие (`/events/{slug}`, форма `event`), успех.** После регистрации показывается
   «Thank you for contacting us. We will get back to you as soon as possible.». Это не подтверждение
   регистрации: врач не понимает, зарегистрирован ли он, и пишет повторно. То же видит кандидат на Careers.
   Текст после запроса вебинара уже в BACKLOG, здесь речь о событиях и Careers.
   **Минимальная правка:** текст успеха брать по `form` (event: «You're registered for {title} on {date}.
   We'll email the details.», careers: «Thanks — we've received your details.»).

3. **Webinars `/us/webinars`, 1280 и 390.** Карточки вебинаров не кликаются, а выбирать вебинар нужно в
   выпадающем списке под подписью «How can we help? Select a topic.*». Врач кликает по карточке, ничего не
   происходит. Ниже он видит форму, похожую на общий контакт, и не понимает, что поле «topic» — это и есть
   выбор вебинара. Со страницы терапии кнопка «Request to view» (вкладка In-Practice) тоже открывает
   форму без выбранного вебинара.
   **Минимальная правка:** на карточку добавить «Request this recording», которая ведёт на
   `#request?webinar={id}` и предвыбирает его в списке. Подпись select задавать по `form`:
   «Webinar*» для webinar, «Area of interest*» для careers.

4. **About → карта (`Middle East`), выбор региона, контактная форма. Это дополнение к вопросу №3 из
   site-ia.** Клик по «Middle East» ведёт на `/contact-us?region=apac`, а форма предвыбирает «Asia
   Pacific», хотя в ней есть отдельный вариант «Middle East». По IP (`regionForCountry`) Израиль, ОАЭ,
   Саудовская Аравия и Турция тоже уходят в APAC, а выбор региона и переключатель называют `ous`
   «Europe & Middle East». Врач из ОАЭ видит в переключателе «Asia & Pacific», выбирает «Europe & Middle
   East» и получает другой набор терапий, а его заявка уходит с регионом «Asia Pacific».
   **Минимальная правка:** до ответа Emily по №3 хотя бы на карте передавать значение для формы
   (`?region=apac&area=middle-east` → «Middle East»). Решение «куда относится Ближний Восток» внести в
   тот же вопрос к Emily.

   тем, хотя ключ `support` в `TOPIC_KEYS` уже есть.

7. **Контактная форма, поле Region (все формы).** Варианты: «Americas / Europe / Asia Pacific / Middle
