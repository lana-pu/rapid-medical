# Разбор текущей админки — основа для единой админки

2026-11-06. Экспертный разбор: код на `e1200af` и демо. С реальными редакторами не проверялось, поэтому причины
ниже — наблюдения, а раздел «Направление» — гипотеза. В демо сохранение не работает, поведение сохранения взято из кода.

## Главный вывод

Админка устроена как база данных, а редактор думает страницами сайта. Функций хватает: черновики, история,
предпросмотр, согласование. Запутанность идёт не от их нехватки, а от того, что одно и то же действие
работает по-разному в зависимости от того, в какой таблице лежат данные.

| № | Задача | Путь сегодня | Где ломается |

## Что запутано и почему

### 1. Страница сайта лежит в одном из трёх мест

| Где | Что там |
|---|---|
| Записи в меню | Терапии, юридические страницы, команда, вакансии |
| Вкладка в Site settings | Главная, About, Careers, Evidence, лендинги терапий ×3, выбор локации |
| В коде | Меню, футер, заголовок Contact |

Редактор должен знать устройство базы, чтобы найти страницу. Настройки при этом смешивают контент (Home page) с
системным (Workflow, Integrations): 13 вкладок, последние уезжают за край экрана.

### 2. Четыре правила сохранения

| Что правим | Что делает Save |
|---|---|
| Неопубликованная запись | Правка на месте |
| Опубликованная запись | Черновик, нужен Publish |
| Products, Redirects | Сразу в live |
| Site settings, форма | Сразу в live; заодно публикует черновики, сделанные на странице |

Одна и та же кнопка то безопасна, то меняет живой сайт. Это главный источник ошибок.

### 3. Состояние записи размазано

Статус (draft/published), наличие правок, ревью (четыре значения), расписание и подпись Live показаны отдельно.
Ответ на простой вопрос «что сейчас видят посетители и что будет дальше» приходится собирать из панели.

### 4. Три разные модели регионов

- Терапии: отдельная запись на регион, кнопка Copy to, связи между копиями нет.
- Evidence и вебинары: одна запись с галочками регионов.
- Лендинги: отдельная вкладка настроек на регион.

Для регулируемого контента это критично: разъезд текстов между регионами нигде не виден.

### 5. Форма терапии

67 полей, включая вложенные, 11 разделов одной лентой без навигации. Два поля требуют писать JSON (график, схема
устройства), поля legacy стоят рядом с актуальными, часть полей техническая (Sort order, Slug, Breadcrumb вручную).

### 6. Навигация и слова

16 пунктов плоским списком: контент, настройки и журналы вперемешку. Edit site спрятан внизу сайдбара, за краем экрана
на ноутбуке. Названия расходятся: Therapies / Therapy pages / solutions, Evidence / Publications, Leadership team /
Team members. Главная показывает счётчики записей, а не то, что нужно сделать.

### 7. Два редактора с разными возможностями

Форма умеет всё, на странице можно править только текст и медиа, а структуру нельзя. Правила сохранения у них разные
(пункт 2). Предпросмотр есть не у всех типов: только терапии, команда, вакансии, страницы.

## Что сохранить

- Черновик поверх live и история с diff (ADR-003).
- Правка на странице: лучший опыт для текстов и картинок.
- Подсказка, где используется файл, и запрет удаления.
- Предпросмотр по ссылке, журнал действий, битые ссылки в один клик, таблица спецификаций со вставкой из Excel.
- Генерация форм из описания ресурсов: упрощает перестройку.

## Что нужно инструменту и как это пересекается

Источник: `docs/tigertriever/research/admin-ux-content-workflows.md`, `tables/feature-inventory.csv` (A-01…A-21).

| Что | Сайт | Инструмент | Вывод |
|---|---|---|---|
| Вход, 2FA, роли, журнал | есть | нужно | Общее |
| Медиатека | есть, без замены | нужны версии, применимость, готовность съёмки | Общая основа, инструменту метаданные сверху |
| Согласование | есть, выключено | обязательно, медицинское | Общая модель, инструменту строже |
| История и diff | есть | сравнение с последним релизом | Общая основа |
| Предпросмотр | есть | точная копия для ученика | Общий принцип |
| Единица контента | страница | программа → этап → урок | Раздельно |
| Публикация | сразу на сайт | замороженный релиз, офлайн-пакет | Раздельно |
| География | регионы сайта | рынки × устройство × ручка | Раздельно, это не одни и те же списки |
| Покрытие | нет | матрица и блокеры релиза | Сайту тоже полезно: матрица терапия × регион |

Проблемы сайта из пунктов 2–4 инструмент получил бы в худшем виде: у него цена ошибки выше. Модель состояний и
модель «один объект, несколько вариантов» стоит решать один раз для обоих.

## Направление (гипотеза)

**Одно правило сохранения.** Save никогда не меняет живое. Живое меняет только явное действие: Publish на сайте,
Release в инструменте. Исключения — только системные настройки, и они выглядят иначе.

**Один статус вместо пяти.** Например: Черновик → На согласовании → Одобрено → Опубликовано, плюс пометка «есть правки» и дата,
если запланировано. Для инструмента дальше: Собрано → Распространено.

**Структура.**

```
Вход
└── Рабочий стол: на согласовании, мои черновики, новые заявки
    ├── Сайт
    │   ├── Страницы: дерево как на сайте, включая главную и лендинги
    │   ├── Терапии: одна терапия, внутри регионы рядом
    │   ├── Evidence, Новости, Вебинары, Вакансии, Команда
    │   └── Заявки
    ├── Инструмент
    │   ├── Каталог и покрытие
    │   ├── Программы и этапы
    │   ├── Сравнения
    │   └── Релизы
    └── Общее: Медиатека, Люди и роли, Журнал
        └── Настройки сайта: контакты, редиректы, интеграции (только admin)
```

**Форма терапии.** Разделы с навигацией, те же названия, что на странице; JSON заменить нормальными редакторами,
legacy убрать; техническое спрятать.

## Открытые вопросы

1. Кто реально работает в админке и сколько человек? Ресёрч говорит о маркетинговой команде из двух человек, это из
   документов инструмента, для сайта не подтверждено.
2. Нужно ли согласование на сайте? Если да, кто согласует регуляторные тексты?
3. Правка на странице — основной способ или дополнительный?
4. Должны ли регионы по умолчанию наследовать общий текст с отличиями, или это всегда отдельные тексты? В инструменте
   наследование запрещено без явного подтверждения (нет автоматической синхронизации).
5. Нужно ли редактору менять меню и футер?
