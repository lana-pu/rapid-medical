# 2026-11-22 — Всё в вайрфреймах на дизайн-системе

**Задача:** «всё переводим на дизайн-систему» — шапка, футер, баннер, окно региона, страницы материалов, состояния форм,
решения закрытых страниц, прототип, каталог.

## Что сделано
- `siteChrome()` (`src/components/site/chrome.ts`) — данные шапки и футера из одного места; layout сайта и снимок вайрфреймов.
- Снимок (`blocks-kit/render.cjs`) знает четыре вида узлов: блоки, шапка/футер/баннер, окно `RegionModal` (каждое —
  отдельной загрузкой, `?only=`), страница по адресу (`rm-route`). Состояния — `act` в браузере; значения полей
  переносятся в атрибуты; `:hover` → `[data-wf-hover]` для открытого меню.
- Пак: `links` (горячие зоны на настоящих ссылках, все совпадения, без хвостовых стрелок), `state.hover`, `focus` частей
  шапки; `rm-page` применяет их ко всей странице.
- `site-pages`: 26 экранов решений → сам сайт, заметки эскизов перенесены; «Evidence в коде». Прототип и флоу врача —
  настоящие страницы; `proto-pack.js` больше не используется. Library = каталог на настоящих компонентах.
- «Как было»: `modal-asis.tsx` вместо окна (в старом коде его не было), `chrome.ts` подкладывается в старый код.
- Набор вайрфреймов (Studio): `build.py` проверяет `links` пака как `to`.

## Находки
- Форма Contact: пустые обязательные поля держит браузер, сервер их не видит; серверная ошибка — например, email без домена.
- Ловушка для ботов (`website`) — честный путь к «отправлено» без записи в базу.
- Локально страна в форме не подставляется (IP неизвестен) — отправка блокируется браузером до выбора страны.
- Вакансий в базе сейчас нет: «с ролями» — примерные данные витрины, подписано в заголовке экрана.
