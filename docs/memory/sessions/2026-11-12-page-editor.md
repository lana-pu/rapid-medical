# 2026-11-12 — Рабочий редактор страниц в админке

**Задача:** редактор по флоу `docs/flows/site-editor.json` целиком (решение владелицы 2026-11-12), регионы — пока копии.
Бриф: `docs/briefs/page-editor.md`. Решение по хранению: ADR-007.

## Что сделано
- **Страница = список блоков в базе.** `solutions.blocks`, `pages.blocks`, новая таблица `site_pages` (Home, About, Careers,
  Evidence ×3, обзор терапий ×3). Перенос — `scripts/migrate-blocks.ts` (идемпотентный, также черновики), вызывается из
  bootstrap и e2e-setup; `npm run db:blocks`. Тесты совпадения: все 13 терапий из сида и все синглтоны рендерятся как раньше.
- **Списки — источники при показе** (`src/blocks/stored.ts → SOURCES`): версии в регионах, подпись региона, новости, команда,
  офисы (правятся в Contact details), пины карты, публикации (featured / latest / по продукту), группа терапий, число вакансий.
  Пустой список прячет секцию, как раньше. `{region}` / `{product}` в ссылках; без региона — через выбор региона.
- **Редактор на странице:** верхняя панель (Pages, название, регион, Compare with…, статус словами, Undo, History,
  Preview, Publish); секции — выделение, вариант, ↑ ↓, Copy, Delete, Add section из пресетов; боковая панель для rich /
  link / media; Review changes словами → Live now; History с восстановлением черновиком; конфликт версий двух редакторов.
- **Pages** `/admin/editor`: поиск, фильтр регионов, статус словами, New page по шаблону (текстовая, лендинг, терапия);
  после входа открывается этот экран; ресурс `pages` в сайдбаре — «Text pages».
- **Формы админки:** поля, переехавшие в блоки (`onPage`), скрыты и сохраняются как есть; Site settings без текстов страниц,
  сохранение группы сливает форму с текущим значением.
- **Демо:** секции без сервера (перестановка, копия, удаление, добавление из `/style-guide`), повтор при загрузке;
  экспорт включает `/admin/editor` и `/admin/site-pages/*`. Опубликовано (`gh-pages` db80c97).
- **Безопасность (авторевью):** restore больше не публикует неопубликованную запись (дыра была и в форме админки);
  поля-адреса внутри блоков всегда проверяются как URL.

## Принятые решения
- Состав страницы — поле записи, синглтоны — ресурс `site-pages` (always live): ADR-007.
- Ссылки на странице в режиме правки не переходят (кнопки работают); переход — в Preview.
- Колонки старых полей и ключи настроек не удалены — откат возможен; удалить отдельной миграцией после прода.

## Находки
- Обход объектов при подстановке ссылок превращал `Date` в `{}` — даты новостей и публикаций пропали бы; ловит тест совпадения.
- Метки секций — невидимые `<i hidden>` перед блоком, без обёрток: вёрстка в редакторе та же, что у посетителя.
- dev-сервер Next держал устаревший layout группы `(dashboard)` до перезапуска.

## Открытые вопросы / следующие шаги
- Оценка владелицы: пройти редактор (живой — после подключения сервера; сейчас демо) и флоу.
- Не сделано по флоу: наследование регионов, комментарии, экран «сайт или инструмент», правка меню и футера, мини-превью
  пресетов, добавление секций внутрь вкладок Product details.

## Медиатека (вторая часть дня)
Владелица: «пока функционал, UX — позже»; выбрала медиатеку. Сделано (`docs/screens/admin-media.md`, e2e `media.spec.ts`):
- замена файла везде — черновиком (по умолчанию) или с публикацией, если можно публиковать; точная замена адреса в полях,
  блоках, rich text, списках; описание переносится;
- места использования одним проходом, с черновиками записей и настроек; удаление учитывает черновики; старые тексты
  страниц в настройках не считаются;
- фильтр «No description», очередь «Describe pictures» (163 картинки без alt — тексты за маркетингом);
- описание из медиатеки — основной alt на сайте; API медиатеки требует 2FA.
- Сборка демо отказывается работать на базе с настоящими учётными записями (ревью безопасности).
- Ревью безопасности после коммита: статус из устаревшего черновика (опубликовали → сняли) мог опубликовать запись в обход
  согласования через замену файла, правку на странице и секции. Теперь `saveWithWorkflow` публикует только из формы
  (`formPublish`) и только при `canPublish`; заодно закрыто расхождение «editor публикует через статус в форме» (8df6f25).

## Секции во вкладках и согласование (третья часть дня)
Владелица: «go on» — взяты секции внутри вкладок Product details (из трёх предложенных).
- Адрес вложенной секции — позиция `{блок}/{вкладка}/{j}[/{k}]` (у вложенных блоков нет id); устаревание позиций ловит
  проверка версии страницы. Метки `data-rm-b` с полем `l` (список) и концом каждого списка (`src/blocks/mark.tsx`);
  редактор меряет по спискам, выделяет самую внутреннюю секцию; секция во вкладке кончается и там, где начинается группа.
- Во вкладку — только `nestable` блоки; последняя секция группы уносит подзаголовок; вкладка держит одну секцию.
- Демо: операции во вкладке повторяются после перезагрузки (проверено локальной сборкой, не опубликовано).
- Ревью безопасности (6 замечаний подряд по workflow) — всё исправлено: см. коммиты 8df6f25…8aa006d и `spec.md → Workflow`.
- Находка: `saveRow` не переводил даты из JSON черновика в Date — Publish отложенных правок новости падал.
- Находка: после «добавить → удалить» черновик совпадает с live — Publish честно неактивен, нужен Discard.

## Весь функционал админки (четвёртая часть дня)
Владелица: «доделаем весь функционал админки, а потом запушим» (запушим = обновить демо в конце); план одобрен «ok».
- Согласование убрано по ADR-006: роли editor / designer / admin (approver → editor, миграция 0014); дизайнер и админ
  меняют вариант секций и Branding, админ — люди и Integrations.
- `/admin/start` (Website / Training tool — инструмента нет, карточка неактивна), `/admin` «What needs you», меню по флоу.
- Форма записи: автосохранение, Publish в форме (в правой панели его нет), сводка ошибок, «месяц и год», время по Израилю.
- Заявки: кто отвечает, статус, заметка, фильтры (миграция 0015). Люди: приглашение по ссылке (0016), второй шаг
  обязателен и настраивается при первом входе (ключ на сервере, пароль ещё раз).
- Редактор: правка самих вкладок Product details.
- Находки: `publish()` оставлял строку черновика с расписанием (моя ошибка при правке unpublish) — исправлено; форма
  заявки после «I'll answer» показывала старого ответственного (defaultValue без перемонтирования); загрузка и CSV не
  проверяли 2FA.
- Затем: мини-превью пресетов (образцы из /style-guide), меню и футер (группа `navigation`, подписи на странице),
  комментарии на странице (таблица `comments`, 0017). Демо опубликовано (`gh-pages` 6e564b3).
- Ревью безопасности после каждого коммита — всё исправлено, кроме одного решения за владелицей: меню и футер (включая
  адреса ссылок) правит любой редактор, не только дизайнер/админ.
- Не сделано: наследование регионов (ждёт Emily), Redo в редакторе (во флоу есть кнопка), сам инструмент Tigertriever.
