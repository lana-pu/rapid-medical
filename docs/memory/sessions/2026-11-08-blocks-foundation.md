# 2026-11-08 — Механизм блоков и основные блоки

**Задача:** до редизайна сделать то, что понадобится при любом дизайне: страницы собираются из блоков, блок описан в
одном месте. Бриф: `docs/briefs/blocks-foundation.md` (одобрен владелицей).

## Что сделано
- Реестр `src/blocks/`: один файл на блок (название, назначение, варианты, поля, пример, компонент), `registry.ts`,
  рендер `BlockList`. 12 блоков, 25 вариантов. По просьбе владелицы похожие секции — один блок с вариантами
  (Text and media: медиа справа · слева · три колонки; Call to action: полоса · плашка · ряд кнопок и т. д.).
- Все 13 страниц терапий (US, OUS, APAC) рендерятся из блоков: `solutionToBlocks()` собирает их из нынешних полей
  `solutions`. Хранение не менялось.
- Связка полей для on-page editor (`src/blocks/bind.ts`): поле блока → путь в записи (`title` → `heroTitle`,
  `stats.0.value` → `benefits.1.stats.0.value`). Пути `data-e` те же, что раньше.
- Витрина `/style-guide`: все блоки во всех вариантах на примерных данных, noindex, не в sitemap; попадёт в демо-экспорт.
- Спека: `screens/therapy.md → Блоки`, `DESIGN.md → Коллекция блоков → В коде`, `spec.md → Платформа, Экраны`.
- Тесты: 13 unit на адаптер и связку полей, e2e на витрину.

## Проверка
- Паритет: HTML основной части всех 13 страниц совпадает до и после, в режиме посетителя и в режиме редактора
  (72 поля `data-e` на LVO). Нормализация — только пустые разделители React `<!-- -->`.
- `tsc`, `lint`, `vitest` (22), e2e 41/41 на production-сборке.
- Витрина просмотрена глазами на 1280 px; на 390 px нет горизонтальной прокрутки, ошибок в консоли нет.

## Изменённые файлы
- `src/blocks/*` (новое), `src/app/(site)/[seg]/therapies/[slug]/page.tsx`, `src/app/(site)/style-guide/page.tsx`
- `tests/unit/blocks.test.ts`, `tests/e2e/site.spec.ts`, `vitest.config.ts` (алиас `@`), `scripts/export-demo.ts`
- `docs/DESIGN.md`, `docs/screens/therapy.md`, `docs/briefs/blocks-foundation.md`

## Принятые решения
- Блоки собираются из полей записи при показе; хранение «страница = список блоков» — вместе с новым редактором и
  моделью регионов. Причина: не заводить второй источник правды, пока не решены регионы. Следствие ADR-006.
- Ряды Text and media подряд стоят в одной полосе (`stack` в определении блока) — так было в шаблоне.
- Подписи блоков в реестре — по-английски: их увидят редакторы клиента в пресетах.
- Примеры на витрине — нейтральные («Sample…»), без характеристик и цифр под реальными названиями продуктов.

## Находки
- Сохранены квирки шаблона ради паритета: индекс картинок спецификации считается после фильтра; у сноски таблицы
  есть «*», у сноски картинок нет; класс `mt-6` у References виден только в режиме редактора.
- e2e-подготовке нужны `psql` в PATH и `DATABASE_URL` в окружении. Шаг теста on-page editor на главной один раз не
  уложился в 5 с на свежей сборке; при повторе и отдельно проходит — нестабильный.
- Turbopack dev в копии во временной папке не всегда подхватывает изменения файлов — перезапускать сервер.
- Параллельная сессия закоммитила мои правки `spec.md` в `17bdc79`: при работе двух сессий в одном репозитории
  `git add` файла целиком забирает чужие правки (`rules/parallel-editing.md`).
