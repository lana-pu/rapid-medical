# ADR-008 — Базовая линия безопасности админки

**Статус:** принято · **Дата:** 2026-11-13 · Основание: аудит `docs/audits/security-check-2026-11-13.md` (4 критичных, все
починены), решения владелицы 2026-11-12 (двухшаговый вход для всех, ADR-006 — без согласования).

## Решение
1. **Вход.** Пароль (bcrypt 12, ≥ 10 символов) + обязательный второй шаг (TOTP), настраивается при первом входе; ключ
   выдаёт сервер, при настройке — пароль ещё раз. Лимиты: пароль — 8 неудач за 15 мин на e-mail и IP; код — 5 неудач за
   15 мин, затем сессия закрывается. Сессии в БД, отзываются; сброс админом закрывает все сессии и ссылки человека.
2. **Переадресации** по параметрам запроса — только на путь этого сайта (`safeLocalPath`).
3. **Загрузки** — тип по содержимому файла, расширение от типа, SVG без скриптов; `/uploads` с `nosniff`, SVG в
   песочнице CSP. Типу и имени от браузера не доверяем.
4. **Секреты** — без `AUTH_SECRET` (≥ 32) и, в проде, `CRON_SECRET` приложение отказывает, а не работает молча.
5. **HTML** от редакторов выводится только через `safeHtml`; значения настроек, попадающие в скрипты, — по формату.
6. Проверки — `docs/security-checklist.md`; e2e «security: …» — регрессия.

## Следствия
- CSP, запуск контейнера не от root, лимит форм в БД, логи без ссылок — в бэклоге, к подключению Vercel.
- Новый вектор (API, загрузка, переадресация, вставка в скрипт) → пункт в чек-лист и проверка в e2e.
