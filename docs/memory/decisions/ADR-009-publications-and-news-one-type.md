# ADR-009 — Публикации и новости — одна сущность

**Статус:** принято направление, детали — на вайрфреймах и в спеке · **Дата:** 2026-11-14 · Связано: BACKLOG п. 7–8,
`docs/briefs/linkedin-leads.md` (вопрос 3), `DESIGN.md → Страница из документа`, ADR-007

## Контекст
Сейчас две таблицы: `publications` (Evidence, 102 записи: журнал, авторы, ссылка / PDF / DOI, продукт, регионы) и
`news_items` (53 записи: заголовок, дата, внешняя ссылка — BusinessWire, NeuroNews и т. п.). Своих страниц нет ни у тех,
ни у других; страницы исследований (SUCCESS ×3 региона, DISTALS, Patankar, Long-term outcomes) живут отдельно в `pages`.
Новая фича «страница из документа» (BACKLOG п. 8) одинаково нужна исследованиям и новостям. Владелица 2026-11-14:
«не разделять публикации и новости — новая публикация может появиться в новостях; провисит там не бесконечно, но
появится. Функционал одинаковый, дизайн страниц, возможно, разный».

**Где материалы показываются сейчас (по коду `src/lib/content.ts`, 2026-11-14):** главная — «Latest news» (4 featured,
иначе последние); News & Events — карусель и лента по годам; Evidence (по региону) — счётчик «102+», featured,
последние, вкладки по продуктам; страницы терапий — вкладка «Clinical evidence» → `/{region}/evidence#{продукт}` и
ручные ссылки в тексте на страницы исследований (Aneurysm → SUCCESS, MVO → DISTALS, Aneurysm OUS → Patankar);
Long-term outcomes — без входящих ссылок; снаружи — посты LinkedIn (бриф). Всё это переводится на новую сущность;
идея — вкладка терапии показывает материалы продукта из записей вместо ручных ссылок (решить на вайрфрейме терапии).

## Решение
1. **Одна сущность** (рабочее имя — «материал»), поле **вид** (дополнено 2026-11-14):
   | Вид | Сверху | Полный текст | Сейчас на сайте |
   |---|---|---|---|
   | исследование | паспорт, инфографика | скопирован / PDF | SUCCESS ×3, DISTALS, DRIVEWIRE™ 24 SVIN Poster (черновик) |
   | публикация | ключевые выводы, цитата | PDF / ссылка (по правам) | Evidence (102), Long-term outcomes |
   | новость / апдейт | ключевые цифры, если есть | скопирован + ссылка на оригинал | News (53, сейчас — внешние ссылки) |
   | клинический случай | видео, шаги, выводы | — / PDF | Patankar, See the comparison (черновики) |
   | документ | — | **только встроенный PDF** и ссылка (IFU нельзя пересказывать) | TIGERTRIEVER™ IFU – Canada; брошюры (BACKLOG №17) |
   Из 11 нелегальных текстовых страниц `pages` 9 — материалы; у Privacy, Terms, Compliance, Patents — текстовый шаблон.
   Общее у всех: заголовок, дата, продукт, регионы, источник и ссылка на оригинал, файл (PDF), «создать из документа»,
   блоки страницы (ADR-007: основная графика из набора инфографики + полный текст), режим полного текста (скопирован /
   встроенный PDF / только ссылка), featured.
2. **Своя страница — по желанию.** Материал без страницы ведёт на оригинал (как сейчас все новости и публикации);
   с наполненной страницей — на неё.
3. **Где показывается** — по виду и флагу, а не по таблице: Evidence — исследования и публикации (вкладки по продуктам,
   как сейчас); News & Events — новости и материалы с отметкой «показать в новостях» (новое исследование попадает в
   новости и со временем уходит из ленты, оставаясь в Evidence).
4. **Дизайн страницы — по виду:** исследование — паспорт, инфографика, «Full study»; новость — редакционная страница
   (дата, вводка, картинка, текст, ключевые цифры при наличии). Функционал один, шаблоны — варианты одного шаблона
   «Страница из документа» (DESIGN.md). Дизайн новостной страницы — вместе с News & Events в очереди вайрфреймов.
5. **События (`events`) остаются отдельно**: у них регистрация, даты и итоги.

6. **Ещё где могут показываться (идеи, решать на вайрфреймах этих страниц):** вкладки терапии «Clinical evidence»
   (исследования продукта) и «In-Practice» (клинические случаи) — из записей вместо ручных ссылок; итоги событий —
   представленные исследования; вебинары — позже (своя механика доступа к записи).

7. **Вид при создании определяет сайт, бесплатно, до ИИ** (2026-11-14): по адресу ссылки (businesswire → новость, doi /
   журнал → публикация) и словам в PDF («Instructions for Use» → документ, «Methods / Results» → исследование, «About
   Rapid Medical» → новость). Сайт подставляет вид с пояснением «Suggested from the file», человек меняет одним кликом.
   Вид решает шаги: у документа нет сводки от ИИ и инфографики — только PDF.
8. **Где появляется — галочки при создании, потом в карточке материала** (2026-11-14):
   Evidence (вкладка продукта) · лента новостей · **хайлайты** (главная — 4, News & Events — блок «главное»: 1 + 3
   вместо карусели с 2026-11-14, Evidence — featured). По умолчанию по виду: исследование — Evidence + новости + хайлайты; публикация — Evidence + хайлайты;
   новость — новости + хайлайты; клинический случай — по ситуации; документ — нигде автоматически.
   **Хайлайты у нового включены по умолчанию**; карусели берут самые свежие отмеченные, старые уходят сами по мере
   добавления. Галочку можно снять — материал не попадёт в карусели. Закрывает BACKLOG №13 («Featured publications —
   отмеченные или последние»): отмеченные, а новые отмечены по умолчанию. Сейчас по коду Evidence показывает последние,
   флаг не смотрит.

## Последствия
- Миграция: две таблицы + страницы исследований из `pages` → одна. Старые таблицы не удалять, пока перенос не проверен;
  старые адреса страниц исследований — редиректами.
- Админка: один список с фильтром по виду; в меню по разделам сайта он виден и в Evidence, и в News (тот же список,
  разный фильтр).
- Запросы Evidence, News & Events и главной (featured news) переписываются на новую сущность.
- Вопрос 3 брифа LinkedIn («отдельный тип или расширение publications») закрыт этим решением.

## Открыто
- Имя сущности и адреса страниц (глобально `/…/{slug}` или в регионе — сейчас SUCCESS есть в трёх регионах с разными
  файлами; ADR-002).
- «Показать в новостях»: просто флаг или флаг с датой «до».
- Региональные версии одного исследования: одна запись с регионами или копии (как терапии, ADR-007).
