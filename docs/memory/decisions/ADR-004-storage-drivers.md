# ADR-004 — Хранилище медиа: драйверы `local` / `s3`

- **Статус:** принято частично — код готов, выбор хостинга/бакета **не сделан** (ретроспективно, код `59169da`)
- **Код:** `src/lib/storage.ts`, `src/lib/media.ts`, `src/app/api/admin/upload/route.ts`

## Решение
- `STORAGE_DRIVER=local` — `public/uploads/<yyyy-mm>/…` (один сервер, dev, Docker).
- `STORAGE_DRIVER=s3` — любой S3-совместимый бакет (AWS S3, Cloudflare R2, Backblaze, MinIO), опц. CDN
  через `S3_PUBLIC_URL`.
- Пайплайн одинаков для обоих: WebP 480/960/1600, blur-плейсхолдер, постер видео (ffmpeg); удаление
  чистит оригинал, варианты, постер; удаление запрещено, пока файл где-то используется.
- Временно мигрированные медиа (~270 МБ) **закоммичены в git**, чтобы локальный запуск и первый деплой
  работали без бакета (`2419c15`, `61a80f1`).
- На Vercel с `local` загрузка отвечает 503 с понятным сообщением.

## Обоснование
README: «`STORAGE_DRIVER=s3` … required on Vercel or with more than one instance»; перенос в бакет —
«todo when hosting is decided».

## Последствия / открыто
- Выбор провайдера бакета и перенос файлов — BACKLOG P1 / Решения за владельцем.
- После включения S3 — вернуть `/public/uploads/` в `.gitignore` (комментарий в `.gitignore`).
- Рост репозитория из-за бинарников, пока медиа в git.
