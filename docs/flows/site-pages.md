# Страницы сайта на вайрфреймах — порядок и статус

Флоу: `site-pages.py` → `site-pages.json` → артефакт (приватная ссылка): https://claude.ai/artifact/Dyud46HRkPumSyPiZXrMVA. Сборка:
`python3 docs/flows/site-pages.py && python3 .claude/skills/wireframes/scripts/build.py docs/flows/site-pages.json <scratchpad>/site-pages.html --pack docs/flows/pack.js`,
публиковать тем же путём файла.

## Цикл на каждую страницу (решение владелицы 2026-11-13)
Строго по одной странице, следующая — только после закрытия текущей.
1. **Показ.** Как страница собрана сейчас (настоящие блоки из `rm-pages.json`, десктоп и телефон) + экран с примерами из
   Mobbin, сгруппированными по вопросам для обсуждения. Скриншоты — `refs/<страница>/` (не в git: репозиторий публичный),
   на странице артефакта — файлами рядом (`files` при публикации). Черновик предложения — можно, но как повод для разговора.
2. **Обсуждение** с владелицей: что поправить.
3. **Закрытие:** решения записываются ниже, в раздел страницы; экраны предложения правятся под решения.
4. **Дизайн-система:** только теперь — новый токен, вариант блока, правило в `docs/DESIGN.md`. Общий компонент
   вайрфреймов — в `.claude/skills/wireframes/assets/kit.js` (репозиторий Studio).
5. Следующая страница. Код — потом: решение → спека экрана `docs/screens/*.md` → код.

## Contact Us — решение (закрыта 2026-11-14)
Путь: v1 перегружен, без иерархии → v2 проще по функционалу, но «разваливается» → v3: две композиции → выбрана A.
- **Композиция A «общая линия»:** H1, тонкая линия, под ней текст и контакты-таблица (4/12) и форма (7/12) с одной высоты.
- **Форма:** тема первой — 3 чипа + «Other topic»; поля парами: имя/фамилия, e-mail/телефон, организация/страна; сообщение;
  подписка; кнопка на всю ширину; строка согласия под ней. Phone и Organization необязательные. State убран.
- **Ошибки** — только у поля, введённое остаётся. **Успех** — заголовок-подтверждение, кому ушло, куда ждать ответ.
- В DESIGN.md: токен `--danger`, «Композиция „общая линия“», примитив «таблица ключ — значение», правила форм.

**Открыто (не блокирует):** страна вместо Region + Country — ответ Emily про Ближний Восток и Латинскую Америку; срок
ответа — цифра от клиента; какие 3 темы частые — проверить по заявкам. **В код** — через спеку `screens/contact-us.md`
(сейчас её правит параллельная сессия, после неё).

## Страница исследования → страница из документа (закрыта 2026-11-14)
Владелица: «придумать что-то интересное». Сейчас: SUCCESS — скриншот постера (во всех 3 регионах), DISTALS — лендинг с
графиками-картинками и PDF, Patankar — видео кейса, Long-term outcomes — ссылка на PDF.
Идея: страница исследования — история в данных из одобренного постера, а не картинка. Название и вывод одной фразой →
«паспорт» (дизайн, пациенты, центры, период, кто оценивал) → 4 итога крупно → графики из чисел (переключатель по времени)
→ матрица «точка = пациент» → таблица безопасности → карта центров → постер PDF, разговор с командой, терапия, публикации.
Блоки в основном есть (Key numbers, BarChart, WorldMap, Indications); новые — паспорт («ключ — значение»), матрица точек,
переключатель на графике. Варианты шаблона: результаты исследования (SUCCESS, DISTALS), клинический случай (видео + шаги),
публикация (цитата, выводы, PDF). Риск: подача цифр — через MLR клиента.

**Решения владелицы (2026-11-14):**
- Это набор инфографик-шаблонов под основные выводы, подставляемых в любое исследование.
- Без дополнительных платежей. ИИ — варианты 1 + 2: (1) паспорт исследования из ClinicalTrials.gov по номеру NCT
  (открытый API, бесплатно); (2) сводку делает ИИ, который у маркетинга уже есть (ChatGPT / Claude / Copilot): в админке
  «Copy instructions for AI» → в своём чате приложить PDF и вставить → ответ вставить в админку → черновик. Сайт ИИ не
  вызывает и за него не платит.
- Механизм общий — **«Create from a document»**: исследования, новости и апдейты компании (позже — клинический случай,
  публикация). У новости нет паспорта.
- Страница: **основная статистика сверху, под ней полный текст** документа. Полный текст — скопировать на страницу,
  встроить PDF или только ссылка на оригинал; выбор при создании.

**Как устроено (вайрфрейм, экраны «Создать из документа»):** полный текст сайт достаёт из PDF сам, без ИИ, и сверяет с
PDF слово в слово. Цитату к каждой цифре из ответа ИИ сайт ищет в тексте PDF: нашлась — блок проверен сам; не нашлась —
«Check», Publish закрыт, пока человек не поправит. Новости сейчас — заголовок и ссылка на BusinessWire / NeuroNews (53
записи), врач уходит с сайта; с механизмом — своя страница с полным текстом пресс-релиза и ссылкой на оригинал.

**Открыто:** какой ИИ уже есть у маркетинга (под него — инструкция); права на полный текст статей из журналов (свои
постеры и пресс-релизы — можно; журнальные — по лицензии или только ссылка); подача цифр — через MLR; дубли
пресс-релизов с BusinessWire для SEO (canonical); проверить извлечение на реальных PDF (SUCCESS, DISTALS); поля API
ClinicalTrials.gov.

## Evidence — обсуждение (2026-11-14)
Клиент на звонке: «в таком виде Evidence никто читать не будет». Ресёрч — `memory/findings/evidence-benchmark-2026-11-14.md`.
Черновик концепции: счётчик с расшифровкой → Key studies (5–10, дизайн · N · главная цифра · страница исследования) →
вход по клиническому вопросу → архив с поиском и фильтрами (продукт, показание, тип), вывод одной фразой → идущие
исследования.

**Решено: разметка публикаций — по желанию.** Обязательны только поля, которые уже есть у всех (название, дата, продукт,
ссылка/PDF). Тип исследования, N, показание, вывод одной фразой — по желанию. Исключение: «Key study» нельзя отметить без
типа, N и главной цифры. Неразмеченная строка: «первый автор et al. · журнал · год», бейдж продукта. Фильтры по типу и
показанию — только размеченные + строка «N not yet classified — Show them». Клинический вопрос без показания — из
продукта, где однозначно (T13 → MeVO, DRIVEWIRE → доступ); COMANECI — после разметки. Счётчики по разметке — с подписью
«in classified». Админка: очередь «Classify publications» (как «Describe pictures» в медиатеке), ИИ маркетинга предлагает,
человек подтверждает.
